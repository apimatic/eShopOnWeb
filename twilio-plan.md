## 2. CONTRACT SHEET

> **Signatures are generated code, verbatim — every parameter name is the literal
> C# identifier. The cancellation-token parameter really is named `ct`: in named
> arguments write `ct:`, never `cancellationToken:`.**
>
> **Every SDK type is written fully-qualified with the namespace the map gives it** — take
> each one from that type's own map row, never from where a neighbouring type sits. A members
> table names the namespace outright; otherwise the row's source path implies it
> (`Core/Configuration/…` ⇒ `…Core.Configuration`; a file at the repo root ⇒ the root
> namespace). Enums, unions, auth, server and client-config types are spread across different
> child namespaces, and two types configured side by side in the same options object routinely
> live in different ones. Dropping a type to the root or to `.Models` makes the implementer
> guess the wrong `using`, and the build breaks.

## 3. Trap notes

- ⚠ Step 1 (client registration) — `HttpClient`/handler and generated client lifetimes can turn a working integration into connection exhaustion or stale-network behavior. **MUST load `dotnet-client-initialization`** before wiring the client.
- ⚠ Step 1 (authentication) — credential construction, configuration timing, and secret rotation determine whether calls authenticate without leaking or freezing secrets. **MUST load `dotnet-authentication`** before wiring credentials.
- ⚠ Step 1 (server/retry/timeout) — server-node override placement, timeout boundaries, and transport/status retry behavior can route to the wrong host or duplicate non-idempotent writes. **MUST load `dotnet-configuration-resilience`** before configuring server/retry/timeout/logging or pagination.
- ⚠ Steps 2–9 (endpoint calls) — long generated signatures have required-but-nullable positional slots and list calls can silently mis-bind filters, breaking validation, sender scoping, or scheduling. **MUST load `dotnet-calling-endpoints`** before the first call.
- ⚠ Steps 2–9 (models/enums) — generated string enums, nullable response fields, immutable models, and wire/C# name differences can corrupt status and validation mapping. **MUST load `dotnet-models`** before mapping requests/responses.
- ⚠ Steps 2–9 (error boundary) — Case-B raw errors, transport failures, cancellation, and deserialization failures cross different exception paths; an incomplete boundary can fail domain operations or misreport provider outcomes. **MUST load `dotnet-error-handling`** before writing the boundary.
- a drifted or malformed **2xx** body (a missing `required` member) surfaces as a `JsonException` from deserialization, **not** as an `SdkException` — so an SDK-exception-only catch ladder lets it escape the integration boundary;
- a **non-2xx** body that does not match its operation's generated `{Operation}Error` shape throws `JsonException` *while the error object is being constructed*, so the `JsonException` **replaces** the `SdkException` and the HTTP status is destroyed with it — a boundary that maps every `JsonException` to a 5xx then reports a deterministic rejection as an outage, and a caller that retries 5xx retries something that can never succeed.

**MUST load `dotnet-error-handling`** before writing that boundary.

- ⚠ Step 10 (tests) — faking generated controllers instead of the supported HTTP seam couples tests to implementation and misses real serialization/error behavior. **MUST load `dotnet-testing`** before creating provider tests.

## 5. Assumptions & Blockers

**Assumptions**

- “A few days later” is implemented as exactly three days after the dispatch instant. `YOUR CALL — not in the map`.
- The reconciliation interval is defined as the open interval `(from,to)` because the generated provider filters are literally `DateSent>` and `DateSent<`. `YOUR CALL — not in the map` for the endpoint's interval convention.
- **UNVERIFIED:** the map and generated source state that `UpdateMessage` redacts body text and expose nullable `body`, but do not document the redaction sentinel. Submit `string.Empty`, require the returned `Body` to be null/empty before declaring provider disposal complete, and retain a retryable failure otherwise. This is the only defensive directive needed for a fact that only live traffic can confirm.

**Blockers**

- None.
