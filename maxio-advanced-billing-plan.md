**Switch sequence by current state (F6).** State is read first (`ReadSubscription`); the target handle is first checked against the plans list and must differ from the current `Product.Handle` (rule `migrateSubscriptionProduct.2`, otherwise 409).

| Current state | Sequence | Rule basis |
| --- | --- | --- |
| `active`, `trialing` | `MigrateSubscriptionProduct` with `PreservePeriod` omitted (YOUR CALL — not in the map: new period starts today at the new plan's full price; `true` would prorate) | `migrateSubscriptionProduct.1/.8` |
| `canceled`, `trial_ended`, `unpaid` | `UpdateSubscription { ProductHandle = new }` (product changed while not live), then `ReactivateSubscription { Resume = false }`, then `ReadSubscription` and require `State == Active` and `Product.Handle == new` | rule text "for trial_ended, cancel, change the product and reactivate" (`migrateSubscriptionProduct.1`), `reactivateSubscription.1`; update-while-canceled acceptance is UNVERIFIED (fallback: Reactivate then Migrate; both orders end Active on the new plan) |
| `on_hold` | `ResumeSubscription`, then `MigrateSubscriptionProduct`, then verify | `resumeSubscription.1`, `migrate.1` |
| `past_due`, `soft_failure`, `suspended`, other non-live | 409 with reason (owes money / not switchable now); no Maxio write | `migrate.1` |

Result of any path must be re-read and verified; if verification fails after a partial path, answer 409 describing the state reached (no rollback attempted).

### Client construction / auth / server facts
- `new MaxioAdvancedBilling.MaxioAdvancedBillingClient(HttpClient, MaxioAdvancedBilling.MaxioAdvancedBillingClientOptions)` or `services.AddMaxioAdvancedBillingClient(options => ...)`. Options: `Environment`, `Retry`, `Logging`, `TimeProvider`, `Server`, `StreamReadTimeout`, `Hooks`, `BasicAuth`, `BasicAuthProvider`.
- Auth = HTTP Basic: `options.BasicAuth = new BasicAuthCredentials { Username = <Maxio:ApiKey>, Password = "x" }` (the map names `x` as the documented password; it is a protocol constant, not a configured secret). SDK env fallback names (`MAXIO_ADVANCED_BILLING_BASIC_AUTH_USERNAME/PASSWORD`) must NOT be relied on: credentials come from the `Maxio:` section only.
- Server group used: `Production` only (every operation above; no operation here is on `Ebb`). `Production.Us.BaseUrl` default `https://{site}.chargify.com`, `Production.Eu.BaseUrl` default `https://{site}.ebilling.maxio.com`; site variable `options.Server.Production.Us.Site` / `.Eu.Site` (default literal `"subdomain"`). Only the selected environment's options are read; `Environment` is captured at construction, so configure everything before constructing.
- The SDK declares no sandbox environment: a Maxio sandbox is a test site on the same hosts, selected by subdomain + that site's API key. Mapping decided: `Maxio:Environment` value, case-insensitive: `us` -> `ServerEnvironment.Us`, `eu` -> `ServerEnvironment.Eu`, anything else (or blank) refuses startup. `Maxio:Subdomain` -> `options.Server.Production.<Env>.Site`. `Maxio:BaseUrl` when non-blank -> assigned verbatim to `options.Server.Production.<Env>.BaseUrl` of the selected environment (no trimming, no appended path), and then `Maxio:Subdomain` is not required.

### Trap notes
- Client options are built once at registration and captured in the singleton; `Environment` is read at construction and later edits to it are silently ignored. MUST load maxio:dotnet-client-initialization.

- `Retry.Timeout` and `HttpClient.Timeout` are per attempt and neither bounds a whole call; the default retried verb list includes `PUT`, which is used by `ReactivateSubscription`, `UpdateSubscription` and `UpdateProductCurrencyPrices` (money and billing-date writes). MUST load maxio:dotnet-configuration-resilience.

## 6. Assumptions & Blockers

Blockers: none that stop planning. The items below are decisions and unverified facts the main agent must carry.

1. **Identity and ownership.** The JWT has only `ClaimTypes.Name` (and roles). Maxio customer `reference` = `name.Trim().ToLowerInvariant()` (the token carries the name as typed at login, so case may vary between logins; normalising keeps one customer per user). Ownership = `Subscription.Customer.Reference` equals that normalised value after the same normalisation; null or different -> 404 (not 403) so other subscriptions are not disclosed. Never trust ids from the body for identity; never use `ListSubscriptions.Q` (fuzzy search) for ownership. Shopper endpoints are owner-only even for Administrators (YOUR CALL — not in the map). Customer fields: email = the JWT name (must contain `@`, else 400 "account has no email address"); first_name = local part, last_name = fixed literal "Shopper" (YOUR CALL — Maxio requires both, the JWT has neither).
2. **Plans = brands.** One Maxio product family per `CatalogBrand` (`eshop-brand-{Id}`, created on first plan of that brand, YOUR CALL — not in the map); a plan is a non-archived product in such a family; plan handle generated as `plan-{brandId}-{slug(name)}` (YOUR CALL), duplicate -> Maxio 422 -> 409. `monthlyPrice` decimal > 0 with at most 2 decimals, converted to `price_in_cents`; interval = 1 Month; description defaults to the name (Maxio requires it). `planId` in F9 = Maxio product id. `GET /api/plans` requires an authenticated user (YOUR CALL).
3. **No card.** Subscribe sends no payment profile. Collection method chosen from `Sites.ReadSite`: `RelationshipInvoicingEnabled == true` -> `Remittance`; otherwise `Invoice` (rule `createSubscription.41`: Relationship Invoicing accepts automatic/remittance/prepaid, statement sites automatic/invoice). If Maxio still answers 422 asking for payment info for a paid plan (`createSubscription.7`) the endpoint returns that reason as 422/4xx. UNVERIFIED: whether a priced plan without a card is accepted on the sandbox site.
4. **`paid`.** `paid = true` only when ALL hold: `Subscription.BalanceInCents <= 0` (negative = credit), `AccountBalances.OpenInvoices.BalanceInCents <= 0` (null treated as unknown), and `State` is not `PastDue`/`Unpaid`/`SoftFailure`. `PendingInvoices` (not yet issued) are not counted as owed (YOUR CALL). If either balance field is absent, the answer is 502 with reason rather than a guessed `true`. Amounts are cents; response also exposes `balanceInCents`.
5. **Switch.** See the sequence table in §2. Migrate sends `preserve_period` omitted (new period starts today, full price of the new plan, per `migrateSubscriptionProduct.8`) — YOUR CALL; the alternative `true` gives a prorated charge. The cancelled path relies on `UpdateSubscription` accepting a product change on a cancelled subscription: UNVERIFIED (the only evidence is the rule text for trial_ended); fallback sequence Reactivate then Migrate is acceptable. Reactivation needing a payment method on a priced plan with no card returns 422 (`reactivateSubscription.12`); that reason is surfaced and the result is then NOT active — the endpoint answers 4xx stating the subscription remains cancelled (and on which product it now sits, if the product update already applied).
6. **Restart** only from `canceled` (others 409 with their state); `Resume = true`. Pause: only `active`/`trialing`; 422 from Maxio (within 24h of billing, not eligible; `pauseSubscription.1/.2`) is returned as 409/422 with its message. Resume: only `on_hold`. Cancel: immediate; already canceled -> 409.
7. **Usage for one day.** `date` strictly `YYYY-MM-DD` (400 otherwise). Metered usages are listed for every component with `Kind == MeteredComponent` (prepaid usage excluded, YOUR CALL), all pages. Boundaries: `ListUsages` `since_date`/`until_date` are date-only and midnight-based (the member doc says `until_date` is "less than or equal to midnight" and the rule says it excludes later usage on that day; the site time zone is not readable from the SDK `Site`). To be correct regardless, request `since_date = date - 1 day`, `until_date = date + 2 days`, then keep only usages whose `CreatedAt` (which carries the site offset, `every-request.12`) has calendar date == `date`, i.e. `[date 00:00, date+1 00:00)` in site-local time, all pages. Response lists items, per-component totals (sum of `Quantity`, read per the `Quantity1` union) and `Truncated`.
8. **Next billing date.** Body `{ "date": "YYYY-MM-DD" }`; must be a real calendar date (Maxio silently rolls over Feb 30, `updateSubscription.10`, so validate first) and strictly later than today; subscription must be in a state that renews (`active`, `trialing`; `past_due` too is refused to avoid masking a balance; `on_hold`/`canceled`/other -> 409, they would not be billed on that date, `background.69`). Send a timestamp at 12:00 using the UTC offset of the subscription's `CurrentPeriodEndsAt` (site offset) so the date is the site-local billing day; after the call re-read and require local date of `CurrentPeriodEndsAt` == requested date (the response has no `next_billing_at`, `updateSubscription.12`); mismatch -> 409 with the actual date. The new date becomes the anchor of later periods (`updateSubscription.11`). UNVERIFIED: DST offset differences between "now" and the target date; the verification step catches it.
9. **Currency prices.** Currency must be an ISO code in `Site.NonPrimaryCurrencies`; price decimal > 0. Units of `CreateProductCurrencyPrice.Price` (int) vs `UpdateCurrencyPrice.Price` (double) are UNVERIFIED: the `CurrencyPrice.FormattedPrice` read back from `ReadProductPricePoint` (CurrencyPrices=true) must be compared to the requested amount in the sandbox on first use, and the conversion (whole units vs cents) fixed to match; if the int field cannot carry a fractional amount, a fractional input is rejected 400 with that reason. Existing currency on the price point -> Update (by `CurrencyPrice.Id`, rule `updateProductCurrencyPrices.2`), else Create. Plans have no trial/setup fee, so only the Baseline role is sent (`createProductCurrencyPrices.2`). Custom price points are not touched.
10. **Error mapping.** Maxio 404 -> 404; 422 -> 422 with the Maxio message(s); 429 -> 429 with reason; other 4xx -> same status; 5xx / connection / timeout / deserialisation -> 502 / 504 with a generic reason (and logged detail). Every non-2xx body is `{ statusCode, message }` (the `ErrorDetails` shape from `BlazorShared.Models`, as `ExceptionMiddleware` uses) — via `Results.Json`/`Results.Problem`, not exceptions, because `ExceptionMiddleware` would turn them into 500.
11. **Tests.** Integration tests call the real sandbox (skipped with a visible reason when user-secrets are missing); no HttpClient stubs and no fabricated Maxio payloads. Error paths (unknown plan handle, foreign subscription, bad date, non-admin on admin routes, brand not in catalog) are exercised without needing Maxio fabrications.
12. **Environment variable `MAXIO_ENVIRONMENT`** is a 2-character value that maps to `us`/`eu`; its value is not recorded here.
13. **SDK reference.** `dotnet add src/PublicApi/PublicApi.csproj reference <plugin-root>/sdk/dotnet/src/MaxioAdvancedBilling/MaxioAdvancedBilling.csproj` — a machine-local `ProjectReference`; say so in the hand-over. The SDK targets `netstandard2.0`, the project `net8.0`.
