### CROSS-OPERATION INVARIANTS

| Invariant | Operations | Enforced where |
| --- | --- | --- |
| A plan handle accepted by subscribe must be one returned by the list-plans read for the configured product family (not merely a handle that exists in Maxio) | `Subscriptions.CreateSubscription` (`CreateSubscription.ProductHandle`) <- `ProductFamilies.ListProductsForProductFamily` (`handle:{Maxio:ProductFamilyHandle}`) | `SubscriptionService.SubscribeAsync`, BEFORE the subscription claim and before any `CreateCustomer`/`CreateSubscription`: it calls the same plan-listing method the GET endpoint uses and rejects a handle not in the result (400/422, no Maxio write). If the listing was truncated (IsTruncated) and the handle is absent, fail closed (503), never accept |
| The customer id passed to `CreateSubscription.CustomerId` must be the id returned by `ReadCustomerByReference`/`CreateCustomer` for the caller's own reference (never from the request body) | `Subscriptions.CreateSubscription` <- `Customers.ReadCustomerByReference` / `Customers.CreateCustomer` | `SubscriptionService.EnsureCustomerAsync` result is the only source of `CustomerId`; caller identity comes from `ClaimTypes.Name` |

## 6. Assumptions & Blockers

Blockers: none that stop planning.

Assumptions (need user awareness; each has a proposed decision):

- **A1 SDK frameworks vs repo (compatibility).** The SDK targets `netstandard2.0` (C# `LangVersion 14`, `TreatWarningsAsErrors` inside its own tree) — consumable from the repo's `net8.0`. Issues: (a) C# 14 needs the .NET 10 SDK; `global.json` pins `8.0.x` with `rollForward: latestFeature` and only SDKs 9.0.308 and 10.0.401 are installed, so every `dotnet` command fails until `global.json` is changed. Decision: set `rollForward` to `latestMajor` (keep `version` 8.0.x) so SDK 10 builds everything; `TargetFramework` stays `net8.0` for repo projects (net8 runtime 8.0.31 is installed, so tests run on it; `DOTNET_ROLL_FORWARD=Major` only as a fallback). (b) The SDK pins package versions 10.0.8 (`Microsoft.Extensions.Http`, `System.Text.Json`, `Microsoft.Bcl.*`, `System.Net.Http.Json`, Polly 8.6.5) in its own `Directory.Packages.props`; the repo pins `System.Text.Json` 8.0.3 centrally. Transitive resolution should lift to 10.0.8 for PublicApi/Infrastructure; if NU1605/NU1109 appears, decision: raise `System.Text.Json` (and any named package) in the repo's `Directory.Packages.props` to 10.0.8 rather than altering the SDK. (c) The SDK is referenced by a path into this plugin install (not copied, not on NuGet): machine-local; CI/teammates need the plugin installed. Not a Blocker; stated in hand-over.
- **A2 Caller identity.** The JWT has only `ClaimTypes.Name` (user name) + roles; no stable user-id claim. Decision: identity = `ClaimTypes.Name` normalized (lowercase); claims/references keyed on it. Missing/blank -> 401.
- **A3 Customer attributes.** `CreateCustomer` requires first/last name and e-mail, which the token does not carry. Decision: look up `ApplicationUser` e-mail (via `UserManager`, falling back to the user name when it is an e-mail); first name = e-mail local part, last name = a fixed placeholder. Flag if the user wants real names.
- **A4 Default plan.** Request without a plan handle defaults to `eshop-pro` (task: "default subscribe target"); a constant, still subject to the list-plans invariant (so it is rejected if absent from the family). Metered component `api-call` and `basic-plan` upgrades/usage reporting are out of scope; plans are listed from `ListProductsForProductFamily` only.
- **A5 No hot secret rotation; restart to rotate.**
- **A6 Persistence limits.** Claims live in `CatalogContext`; with in-memory EF they vanish on restart (reconciliation by Maxio reference covers it). On a real SQL Server deployment a new EF migration for the two claim tables is required (migrations are ignored by the in-memory provider and not generated here).
- **A7 Re-subscribe.** One subscription per (user, plan): a later request for the same pair returns the existing subscription (200) rather than creating another, even if canceled; re-subscription after cancellation is out of scope.
- **A8 Environment variable mapping.** `MAXIO_ENVIRONMENT` has no `Maxio:` binding key among the four mandated; it is read directly (`us`/`eu`, default `us`).
- **A9 HTTP status mapping (YOUR CALL — not in the map):** missing/invalid token 401; plan not offered / bad body 400 (or 422); claim in progress 409; Maxio 422 (typed) 422 with generic message; Maxio 401/403 (bad credentials) 502 (config fault, logged Error); Maxio 404 on product family 502/503; Maxio 429/5xx/connection failure 503; timeout 504; deserialization drift 502. Provider text never echoed to the client.

UNVERIFIED (defensive-coding directives, only live traffic can settle):

- **U1** `ReadCustomerByReference` is Case B: treat `ApiException<RawError>` with `StatusCode == 404` as "no customer"; any other status is an error (not "no customer").
- **U2** Whether Maxio rejects a duplicate `reference` on `CreateCustomer`/`CreateSubscription`: assume NOT; rely on the claim, and after any create re-read by reference and, if more than one subscription for the same reference appears, log Error and return the earliest.
- **U3** Whether `ListCustomerSubscriptions` truncates results: no paging shown; assume complete.
- **U4** Name of a provider correlation/request-id response header: unknown to the map; log any of `X-Request-Id`/`X-Chargify-Request-Id` present in `ApiException.Headers`.
- **U5 (settled by live traffic)** A priced plan without a payment profile and without `PaymentCollectionMethod` is refused 422 ("No payment method was on file"); the call now sends `PaymentCollectionMethod = Remittance` and the sandbox accepted it (201, state `active`). If a site runs the legacy Statements architecture the valid value would be `Invoice` instead (per the member doc).
- **U6** `next_assessment_at` vs `current_period_ends_at` as "next billing date": plan reports `NextAssessmentAt`, falling back to `CurrentPeriodEndsAt` when null.
