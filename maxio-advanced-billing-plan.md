# Maxio Advanced Billing plan — eShopOnWeb `src/PublicApi` subscription billing

SDK source (plugin-relative): `sdk/dotnet/` (map `sdk/dotnet/sdk-map.md`, pages `sdk/dotnet/map/operations/*.md`). Business rules: `business-rules/` (ids cited as `maxio-c4:<op>.<n>`).
Source labels used in tables: a map page / map-named file, `UNVERIFIED`, or decided in code (see BillingService).

## 1. Scope & sequence

Identity model (JWT carries only `ClaimTypes.Name` and `ClaimTypes.Role`, see `src/Infrastructure/Identity/IdentityTokenClaimService.cs`): the caller is `User.Identity.Name`; staff = role `BlazorShared.Authorization.Constants.Roles.ADMINISTRATORS`. The Maxio customer is linked to the shopper by **customer `reference` = JWT name**. Subscription ownership = `subscription.customer.reference` equals JWT name (ordinal, ignore case). A non-owned or missing subscription is a 404 "subscription not found" (never reveal it exists).

| # | Step (endpoint) | Operations used (in order) |
| --- | --- | --- |
| 0 | Config + client (`Maxio:ApiKey/Subdomain/Environment/BaseUrl`), fail-fast, DI singleton | none |
| 1 | `GET /api/plans` (auth: any signed-in user) | `Products.ListProducts` (non-archived, paged until a short page) |
| 2 | `POST /api/subscriptions` `{planHandle}` | `Products.ListProducts` (handle must be in legal set) → `Sites.ReadSite` (collection method) → claim → `Customers.ReadCustomerByReference` (404 ⇒ `Customers.CreateCustomer`) → `Subscriptions.CreateSubscription` (by `customer_id`, `product_handle`, `payment_collection_method`, unique `reference`, no payment profile) |
| 3 | `GET /api/subscriptions/{id}` | `Subscriptions.ReadSubscription` → ownership check → `SubscriptionInvoiceAccount.ReadAccountBalances`; `paid` derived (see Assumptions A5) |
| 4 | `POST …/{id}/pause`, `/resume` | `ReadSubscription` + ownership + state precheck → `SubscriptionStatus.PauseSubscription` (no auto-resume date) / `ResumeSubscription` |
| 5 | `POST …/{id}/cancel`, `/restart` | `ReadSubscription` + ownership + state precheck → `SubscriptionStatus.CancelSubscription` (immediate, no schedule fields) / `SubscriptionStatus.ReactivateSubscription` (only for `canceled`) |
| 6 | `POST …/{id}/switch` `{planHandle}` | `Products.ListProducts` (legal set) → `ReadSubscription` + ownership → `Subscriptions.UpdateSubscription` (`product_handle`, immediate, not delayed) — works for any state incl. `canceled` (UNVERIFIED for canceled, see Blockers B2) |
| 7 | `GET …/{id}/usage?date=YYYY-MM-DD` | `ReadSubscription` + ownership → `SubscriptionComponents.ListSubscriptionComponents` (metered/prepaid kinds) → `SubscriptionComponents.ListUsages` per component, paged, window widened and filtered client-side by the usage's own local date |
| 8 | `POST /api/admin/plans` `{name, monthlyPrice, brand}` (ADMINISTRATORS) | catalog brand check via `IReadRepository<CatalogBrand>` → claim → `ProductFamilies.ListProductFamilies` (find by name; else `ProductFamilies.CreateProductFamily`) → `Products.CreateProduct` |
| 9 | `POST /api/admin/plans/{planId}/currency-prices` `{currency, price}` (ADMINISTRATORS) | `Products.ReadProduct` → `Sites.ReadSite` (currency legal) → `ProductPricePoints.ReadProductPricePoint` (`CurrencyPrices=true`) → claim → `ProductPricePoints.CreateProductCurrencyPrices` or `UpdateProductCurrencyPrices` |
| 10 | `PUT /api/admin/subscriptions/{id}/next-billing-date` `{date}` (ADMINISTRATORS) | `ReadSubscription` → claim → `Subscriptions.UpdateSubscription` (`next_billing_at`) → `ReadSubscription` (verify via `current_period_ends_at`) |

`planId` in admin routes = Maxio product id (int). `subscriptionId` = Maxio subscription id (int). Brand = Maxio **product family** whose `name` equals the catalog brand name (`CatalogBrand.Brand`).

## 2. CONTRACT SHEET

⚠ Signatures are generated code, verbatim: every operation that takes input takes ONE request record as its first parameter (an operation with no inputs takes none — `Sites.ReadSite` takes only `requestOptions`/`cancellationToken`), built with an object initializer whose property names are the record's own, never flat arguments. Every operation also ends `RequestOptions? requestOptions = null, CancellationToken cancellationToken = default`.
⚠ Every SDK type is written fully-qualified with the namespace its source path implies, taken from the path the map gives for THAT type, never from where a neighbouring type sits. Namespaces: client/options `MaxioAdvancedBilling`; controllers `MaxioAdvancedBilling.Api`; models `MaxioAdvancedBilling.Models`; enums `MaxioAdvancedBilling.Models.Enums`; AnyOf unions `MaxioAdvancedBilling.Models.AnyOf`; errors `MaxioAdvancedBilling.Errors`; request records `MaxioAdvancedBilling.Requests.<ControllerFolder>`; `ApiException<T>`/`SdkException` family `MaxioAdvancedBilling.Core.Exceptions`; `RawError` `MaxioAdvancedBilling.Core.ErrorResponse`; `ServerEnvironment` `MaxioAdvancedBilling.Servers`; `BasicAuthCredentials` `MaxioAdvancedBilling.Core.Authentication.Basic`; `RetryOptions` `MaxioAdvancedBilling.Core.Configuration`.

Common: error case B = `ApiException<RawError>` (accessors `StatusCode`, `ReadAsBytes()`, `ReadAsString()`, `ReadAsJson<T>()`); case A = `ApiException<{Op}Error>` with `TryGet…` accessors + `TryGetRawError`. No pagination unless a row says so. Throw-only SDK (no `…Result`).

### CROSS-OPERATION INVARIANTS

| Invariant | Operations | Enforced where |
| --- | --- | --- |
| `planHandle` on subscribe/switch must be a plan the app offers shoppers (non-archived product) | `Subscriptions.CreateSubscription` / `Subscriptions.UpdateSubscription` ← `Products.ListProducts` | before the write, in a shared `PlanCatalog.GetLegalPlansAsync` helper that both endpoints call (a single product-by-handle read would not prove it is offered) |
| `brand` on admin create-plan must be one of the shop's catalog brands | `Products.CreateProduct` / `ProductFamilies.CreateProductFamily` ← `IReadRepository<CatalogBrand>.ListAsync` (table `CatalogBrands`) | before any Maxio write, in the admin create-plan endpoint; match name ordinal-ignore-case; brand not found ⇒ 422 with the list of valid brand names |
| `subscriptionId` in every `/api/subscriptions/{id}…` route must be owned by the JWT caller | `ReadSubscription` ← `Customers.ReadCustomerByReference` (the customer created at subscribe time carries `reference` = JWT name) | before any status/usage/switch call: compare `Subscription.Customer.Reference` to `User.Identity.Name`; mismatch ⇒ 404 |
| `usage` component must be a usage-bearing component of that subscription | `SubscriptionComponents.ListUsages` ← `SubscriptionComponents.ListSubscriptionComponents` | the endpoint iterates only components of kind `MeteredComponent`/`PrepaidUsageComponent` returned for that subscription; no caller-supplied component id |
| `currency` on currency-prices must be a non-primary currency configured on the site | `ProductPricePoints.CreateProductCurrencyPrices` / `UpdateProductCurrencyPrices` ← `Sites.ReadSite` (`Currency`, `NonPrimaryCurrencies`) | before the write, in the admin currency-price endpoint (case-insensitive compare, send upper-case ISO code) |
| `planId` on currency-prices must be an existing product; the price point is that product's `DefaultProductPricePointId` | `ProductPricePoints.*CurrencyPrices` ← `Products.ReadProduct` | before the write; 404 from `ReadProduct` ⇒ 404 "plan not found" |
| `date` for next-billing-date must be a future calendar date | `Subscriptions.UpdateSubscription` ← request body | before the write (an impossible date silently rolls over, maxio-c4:updateSubscription.10; so parse as `DateOnly` and require > today) |
| `restart` only on `canceled`, `resume` only on `on_hold`, `pause` only on active/trialing | `ReactivateSubscription` / `ResumeSubscription` / `PauseSubscription` ← `ReadSubscription.State` | before the write; otherwise 409 with the state in the reason |

## 6. Assumptions & Blockers

**Assumptions**

- A1 (identity/ownership): `ClaimTypes.Name` (JWT) is the only identity claim; customer `reference` = that name. A subscriber's Maxio customer is found via `ReadCustomerByReference`, created on first subscribe with first/last name derived from the account's email local part and `Email` read from `UserManager<ApplicationUser>` (Identity). If the account has no email the subscribe call is refused 422 "account has no email address". decided in code (see BillingService).
- A2 (legal plan list): shoppers may subscribe to every **non-archived** Maxio product on the site (ListProducts default excludes archived, maxio-c4:listComponents.6; archived products are disabled for purchase, maxio-c4:archiveProduct.1-3), regardless of whether its family matches a catalog brand (sandbox may hold products not made by this app). Plan JSON: `id, handle, name, brand (= product_family.name), monthlyPrice (decimal, price_in_cents/100), currency prices not listed`.
- A3 (subscribe without card): signup sends no payment profile. A paid product without a payment method is refused for automatic collection (maxio-c4:createSubscription.7), so the call sets `payment_collection_method` to `Remittance` when `Site.RelationshipInvoicingEnabled == true`, else `Invoice` (allowed sets: maxio-c4:createSubscription.41 / every-request.42). Several subscriptions to different plans (and repeat plans) are allowed; the claim only blocks concurrent duplicates.
- A4 (cancel / restart semantics): `cancel` = immediate cancellation (no schedule fields) so the subscription becomes `canceled` and restart is meaningful; delayed cancellation rejected because it needs the Schedule-Subscription-Cancellation site feature (loud, maxio-c4:cancelSubscription.2) and leaves the subscription active. `restart` = `ReactivateSubscription` with `Resume.Bool(true)` and no card; allowed only when state is `canceled` (reactivate is also valid for Unpaid/Trial Ended, maxio-c4:reactivateSubscription.1, but the endpoint is "restart one they cancelled"); reactivation may charge/invoice (maxio-c4:reactivateSubscription.2-.4,.12) and can return a 3DS/`payment method` 422 ⇒ mapped to 4xx with Maxio's message.
- A5 (`paid`): `paid = (Subscription.BalanceInCents ?? 0) <= 0 && (AccountBalances.OpenInvoices?.BalanceInCents ?? 0) <= 0` and state is not `PastDue`/`Unpaid`/`SoftFailure`. Reason: `balance_in_cents` is the outstanding subscription balance, `open_invoices` is the sum of open payable invoices (relationship-invoicing sites); a subscription owed money on either is unpaid. Pending invoices are not counted (not yet payable). decided in code (see BillingService) (state list) / `Models/Subscription.cs` (balance doc) / `map/operations/SubscriptionInvoiceAccount.md`.
- A6 (pause/resume): pause with no `automatically_resume_at` (held until resumed). Maxio refuses pause when `next_billing_at` is within 24 h (maxio-c4:pauseSubscription.1) and when not eligible (422, .2) ⇒ surface as 409/422 with Maxio's reason. Resume allowed only from `on_hold` (maxio-c4:resumeSubscription.1); resuming after the renewal date charges immediately (.3) — expected, not an error.
- A7 (usage per day): usage rows have only `created_at` (with the site's UTC offset, every-request.12). The site time zone is not exposed on `Site`, so the call asks Maxio for a widened window (`since_date = D-1`, `until_date = D+2`, midnight UTC), pages it fully, and keeps rows whose own `CreatedAt` local calendar date (using the offset carried in the timestamp, never converted to UTC) equals `D`. Response = per-component list `{componentId, handle, name, unit, quantity (sum, decimal), entries[]}` plus `date` and `truncated`. Components of kind quantity-based/on-off/event-based are skipped (usage listing is invalid for quantity-based, maxio-c4:listUsages.1). `UNVERIFIED`: how the SDK serialises `DateTimeOffset` in the query (date vs full timestamp) — verify against sandbox.
- A8 (brand → product family): the brand name is sent as `brand` in the admin request body; matched ordinal-ignore-case against `CatalogBrands.Brand` (seeded table, `CatalogBrand`); the plan's Maxio product family is looked up by `name == brand name` and created on first use (handle = slug of brand). Admin create-plan: `price_in_cents = round(monthlyPrice × 100)`, `interval = 1`, `interval_unit = Month`, `description = name` (required by the model), handle = slug of the name (a taken handle ⇒ 409). decided in code (see BillingService).
- A9 (next billing date): admin sends `date` (`yyyy-MM-dd`); the app sends `next_billing_at` = that date at **12:00 UTC** (a bare date means noon in the site's zone, every-request.14; noon UTC keeps the same local calendar date for any site offset from -12 to +11). "Subscriber is billed on that date" = Maxio's `next_billing_at`, which becomes the anchor for later billing (maxio-c4:updateSubscription.11); subscription must not be `canceled`/`expired` (409). Verification: re-read and compare `CurrentPeriodEndsAt` local date (response carries no `next_billing_at`, maxio-c4:updateSubscription.12). A `billing_date_change` webhook is sent (.13) — not consumed here.
- A10 (currency price): `price` accepted as a decimal in major units. Because `CreateProductCurrencyPrice.Price` is an `int`, a fractional price is created with `floor(price)` and then fixed with `UpdateProductCurrencyPrices` (`double`) on the returned record id; existing entries (detected from `ReadProductPricePoint` currency prices) go straight to `UpdateProductCurrencyPrices` (update before create is refused, maxio-c4:updateProductCurrencyPrices.2). Only `Baseline` is created; a default price point that also has trial/initial prices needs those roles too (maxio-c4:createProductCurrencyPrices.2) ⇒ 422 with Maxio's message (our created plans have none).
- A11 (switch semantics): immediate product change via `UpdateSubscription` (`product_change_delayed` not set), not `MigrateSubscriptionProduct`: migrate requires an active/trialing subscription (loud, maxio-c4:migrateSubscriptionProduct.1), charges the new plan immediately and fails when a balance is due and no card is on file (.10). UpdateSubscription changes the product now with the new amount billed from the next period, no proration (maxio-c4:updateSubscription.3); a delayed change would not put the shopper on the new plan, so it is not used. Switching to the current plan ⇒ 409 (migration to current product fails, maxio-c4:migrateSubscriptionProduct.2; same rule applied here). No price point sent ⇒ default price point of the new product (.5).
- A12: Webhooks are not consumed (state is read from Maxio on every request; Maxio is the system of record). Currency of a subscription is not selectable at signup (out of scope).

**Blockers / items the main agent must verify against the sandbox during implementation (none stops planning)**

- B1 `UNVERIFIED`: whether the sandbox site is on Relationship Invoicing or Statements (decides `Remittance` vs `Invoice`); the code reads `Sites.ReadSite` per call (cache for the process lifetime is fine) rather than assuming.
- B2 `UNVERIFIED`: Maxio accepting a product change on a `canceled` subscription through `UpdateSubscription` (no business rule forbids it; the migrate rule recommends "cancel, change the product and reactivate" for trial_ended, maxio-c4:migrateSubscriptionProduct.1). If sandbox refuses with 422, fall back — decision for the main agent — to `ReactivateSubscription` → `UpdateSubscription` → `CancelSubscription`, which creates a reactivation charge (`paid` may flip to false) — or return 422 with Maxio's reason. Record the outcome in this row once settled.
- B3 `UNVERIFIED`: product default price point `use_site_exchange_rate` (cannot be set through `CreateOrUpdateProduct`); if true, Maxio may refuse custom currency prices (rule only says "non-custom price point"). Fallback: `ProductPricePoints.CreateProductPricePoint` with `UseSiteExchangeRate=false` + `PromoteProductPricePointToDefault` (open `map/operations/ProductPricePoints.md`), then currency prices on it.
- B4 `UNVERIFIED`: Multi-Currency enabled on the sandbox site and ≥1 non-primary currency defined; otherwise admin currency-price returns 422 "currency not configured on the site".
- B5 `UNVERIFIED`: whether `Maxio:BaseUrl` verbatim value needs a trailing-slash/`{site}` treatment by the SDK's URL builder (template-based); verify the generated request URL once with `Maxio:BaseUrl` set.
- B6 Plans created through `POST /api/admin/plans` also get a Public Signup Page automatically (maxio-c4:createProduct.102) — harmless, noted.
