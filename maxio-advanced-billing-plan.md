## 2. CONTRACT SHEET

> **Signatures are generated code, verbatim: each operation that takes input takes ONE request record as its first parameter (an operation with no inputs takes none), built with an object initializer using the record's own property names — never flat arguments.**
> **Every SDK type is written fully-qualified with the namespace its source path implies, taken from the path the map gives for THAT type, never from where a neighbouring type sits.** Namespaces: client/options `MaxioAdvancedBilling`; controllers `MaxioAdvancedBilling.Api`; models `MaxioAdvancedBilling.Models`; enums `MaxioAdvancedBilling.Models.Enums`; AnyOf unions `MaxioAdvancedBilling.Models.AnyOf`; errors `MaxioAdvancedBilling.Errors`; request records `MaxioAdvancedBilling.Requests.<Controller>`; `ServerEnvironment` `MaxioAdvancedBilling.Servers`; `BasicAuthCredentials` `MaxioAdvancedBilling.Core.Authentication.Basic`; `ApiException<T>` `MaxioAdvancedBilling.Core.Exceptions`; `RawError` `MaxioAdvancedBilling.Core.ErrorResponse`.

All operations: `(Request request, RequestOptions? requestOptions = null, CancellationToken cancellationToken = default)`, throw-only, no pagination unless stated, Auth `options.BasicAuth`, server group `Production`. Wire verb/route live in `src/MaxioAdvancedBilling/Api/<Controller>.cs`.

Error cases: **A** = `ApiException<{Op}Error>` with `TryGetErrorListResponse1(out ErrorListResponse1?)` [422] (or the accessor named) + `TryGetRawError` fallback; **B** = `ApiException<RawError>` (`StatusCode`, `ReadAsString()`, `ReadAsJson<T>()`).

### CROSS-OPERATION INVARIANTS

| Invariant | Operations | Enforced where |
| --- | --- | --- |
| Plan handle accepted by `POST /api/subscriptions` and `.../switch` must be one `GET /api/plans` offers (non-archived, shopper-visible product) | `Subscriptions.CreateSubscription` / `SubscriptionProducts.MigrateSubscriptionProduct` <- `Products.ListProducts` (all pages, `IncludeArchived` unset, `ArchivedAt == null`) | the shared plan-catalog service, called before `CreateSubscription` and before `MigrateSubscriptionProduct`; unknown/archived handle -> 400 with reason |
| `brand` accepted by `POST /api/admin/plans` must be a catalog brand of the shop | `ProductFamilies.CreateProductFamily` / `Products.CreateProduct` <- shop catalog brands (`IReadRepository<CatalogBrand>.ListAsync/GetByIdAsync`, the set `GET api/catalog-brands` returns) | before any Maxio write; brand id absent -> 400 "unknown brand". Brand is stored in Maxio as the plan's product family: family handle `eshop-brand-<CatalogBrand.Id>` (name = `CatalogBrand.Brand`), found via `ProductFamilies.ListProductFamilies` and created with `ProductFamilies.CreateProductFamily` only when absent |
| `{planId}` in `POST /api/admin/plans/{planId}/currency-prices` must be a plan the shop offers | `ProductPricePoints.CreateProductCurrencyPrices` <- `Products.ListProducts` (`Product.Id` in the returned set) | before `ReadSite`/currency write; not in set -> 404 "plan not found" |
| `currency` must be a site-level non-primary currency | `ProductPricePoints.CreateProductCurrencyPrices` <- `Sites.ReadSite` (`Site.NonPrimaryCurrencies`) | before the write; not in list (case-insensitive ISO, upper-cased) -> 400 with the allowed list; equal to `Site.Currency` -> 400 "primary currency" |
| Shopper `{subscriptionId}` (get, pause, resume, cancel, restart, switch, usage) must belong to the caller | all shopper-subscription operations <- `Customers.ListCustomerSubscriptions` for the customer whose `Reference == JWT ClaimTypes.Name` (found by `Customers.ReadCustomerByReference`) | the ownership guard BEFORE every shopper operation: no customer for the caller, or id not in that list -> 404 "subscription not found" (never 403, never reveal other shoppers' data). Then `ReadSubscription` for fresh state; additionally assert `Subscription.Customer.Reference == caller` |
| Mapping Maxio customer <-> JWT identity | `Customers.CreateCustomer.Reference` = caller's `ClaimTypes.Name` (user name = email in eShop) ; `Customers.ReadCustomerByReference.Reference` | one rule used everywhere (customer created at first subscribe with `Reference=<name>`, `Email=<name>`, FirstName/LastName derived from the e-mail local part); admin-role tokens use the same mapping and get NO cross-customer access on shopper routes |
| Admin `{id}` for next-billing-date must be a subscription the site holds | `Subscriptions.UpdateSubscription` <- `Subscriptions.ReadSubscription` (legal set = every subscription on the site, which is exactly what this lookup answers; the app offers no narrower set to staff) | before `UpdateSubscription`: 404 if absent; 409 if state is `canceled`/`expired`/`on_hold`-for-billing (see trap) |
| `componentId` for usage must be a metered component of this subscription | `SubscriptionComponents.ListUsages` <- `SubscriptionComponents.ListSubscriptionComponents` (`Kind == MeteredComponent`) | before `ListUsages`; quantity-based/other kinds are never queried |
| Subscription `reference` stored for reconciliation | `Subscriptions.FindSubscription` <- the `Reference` this app sent in `CreateSubscription` | set to a fresh GUID string per subscribe attempt, persisted in the claim row |

Project reference: `dotnet add src/PublicApi/PublicApi.csproj reference <plugin-root>/sdk/dotnet/src/MaxioAdvancedBilling/MaxioAdvancedBilling.csproj` (local to this machine; say so at handover).
- Auth: HTTP Basic: `options.BasicAuth = new MaxioAdvancedBilling.Core.Authentication.Basic.BasicAuthCredentials { Username = <Maxio:ApiKey>, Password = "x" }` (map *Servers & auth*; password is the literal `x`, not a secret).
- Servers: group `Production` is the only group these operations use (`https://{site}.chargify.com` Us / `https://{site}.ebilling.maxio.com` Eu; template var `{site}` set through `options.Server.Production.Us.Site` / `.Eu.Site` = `Maxio:Subdomain`). Group `Ebb` is not touched. `ServerEnvironment` has only `Us` and `Eu` — no sandbox member (see Production readiness #8).
- `Maxio:Environment` -> `options.Environment`: accept `US`/`EU` case-insensitively (the env var currently holds `US`); any other value fails startup.
- `Maxio:BaseUrl` (optional): when set and non-blank, set it verbatim as `options.Server.Production.Us.BaseUrl` AND `.Eu.BaseUrl` (the one matching `Environment` is used; the `{site}` template var is then unused if the string has none). When unset, leave the SDK default (derived from subdomain).

Values come from user-secrets (`dotnet user-secrets set "Maxio:ApiKey" ...` fed from env vars `MAXIO_API_KEY`, `MAXIO_SITE_SUBDOMAIN`, `MAXIO_ENVIRONMENT`, performed by the agent at run time, never written to a repo file). `appsettings.json` may carry the section with empty strings only. `Program.cs` already calls `AddEnvironmentVariables()`; `Maxio__ApiKey` style variables would also bind.

**DUPLICATE CLAIMS**

Store: a new EF entity in `CatalogContext` (the store the codebase keeps its records in), `MaxioClaim { Key (string, composite/primary key) , Reference, CreatedAt }`. In-memory mode (`UseOnlyInMemoryDatabase`) keeps it for the process lifetime; SQL Server mode needs an EF migration under `src/Infrastructure/Data/Migrations` (main agent adds it). The primary key is refused even by the in-memory provider (an Add + SaveChanges of an existing key throws `ArgumentException`/`DbUpdateException`). ## 6. Assumptions & Blockers

**Blockers:** none. (Duplicate-claim storage uses `CatalogContext`; if the deployment runs SQL Server an EF migration for `MaxioClaim` must be added by the main agent.)

**Assumptions:**
1. Identity mapping: Maxio customer `reference` == JWT `ClaimTypes.Name` (user name; equals e-mail in eShop). The JWT carries no id/email claim, so name is the only available identity; customer email = name, first/last name derived from the local part of the e-mail.
2. "Brand" in `POST /api/admin/plans` is the shop catalog brand (`CatalogBrand`); request accepts `brandId` (preferred) or a brand name. Maxio has no brand field on products, so brand = product family (`eshop-brand-<id>`), created on demand.
3. "Hidden/not-public" plans: the SDK exposes no such flag; only archived products are hidden. Products archived or with an archived family are never offered.
4. Shopper-visible 404 (not 403) for subscriptions the shopper does not own.
5. `paid` = no balance AND no open invoice with money due; credits count as owing nothing.
6. Subscribing without card details uses `Remittance` (fallback `Invoice`); paid plans therefore start `paid:false`.
7. Currency price must be a whole number (SDK `Price` is `int` on create); non-integer -> 400.
8. Plans are monthly (interval 1 month); price decimal -> cents with max 2 decimals.
9. Restart = reactivate with a new billing period (no `resume`); no `include_trial`.
10. Next-billing date for held/canceled subscriptions is refused (409) because they would not be billed on that date.
11. Maxio sandbox is a separate site selected by `Maxio:Subdomain`; `Maxio:Environment=US`.
12. Product price-point/AnyOf union shapes for `ProductIdModel`/`PricePointIdModel` were not opened (same int-or-string pattern as the three unions read); confirm from their files when writing the call.
13. Decided: endpoints in `src/PublicApi/MaxioEndpoints/`, service `MaxioBillingService` in `src/PublicApi/Maxio/`, claim entity `MaxioClaim` (`src/Infrastructure/Data/MaxioClaim.cs`, migration `AddMaxioClaims`), slug = lower-case alphanumerics joined by `-` (`Slug`).
14. Verified live in the sandbox: cancelled-subscription switch (migrate gets 422, reactivate then migrate works, `MaxioBillingService.SwitchAsync`); next billing date (200, Maxio holds the requested date); remittance subscribe works. NOT verifiable: currency prices (the sandbox site has no extra currencies enabled, endpoint answers 400 with that reason); the create/update currency-price calls were never executed against Maxio.
15. A stale claim older than 5 minutes is expired and retaken (`ClaimAsync`).
