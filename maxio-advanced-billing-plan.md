# Maxio Advanced Billing plan — eShopOnWeb subscriptions (PublicApi)

SDK root (plugin-relative): `sdk/dotnet/` · map: `sdk/dotnet/sdk-map.md` + `sdk/dotnet/map/operations/` · all **source** paths below are relative to that SDK root.
Integrate skill: `dotnet-integrate-maxio-advanced-billing`. Scope: Production server group only; 7 operations on 4 controllers.

## 1. Scope & sequence

| # | Step | Operations used |
| --- | --- | --- |
| 1 | Reference the SDK project (`src/MaxioAdvancedBilling/MaxioAdvancedBilling.csproj` in the plugin) from the project that hosts the Maxio service; bind `Maxio:` settings (`ApiKey`, `Subdomain`, `ProductFamilyHandle`, `BaseUrl`) with fail-fast validation; register the client once (DI). Secrets into PublicApi user-secrets (`UserSecretsId` already in `src/PublicApi/PublicApi.csproj`). | none (client construction) |
| 2 | Add two claim entities to `CatalogContext` (`src/Infrastructure/Data/CatalogContext.cs`, config classes beside `src/Infrastructure/Data/Config/BasketConfiguration.cs`): a customer-link row keyed by buyer, and an enrollment row keyed by the deterministic subscription reference. | 3 | Plan catalog service: list the family's products by handle, page manually, drop archived, return a result that says whether it was truncated. | `ProductFamilies.ListProductsForProductFamily` |
| 4 | `GET /api/subscription-plans` endpoint (JWT, any authenticated user), mirroring `src/PublicApi/CatalogItemEndpoints/CreateCatalogItemEndpoint.cs` (IEndpoint + `AddRoute`, `.WithTags`, response derives `BaseResponse` with `CorrelationId`). | step 3 |
| 5 | Ensure-customer: claim customer-link row → look up by reference → create if absent → record Maxio customer id; settle unknown outcomes by reference. | `Customers.ReadCustomerByReference`, `Customers.CreateCustomer` |
| 6 | Subscribe: validate plan handle against step 3's set → ensure-customer → claim enrollment row → look up by subscription reference → create if absent → record result; settle unknown outcomes by reference. | `ProductFamilies.ListProductsForProductFamily`, `Subscriptions.FindSubscription`, `Subscriptions.CreateSubscription` |
| 7 | `POST /api/subscriptions` endpoint (JWT; buyer = the token's `ClaimTypes.Name`, which `src/Infrastructure/Identity/IdentityTokenClaimService.cs` sets to the user name). Returns plan / price / state / next billing date. | step 6 |
| 8 | `GET /api/my-subscriptions`: customer id from the caller's stored link (no link and no Maxio match → empty list). | `Customers.ReadCustomerByReference` (only when no link row), `Customers.ListCustomerSubscriptions` |
| 9 | Error boundary: translate SDK exceptions to HTTP results in the Maxio service (existing `src/PublicApi/Middleware/ExceptionMiddleware.cs` maps `DuplicateException`→409, everything else→500). | all |
| 10 | Tests (stubbed `HttpClient`) for claims, unknown outcomes, truncation; build; live sandbox run with `UseOnlyInMemoryDatabase=true`. | all |

## 2. CONTRACT SHEET

> ⚠ **Signatures are generated code, verbatim.** Each operation that takes input takes ONE request record as its first parameter (an operation with no inputs takes none), built with an object initializer whose property names are the record's own — never flat arguments. Body-carrying operations put the body model on the record's `Body` member.
> ⚠ **Every SDK type is written fully-qualified with the namespace its source path implies**, taken from the path the map gives for THAT type — never from where a neighbouring type sits (e.g. `CustomerErrorResponse1` is `MaxioAdvancedBilling.Models`, its `Errors1` is `MaxioAdvancedBilling.Models.AnyOf`, `ErrorListResponse1` is `MaxioAdvancedBilling.Models`, `CreateSubscriptionError` is `MaxioAdvancedBilling.Errors`, `RawError` is `MaxioAdvancedBilling.Core.ErrorResponse`, `ApiException<T>` is `MaxioAdvancedBilling.Core.Exceptions`).

### CROSS-OPERATION INVARIANTS

| Invariant | Operations | Enforced where |
| --- | --- | --- |
| The plan handle a caller POSTs must be a non-archived product handle returned for the configured family (`handle:` + `Maxio:ProductFamilyHandle`) | `CreateSubscription.Body.Subscription.ProductHandle` ← `ProductFamilies.ListProductsForProductFamily` | In the subscribe service, before the enrollment claim and before `CreateSubscription`: read the plan set (step 3 service) and reject (400/422) a handle not in it; if the set came back truncated and the handle is absent, refuse rather than pass it through. |
| The customer id sent to subscribe must be the one Maxio returned for **this caller's** reference | `CreateSubscription.Body.Subscription.CustomerId` ← `Customers.CreateCustomer` / `Customers.ReadCustomerByReference` (stored on the caller's customer-link row) | In the subscribe service after ensure-customer: taken only from the link row keyed by the token's buyer id — never from the request body. |

## 6. Assumptions & Blockers

**Blockers:** none.

**Assumptions:**
1. Buyer identity = the JWT `ClaimTypes.Name` value (the user name, which `IdentityTokenClaimService` puts in the token); email and display names for `CreateCustomer` (first/last name are `required`) come from `UserManager<ApplicationUser>`, with names derived from the email/user name because `ApplicationUser` has no name fields.
2. `MAXIO_ENVIRONMENT` has no mandated `Maxio:` key. The plan does not bind it: `ServerEnvironment` stays at the SDK default `Us`, and the sandbox is chosen by the subdomain (or `Maxio:BaseUrl`). An EU-hosted site would need `Maxio:BaseUrl`.
3. Duplicate rule: one subscription per (buyer, plan handle). The deterministic reference blocks re-subscribing to the same plan after a cancellation, and allows the same buyer to hold Basic and Pro at once. Changing this means changing the enrollment key.
4. With `UseOnlyInMemoryDatabase=true`, claims do not survive a restart. Within a process, the PK still refuses concurrent duplicates. After a restart, the look-up-by-reference before each create (`ReadCustomerByReference`, `FindSubscription`) stops a second customer. It stops a second subscription only as far as `FindSubscription` sees the earlier one. On SQL Server the claims are durable, and the two new entities need an EF migration for `CatalogContext`. The in-memory provider ignores migrations.
5. The seeded plans do not require a payment method, so no card capture and no 3DS. Any listed product with `RequireCreditCard == true` is excluded from what can be subscribed.
6. The SDK is referenced as a `ProjectReference` into this plugin's install directory (`sdk/dotnet/src/MaxioAdvancedBilling/MaxioAdvancedBilling.csproj`). The repo builds only where the plugin is installed at that path, so CI and teammates must re-point it.
7. `GET /api/my-subscriptions` returns all of the caller's Maxio subscriptions, not only those in the configured family.

## 7. Source labels

Each **Source** cell holds one of three things. It is a map page or map-named file (relative to `sdk/dotnet/`), or `UNVERIFIED` (only live traffic settles it, and the sheet gives a defensive directive), or `YOUR CALL — not in the map` (an application decision, weighed against the task at implementation time).
