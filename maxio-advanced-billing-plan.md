No Blocker from missing capability.

Endpoint conventions (repo survey): `MinimalApi.Endpoint` style — one class per endpoint implementing `IEndpoint<IResult, TRequest, TDeps...>`, route in `AddRoute` via `app.MapGet/MapPost("api/...")`, `.Produces<TResponse>().WithTags("...")`, request/response types in sibling files `XEndpoint.XRequest.cs` / `XEndpoint.XResponse.cs` deriving `BaseRequest`/`BaseResponse` (correlation id). Exemplar to imitate: `src/PublicApi/CatalogItemEndpoints/CreateCatalogItemEndpoint.cs` (+ its `.CreateCatalogItemRequest.cs`/`.CreateCatalogItemResponse.cs`); read-endpoint exemplar `CatalogItemGetByIdEndpoint.cs`. Auth: `[Authorize(AuthenticationSchemes = JwtBearerDefaults.AuthenticationScheme)]` on the lambda as in the exemplar (without `Roles`). Errors: `src/PublicApi/Middleware/ExceptionMiddleware.cs` maps `DuplicateException` (`ApplicationCore/Exceptions`) to 409 and everything else to 500 — new failure modes needing 404/422/502 are returned as `Results.*` from the endpoint. Endpoints auto-register via `AddEndpoints()`/`MapEndpoints()` in `Program.cs`.

Caller identity (read in `src/Infrastructure/Identity/IdentityTokenClaimService.cs`): the JWT carries only `ClaimTypes.Name` (user name) and `ClaimTypes.Role`; there is NO user-id claim. Identity is therefore `User.Identity.Name`/`ClaimTypes.Name`, resolved to the stable `ApplicationUser.Id` via `UserManager<ApplicationUser>.FindByNameAsync` (already registered in `Program.cs`). The local keys and the Maxio customer `reference` use that `ApplicationUser.Id`, not a request field.

## 6. Assumptions & Blockers

Blockers: none from missing capabilities — every operation the task asks about exists in the map.

Assumptions and decisions the main agent must carry:

1. **Provider will reject, or not, subscriptions on plans requiring a card (UNVERIFIED).** The task states both plans do not require a payment method; the map shows `Product.RequireCreditCard` / `RequestCreditCard` on the listing. The plan sends no payment profile. If a listed product has `RequireCreditCard == true`, the plan is to exclude it from the plans listing and refuse to subscribe to it (decided in `ListPlansCoreAsync`) rather than expect the provider to accept the call.
2. **Default plan / Pro default.** The task wants `eshop-pro` as the "default subscribe target" but forbids hard-coding handles, and the only config keys allowed are the four under `Maxio:`. So `POST /api/subscriptions` requires the plan handle in its body (decision in `MaxioSubscriptionService.SubscribeCoreAsync`: no default plan; a missing handle returns 422). Tell the user if a default-plan key is wanted.
3. **Caller identity.** The JWT has only `Name` and `Role` claims; identity is the user name resolved to `ApplicationUser.Id` with `UserManager`. The Maxio customer `reference` is that Id.
4. **Customer name/email.** `CreateCustomer` requires `first_name`, `last_name`, `email`. `ApplicationUser` (Identity) has only user name/email; where a first/last name is absent the plan splits/falls back (e.g. the email local part for first name and a fixed placeholder for last name) — decided in `CreateCustomerAsync`: first name = email local part, last name = "Customer". Email comes from `ApplicationUser.Email`.
5. **404 on customer lookup is UNVERIFIED.** `ReadCustomerByReference` is Case B (raw); the status a missing reference returns is not in the map; code treats exactly 404 as "no customer" and anything else as failure.
6. **EF duplicate-key exception type** from the in-memory provider is to be confirmed by a test; both `DbUpdateException` and `InvalidOperationException` are handled until then.
7. **Migration.** A SQL Server migration is added for the two tables; it is not exercised in `UseOnlyInMemoryDatabase=true` dev runs. The in-memory store loses claims on restart, and the provider-side reference lookups in the subscribe path (customer by reference, subscription by reference) are what keep a restart from creating duplicates.
8. **Next billing date** is `Subscription.NextAssessmentAt`; it may be null (e.g. canceled states) and is returned as null then.
9. **The product listing's price** is `Product.PriceInCents` (long cents) with `Interval`/`IntervalUnit`; the subscription response price is `Subscription.ProductPriceInCents`.
10. **Not Blockers but verify live:** whether Maxio enforces reference uniqueness for customers and subscriptions (UNVERIFIED); whether `ListCustomerSubscriptions` truncates (UNVERIFIED).
