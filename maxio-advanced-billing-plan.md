# Maxio Advanced Billing plan: eShopOnWeb subscriptions (PublicApi)

SDK root (plugin-relative): `sdk/dotnet/` in the `maxio-advanced-billing` plugin. Every **source** cell below is relative to that root. SDK: `MaxioAdvancedBilling` (netstandard2.0, C# LangVersion 14), referenced as a `<ProjectReference>` to `<plugin-root>/sdk/dotnet/src/MaxioAdvancedBilling/MaxioAdvancedBilling.csproj`. That path only exists where the plugin is installed. Never copy the SDK into the repo.

Repo facts read for this plan (exemplars to imitate, read-only):
- Endpoint pattern: `MinimalApi.Endpoint` `IEndpoint<IResult, TRequest, ...>` with `AddRoute` + `HandleAsync`. Exemplar: `src/PublicApi/CatalogItemEndpoints/CreateCatalogItemEndpoint.cs`. Request/response types derive from `BaseRequest`/`BaseResponse` (`src/PublicApi/BaseMessage.cs` provides `CorrelationId()`).
- Auth: JWT bearer. `IdentityTokenClaimService` puts only `ClaimTypes.Name` (= user name, e.g. `demouser@microsoft.com`) and role claims in the token. There is no user-id claim (`src/Infrastructure/Identity/IdentityTokenClaimService.cs`).
- Records store: `CatalogContext` (`src/Infrastructure/Data/CatalogContext.cs`) through `EfRepository<T>` (`IRepository<T>`, `T : IAggregateRoot`). Entity configs go in `src/Infrastructure/Data/Config/*Configuration.cs`, applied by `ApplyConfigurationsFromAssembly`. Under `UseOnlyInMemoryDatabase=true` both contexts are EF InMemory (`src/Infrastructure/Dependencies.cs`). `BaseEntity.Id` is a store-generated `int`.
- Duplicate refusal: the codebase throws `DuplicateException` (`src/ApplicationCore/Exceptions/DuplicateException.cs`), and `src/PublicApi/Middleware/ExceptionMiddleware.cs` maps it to 409. Every other exception becomes a 500 that echoes `exception.Message`.
- Identity: `ApplicationUser : IdentityUser` has `UserName`/`Email` and no name fields. In-memory seeding re-creates users with new GUID `Id`s on every run (`src/Infrastructure/Identity/AppIdentityDbContextSeed.cs`).
- Tests: `tests/PublicApiIntegrationTests` boots `WebApplicationFactory<Program>`, and its config is only `appsettings.test.json` (`UseOnlyInMemoryDatabase: true`).
- `IMemoryCache` is already registered in `src/PublicApi/Program.cs`.

## 1. Scope & sequence

| # | Step | Operations used |
|---|------|-----------------|
| 1 | Reference the SDK project from `src/PublicApi` only (decided: keeps the machine-local reference and its Microsoft.Extensions 10.x dependencies out of `Infrastructure`, which the Web app also uses). `global.json` must roll forward to the installed .NET 10 SDK (the SDK uses C# 14) | none |
| 2 | Bind and validate `Maxio:` settings (`ApiKey`, `Subdomain`, `ProductFamilyHandle`, optional `BaseUrl`) with fail-fast on start. Register the SDK client as a singleton | client construction |
| 3 | Add claim entities `BillingCustomerLink` and `SubscriptionClaim` to `CatalogContext`. Each has a natural string primary key (see DUPLICATE CLAIMS) | none |
| 4 | Billing gateway service (one class wrapping the SDK, with error translation and per-call budget) | all below |
| 5 | `GET /api/subscription-plans`: list the plans of the configured family, paged up to a cap, excluding archived | `ProductFamilies.ListProductsForProductFamily` |
| 6 | Ensure the Maxio customer for the token's user: local link, then claim, then lookup by reference, then create if absent, then record | `Customers.ReadCustomerByReference`, `Customers.CreateCustomer` |
| 7 | `POST /api/subscriptions` `{ planHandle }`: validate the plan against step 5's set, ensure the customer (step 6), claim, run a provider-side existing-subscription check, create, then record. | 8 | `GET /api/my-subscriptions`: resolve the customer id (local link, else `ReadCustomerByReference`; 404 means an empty list), settle any `Unknown` claims, then list | `Customers.ReadCustomerByReference`, `Customers.ListCustomerSubscriptions`, `Subscriptions.FindSubscription` |
| 9 | Tests: unit tests on the gateway with a stubbed `HttpClient`, and integration tests updated with dummy `Maxio:` config | none |

Out of scope: metered usage on `api-call`, cancellation and plan change, payment capture, and webhooks.

## 3. Trap notes (by step)

- **Step 1:** the SDK is a local `ProjectReference` outside the repo, its own `Directory.Packages.props`/`Directory.Build.props` sit beside it, and it compiles with C# 14. A wrong reference path or TFM mismatch only shows at build. **MUST load `maxio-advanced-billing:dotnet-getting-started`**.
- **Step 2:** the HttpClient's lifetime and ownership, and when the singleton reads its options. Getting this wrong means socket exhaustion or a client built before config is bound. **MUST load `maxio-advanced-billing:dotnet-client-initialization`**.
- **Step 2:** a credential that is never set is skipped silently and the request goes out anyway. A blank key surfaces only as a 401 on the first call. **MUST load `maxio-advanced-billing:dotnet-authentication`**.
- **Step 2:** what `RetryOptions.Timeout` actually bounds versus the whole call including retries and backoff. Without that, the stated budget is fiction. **MUST load `maxio-advanced-billing:dotnet-configuration-resilience`**.
- **Step 2:** which logging switches emit the Basic `Authorization` header or the JSON body (with user email), and what the `MAXIOADVANCEDBILLINGCLIENT_LOG` variable forces when `LoggerFactory` is unset. **MUST load `maxio-advanced-billing:dotnet-configuration-resilience`**.
- **Step 2:** overriding `Server.Production.*.BaseUrl` / `.Site`: the precedence between the template, the environment and the override decides which host the sandbox traffic reaches. **MUST load `maxio-advanced-billing:dotnet-configuration-resilience`**.
- **Step 4–8:** building the per-operation request record (object initializer, required members, the `requestOptions`/`cancellationToken` positions). Flat arguments do not compile. **MUST load `maxio-advanced-billing:dotnet-calling-endpoints`**.
- **Step 5/7/8:** nullable response members (`SubscriptionResponse.Subscription`, `Customer.Id`, `Product.Handle`) and open enums (`SubscriptionState`, `IntervalUnit`) that may carry values the SDK does not declare. A naive `.Value` or `switch` throws on live data. **MUST load `maxio-advanced-billing:dotnet-models`**.
- **Step 6/7:** `CreateCustomer`/`CreateSubscription`/`FindSubscription` are Case A while `ReadCustomerByReference`/`ListCustomerSubscriptions` are Case B. A catch ladder per case decides whether a 404/422 is read or escapes as a 500. **MUST load `maxio-advanced-billing:dotnet-error-handling`**.
- **Step 7:** a cancellation from your own budget token or the caller's `RequestAborted` mid-`CreateSubscription` leaves the outcome unknown, and which exception type it surfaces as decides whether the settle path runs. **MUST load `maxio-advanced-billing:dotnet-error-handling`** and **`maxio-advanced-billing:dotnet-configuration-resilience`**.
- **Step 7:** the existing `ExceptionMiddleware` turns any unhandled exception into a 500 echoing `exception.Message`. An escaped SDK exception message (request URI with site subdomain) reaches the client. **MUST load `maxio-advanced-billing:dotnet-error-handling`**.
- **Step 9:** stubbing the SDK's HTTP, making a write fail at the connection, and asserting the outgoing request body and route. **MUST load `maxio-advanced-billing:dotnet-testing`**.

## 5. PRODUCTION READINESS

| # | Concern | Decision |
|---|---|---|
| 1 | Credential fail-fast | Bind `Maxio:` into a `MaxioSettings` options class with `ValidateOnStart()`. Startup fails when `Maxio:ApiKey` is missing or whitespace, when `Maxio:ProductFamilyHandle` is missing or whitespace, when `Maxio:Subdomain` is missing or whitespace **and** `Maxio:BaseUrl` is unset, or when `Maxio:BaseUrl` is set but is not an absolute http(s) URI. The Basic credential has two parts: username = ApiKey (checked) and password = the literal `x` (a protocol constant, not configuration). `tests/PublicApiIntegrationTests/appsettings.test.json` must carry dummy `Maxio:` values so the factory still boots. `YOUR CALL — not in the map` (mechanism) |
| 2 | Secret sourcing & rotation | Development: `dotnet user-secrets` on `src/PublicApi` (UserSecretsId already present), populated from `MAXIO_API_KEY` / `MAXIO_SITE_SUBDOMAIN` / `MAXIO_DEFAULT_PRODUCT_FAMILY`. Optionally a startup config mapping copies those env vars into `Maxio:ApiKey` / `Maxio:Subdomain` / `Maxio:ProductFamilyHandle` when the `Maxio:` keys are absent. Deployed: env vars `Maxio__ApiKey` etc. or a vault provider. Nothing goes in `appsettings*.json`. Options are built once when the singleton client is created, so **a rotated key takes effect only after a process restart**. Rotation without restart is not required |
| 3 | Total timeout budget | Each SDK call is wrapped in a `CancellationTokenSource` of **20 s**, linked to `HttpContext.RequestAborted`. This covers all attempts and backoff and is enforced in the gateway service. `RetryOptions.Timeout` is set no higher than that budget. The subscribe endpoint's whole flow (up to ~5 calls) is capped at **60 s** by a request-level CTS. Unknown-outcome settle reads use their own 20 s CTS, **not** linked to `RequestAborted`, so a client disconnect does not abandon settlement |
| 4 | Write-retry ownership | Keep `RetryOptions.Default()` methods (GET/HEAD/PUT/OPTIONS). The two POST writes (`CreateCustomer`, `CreateSubscription`) are **never** resent by the SDK, and POST must not be added. The application owns write retry only through the claim/settle paths. GET reads (`ListProductsForProductFamily`, `ReadCustomerByReference`, `ListCustomerSubscriptions`, `FindSubscription`) may be retried by the SDK |
| 5 | Idempotency & ambiguous writes | `CreateCustomer`: no key member on the record. The real dedupe is `CreateCustomer.reference`, which the provider holds unique per site (CreateCustomer remarks). Value: `"eshop:" + normalized user name` (stable across in-memory restarts, unlike the regenerated `ApplicationUser.Id`). Reconcile with `ReadCustomerByReference`. `CreateSubscription`: no key member. Settle rules (`YOUR CALL — not in the map`):
- **Triggers:** `SdkConnectionException`, `SdkTimeoutException`, a budget/abort cancellation, a 5xx, or a `ResponseDeserializationException` on a 2xx from the write. Each one triggers a re-read inside the write's own `catch`.
- **Found:** record `Linked`/`Completed` and return success.
- **Not found (404 / `TryGetNoContent`):** set the claim to `Unknown` (customer: release it and answer 503 "retry", because provider reference uniqueness makes a retry safe). Return **202 Accepted** with `status: "pending"`. An unreadable 200 from the re-read is never treated as "not found". The next POST or GET for that user re-runs `FindSubscription` with the **same** stored reference. If still absent, it re-issues `CreateSubscription` with that same reference under the claim it already owns.

## 6. Assumptions & Blockers

**Blockers:** none. Every capability in scope (list plans by family handle, find/create customer by reference, create subscription by product handle, list a customer's subscriptions, find a subscription by reference) is in the map.

**Assumptions:**
1. **User identity = `ClaimTypes.Name`** (the only identity claim the existing token carries). The email for `CreateCustomer` comes from `UserManager<ApplicationUser>.FindByNameAsync(name).Email`, falling back to the name when it is an email. `ApplicationUser` has no first or last name, so `FirstName` = email local-part and `LastName` = `"eShopOnWeb"` (both required by `CreateCustomer`). `YOUR CALL — not in the map`.
2. **Customer reference = `"eshop:" + normalized user name`,** not `ApplicationUser.Id`, because in-memory seeding regenerates user GUIDs each run. This keeps one Maxio customer per eShop user across restarts. Consequence: two different eShopOnWeb deployments sharing one Maxio site would share customers for the same user name. `YOUR CALL — not in the map`.
3. **`MAXIO_ENVIRONMENT` is not bound.** The task mandates exactly four `Maxio:` keys, and none selects the SDK environment, so `ServerEnvironment.Us` (the SDK default) is used. A non-US site is reached via `Maxio:BaseUrl`. No new configuration key is invented.
4. **Durability of claims:** under `UseOnlyInMemoryDatabase=true` the `CatalogContext` claims live only for one process run (as the task states). Cross-restart duplicate protection then rests on Maxio's customer-reference uniqueness and the `ListCustomerSubscriptions` pre-check. Under SQL Server the claims persist, and the two new entities need an EF migration on `CatalogContext`.
5. **Subscribe without payment details** — RESOLVED on live sandbox traffic: with `payment_collection_method` omitted Maxio returned 422 "No payment method was on file"; the integration now sends `remittance` (invoice collection) and subscribe returns 201 `active`. Any other 422 still surfaces to the caller as 422 with Maxio's `errors` strings.
6. **Subscription `reference` uniqueness** at the provider is `UNVERIFIED` (not stated in the map). The design uses a fresh GUID-based reference per claim, so it does not depend on it.
7. **"Next billing date"** returned to the user = `NextAssessmentAt ?? CurrentPeriodEndsAt`. Plan price comes from `Product.PriceInCents`. The subscription price comes from `Subscription.ProductPriceInCents`. Both are converted to decimal dollars. `YOUR CALL — not in the map`.
8. **`GET /api/my-subscriptions`** returns all of the customer's Maxio subscriptions (Maxio is the system of record), not only those created through this API. `YOUR CALL — not in the map`.
9. **Build environment:** `global.json` pins `8.0.x` with `rollForward: latestFeature`, which cannot roll to the only installed SDK (.NET 10). The main agent must loosen it (e.g. `latestMajor`); the SDK project additionally needs the C# 14 compiler. The SDK `ProjectReference` is machine-local (plugin install path), so CI and teammates need the plugin installed or the reference re-pointed.
