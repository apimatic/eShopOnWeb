# Maxio Advanced Billing integration plan — eShopOnWeb subscriptions

SDK: APIMatic Maxio Advanced Billing .NET SDK, root namespace `MaxioAdvancedBilling`, source at plugin-relative `sdk/dotnet/` (project `sdk/dotnet/src/MaxioAdvancedBilling/MaxioAdvancedBilling.csproj`, `netstandard2.0`, C# 14 — needs the .NET 10 SDK to build). Map: `sdk/dotnet/sdk-map.md` + `sdk/dotnet/map/operations/*.md`. All `source` cells below are relative to `sdk/dotnet/`.

Repo facts read for this plan (exemplars to imitate, read at edit time):
- Endpoint convention: `IEndpoint<IResult, TRequest, ...>` class with `AddRoute` + `HandleAsync`, request/response split into `Endpoint.Request.cs` / `Endpoint.Response.cs` partial-named files, `BaseRequest`/`BaseResponse` correlation id — exemplar `src/PublicApi/CatalogItemEndpoints/CreateCatalogItemEndpoint.cs`.
- JWT carries ONLY `ClaimTypes.Name` (= Identity user name, which is the e-mail for seeded users) and `ClaimTypes.Role` — `src/Infrastructure/Identity/IdentityTokenClaimService.cs`. There is no user-id claim.
- Store the app owns: EF Core `CatalogContext` (`src/Infrastructure/Data/CatalogContext.cs`), configurations via `IEntityTypeConfiguration<T>` in `src/Infrastructure/Data/Config/` (exemplar `OrderConfiguration.cs`); in-memory provider when `UseOnlyInMemoryDatabase=true` (`src/Infrastructure/Dependencies.cs`).
- Duplicate convention: `Microsoft.eShopWeb.ApplicationCore.Exceptions.DuplicateException` → HTTP 409 by `src/PublicApi/Middleware/ExceptionMiddleware.cs` (anything else → 500).
- PublicApi has `UserSecretsId` in `src/PublicApi/PublicApi.csproj`; integration tests host the real `Program` via `WebApplicationFactory<Program>` (`tests/PublicApiIntegrationTests/ProgramTest.cs`, config `appsettings.test.json`).

## 1. Scope & sequence

| # | Step | Operations |
| --- | --- | --- |
| 1 | Reference the SDK project from the project that fronts Maxio (Infrastructure); bind `Maxio:` settings (`ApiKey`, `Subdomain`, `ProductFamilyHandle`, `BaseUrl`) into an app options class; validate at startup; register the client once via `AddMaxioAdvancedBillingClient` in PublicApi `Program.cs` | — (client construction) |
| 2 | ApplicationCore: `ISubscriptionBillingService` interface + app DTOs (plan, subscription summary, list-result with completeness flag); Infrastructure: one service class that fronts every SDK call, owns the per-request budget and the error translation | — |
| 3 | Claim store: new entity `SubscriptionEnrollment` (PK = eShop user name) + `IEntityTypeConfiguration` + `DbSet` on `CatalogContext` | — |
| 4 | Plans: walk the family's products page by page (bounded), drop archived, map to plan DTOs; `GET /api/subscription-plans` | `ProductFamilies.ListProductsForProductFamily` |
| 5 | Ensure customer (idempotent by reference = eShop user name): read by reference; create on 404; on 422 or unknown outcome re-read by reference | `Customers.ReadCustomerByReference`, `Customers.CreateCustomer` |
| 6 | Subscribe `POST /api/subscriptions`: validate handle against step-4 list → take claim → ensure customer (step 5) → **reconcile before create** (the claim does not survive a restart of the in-memory store): `FindSubscription` by the deterministic reference, then `ListCustomerSubscriptions` for a live subscription on a family plan — found same plan → record Active, 200 replay; found other plan → record Active with that plan, 409; read failure → error + release claim, never create → only if nothing found: create subscription with deterministic subscription `reference` and `payment_collection_method = remittance` → record result; settle unknown outcomes by reference | `ProductFamilies.ListProductsForProductFamily`, `Customers.*` (step 5), `Subscriptions.CreateSubscription`, `Subscriptions.FindSubscription`, `Customers.ListCustomerSubscriptions` (fallback) |
| 7 | `GET /api/my-subscriptions`: settle any `Unknown` claim first, then read customer by reference (404 → empty list) and list its subscriptions (Maxio is the system of record) | `Customers.ReadCustomerByReference`, `Customers.ListCustomerSubscriptions`, `Subscriptions.FindSubscription` (settle) |
| 8 | Secrets into PublicApi user-secrets under the `Maxio:` keys; tests (unit with stubbed HttpClient for the failure paths; integration host gets non-secret placeholder `Maxio:` values so fail-fast does not break existing tests) | — |

Out of scope (no operation needed): metered usage for `api-call`, cancellation, plan change, payment capture. Server group `Ebb` is never touched.

### CROSS-OPERATION INVARIANTS

| Invariant | Operations | Enforced where |
| --- | --- | --- |
| The `productHandle` a caller POSTs must be the `Product.Handle` of a non-archived product that `ListProductsForProductFamily` returned for `handle:{Maxio:ProductFamilyHandle}` — never pass a caller handle straight to `CreateSubscription` (a product outside the family, e.g. one seeded elsewhere on the site, would otherwise be subscribable) | `Subscriptions.CreateSubscription` ← `ProductFamilies.ListProductsForProductFamily` | In the subscribe method of the Infrastructure billing service (`MaxioSubscriptionBillingService.SubscribeAsync`, via `MaxioSubscriptionBillingService.ReadPlansAsync`), BEFORE the claim is taken and before `CreateSubscription`: call the same plan-listing member that serves `GET /api/subscription-plans`; unknown handle → 400/422 to caller, no claim, no Maxio write. If the list came back truncated (PAGED READS) and the handle is not in it → refuse (fail closed), do not call `CreateSubscription` |
| The `CustomerId` sent to `CreateSubscription` / `ListCustomerSubscriptions` must be the `Customer.Id` returned by `ReadCustomerByReference`/`CreateCustomer` for THIS caller's reference (never a stored id from another user, never a caller-supplied id — the request contract carries no customer id) | `Subscriptions.CreateSubscription`, `Customers.ListCustomerSubscriptions` ← `Customers.ReadCustomerByReference` / `Customers.CreateCustomer` | In the ensure-customer member of the billing service, which returns the id it resolved for `reference = caller user name`; the subscribe and my-subscriptions members take the id only from it |

### DUPLICATE CLAIMS

Order for both rows: **claim → SDK call → record the result**; release the claim (delete the row) when Maxio definitively refuses the call (Case A 422 / Case B 4xx other than an ambiguous outcome).

Under `UseOnlyInMemoryDatabase=true` the claim row is lost on restart, so the PK refusal alone cannot stop a user who subscribed before the restart. Between the customer step and `CreateSubscription`, `MaxioSubscriptionBillingService.FindExistingSubscriptionAsync` (called from `EnrollAsync`) re-reads Maxio — `FindSubscription` by reference, then `ListCustomerSubscriptions` filtered to live subscriptions on family plans. A hit is recorded on the claim as `Active` (with the plan Maxio holds) and returned as a 200 replay or a 409 for a different plan. A read failure releases the claim and returns an error, so the code never falls through to create. Tests: `Subscribe_AfterRestart_SubscriptionFoundByReference_IsAlreadySubscribed_WithoutCreating`, `Subscribe_AfterRestart_LiveSubscriptionToOtherPlanInCustomerList_IsConflict_AndRecorded`, `Subscribe_AfterRestart_LiveSamePlanInCustomerList_IsAlreadySubscribed`, `Subscribe_EndedSubscriptionsAndOtherFamilies_AreIgnored_AndCreates`, `Subscribe_NothingAtMaxio_ChecksThenCreates_CustomerAndSubscription`, `Subscribe_PreCreateCheckFails_ReleasesClaim_AndNeverCreates`.

## 6. Assumptions & Blockers

**Blockers:** none. Every operation the hero flow needs is in the map (list family products by `handle:`, customer read-by-reference/create, subscription create/find-by-reference, list customer subscriptions).

**Assumptions:**
1. **Customer reference = eShop user name** (`ClaimTypes.Name`), not the Identity user id: the JWT carries no id claim (`IdentityTokenClaimService.cs`), and under `UseOnlyInMemoryDatabase=true` the seeded users get new ids on every restart, which would orphan the Maxio customer. User name is stable across restarts. `CreateCustomer.Email` = the Identity user's e-mail (fallback: user name); `FirstName`/`LastName` are required by the model but eShop has no such fields → first name = e-mail local part, last name = `"eShop"` (YOUR CALL).
2. **One subscription per eShop user through this API** (claim PK = user name). A second POST for the same plan replays the existing subscription; for a different plan → 409. Plan change/cancel/resubscribe-after-cancel are out of scope.
3. **Claim durability:** `CatalogContext` outlives the process under SQL Server; under the mandated `UseOnlyInMemoryDatabase=true` it is lost on restart. Across a restart, Maxio-side reconciliation (customer by reference; subscription by deterministic reference / customer's live subscriptions on family plans, checked before every `CreateSubscription` by `FindExistingSubscriptionAsync`) prevents a second customer and lets the subscribe path detect an existing subscription before creating — so the in-memory mode remains safe for a single instance. A SQL Server deployment needs an EF migration for the new table (implementer adds one if the tooling runs; migrations are ignored in-memory).
4. **MAXIO_ENVIRONMENT is not bound**: the task assigns `Maxio:` keys only to MAXIO_API_KEY, MAXIO_SITE_SUBDOMAIN, MAXIO_DEFAULT_PRODUCT_FAMILY; the SDK has no sandbox environment (only `Us`/`Eu`), so the sandbox is selected by site. EU-hosted sites are reached through `Maxio:BaseUrl`.
5. **"Next billing date"** shown to the user = `Subscription.NextAssessmentAt` (when Maxio next tries to capture payment), falling back to `CurrentPeriodEndsAt` when null; **price** = `Subscription.ProductPriceInCents` (fallback `Product.PriceInCents`) / 100 as decimal USD. Plan list price = `Product.PriceInCents` with `Interval` + `IntervalUnit`.
6. **Archived products** are excluded client-side (`ArchivedAt != null`) regardless of the server default for `IncludeArchived`.
7. UNVERIFIED (only live traffic can settle): (a) `ReadCustomerByReference` returns 404 for an unknown reference — code must treat 404 as "not found" and any other non-2xx as an error, never as "not found"; (b) a literal `Maxio:BaseUrl` with a trailing `/` may produce a doubled slash — strip a trailing `/` before assigning; (c) Maxio's uniqueness of subscription `reference` — not relied on.
8. Runtime: projects target `net8.0`; with only the .NET 10 SDK/runtime installed, run with roll-forward (e.g. `DOTNET_ROLL_FORWARD=Major`) — the main agent's environment concern, noted here because the SDK project needs the .NET 10 SDK (C# 14) to compile.
