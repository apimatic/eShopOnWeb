## 1. Scope & sequence

0. **Wiring.** Add `ProjectReference` to `<plugin-root>/sdk/dotnet/src/MaxioAdvancedBilling/MaxioAdvancedBilling.csproj` from `src/PublicApi` (machine-local path; say so in the hand-over). Bind `Maxio:ApiKey`, `Maxio:Subdomain`, `Maxio:Environment`, `Maxio:BaseUrl` (the exact four keys; no defaults, no literals). Register ONE `MaxioAdvancedBillingClient` singleton. Secrets: `MAXIO_API_KEY`, `MAXIO_SITE_SUBDOMAIN`, `MAXIO_ENVIRONMENT` are loaded into .NET user-secrets (`dotnet user-secrets set "Maxio:ApiKey" ...` from the env vars, run against `src/PublicApi`), never written to a repo file. `Ops: none`.
1. **Plans (GET /api/plans, any signed-in user).** `ProductFamilies.ListProductFamilies` is not needed; `Products.ListProducts` (paged by hand) + catalog brands from `IRepository<CatalogBrand>`; keep products with `ArchivedAt == null` whose `Product.ProductFamily.Name` equals a catalog brand (ordinal-ignore-case). This filtered set is "the plans the shop offers" and is reused by steps 2, 6, 9.
2. **Subscribe (POST /api/subscriptions, signed-in).** Body = plan handle. Check handle is in the offered set (step 1); `Sites.ReadSite` to choose the no-card collection method; `Customers.ReadCustomerByReference` (reference = JWT `Name`) — present: `CustomerReference`, absent (404): `CustomerAttributes` incl. `Reference`; then `Subscriptions.CreateSubscription`. Duplicate claim (§5) before the call.
3. **Subscription page (GET /api/subscriptions/{subscriptionId}).** `Subscriptions.ReadSubscription` -> ownership check (`Subscription.Customer.Reference` vs JWT `Name`, else 404 with reason) -> `SubscriptionInvoiceAccount.ReadAccountBalances` -> `paid`.
4. **Pause / resume.** ownership check, then `SubscriptionStatus.PauseSubscription` / `ResumeSubscription`.
5. **Cancel / restart.** ownership check, then `SubscriptionStatus.CancelSubscription` (immediate, no schedule fields) / `ReactivateSubscription` (only when state is `canceled`).
6. **Switch plan (POST .../switch, new plan handle).** ownership check; target in offered set and different from the current product; active/trialing -> `SubscriptionProducts.MigrateSubscriptionProduct`; every other state including `canceled` -> `Subscriptions.UpdateSubscription` (product change, no reactivation); re-read with `ReadSubscription` and confirm `Product.Handle` == target before answering success.
7. **Usage for a day (GET .../usage?date=YYYY-MM-DD).** ownership check; strict date parse (400 on bad format); `SubscriptionComponents.ListSubscriptionComponents` -> metered components; per component `SubscriptionComponents.ListUsages` (since = date, until = date + 1 day), paged, then keep only usages whose own `CreatedAt` calendar date (offset as returned) equals the requested date.
8. **New plans (POST /api/admin/plans, Administrators).** Body name, monthly price (decimal, shop-currency major units -> `PriceInCents`), brand. Brand must be a catalog brand (`IRepository<CatalogBrand>`); find the product family named like the brand (`ProductFamilies.ListProductFamilies`) else `ProductFamilies.CreateProductFamily`; then `Products.CreateProduct` with monthly interval.
9. **Price in another currency (POST /api/admin/plans/{planId}/currency-prices).** planId in offered set (step 1 ids); `Sites.ReadSite` -> currency in `NonPrimaryCurrencies`; plan's default price point read with `ProductPricePoints.ReadProductPricePoint` (`CurrencyPrices = true`); `CreateProductCurrencyPrices` when that currency has no row, `UpdateProductCurrencyPrices` when it has; read back to confirm.
10. **Next billing date (PUT /api/admin/subscriptions/{id}/next-billing-date).** `Subscriptions.ReadSubscription` (state/eligibility) -> `Subscriptions.UpdateSubscription` (`NextBillingAt`) -> `ReadSubscription` and compare `CurrentPeriodEndsAt` date (the update response carries no `next_billing_at`).

> ⚠ Every SDK type is written fully-qualified with the namespace its source path implies, taken from the path the map gives for THAT type, never from where a neighbouring type sits. ### CROSS-OPERATION INVARIANTS

| Invariant | Operations | Enforced where |
| --- | --- | --- |
| a plan handle accepted by Subscribe must be a plan the shop offers (non-archived product whose family name is a catalog brand) | `CreateSubscription` ← `ListProducts` (+ `IRepository<CatalogBrand>.ListAsync`) | before `CreateSubscription` is called, in the Subscribe endpoint's offered-plan check (a single `ReadProductByHandle` is NOT enough: it proves existence, not that the shop offers it) |
| the new plan handle accepted by Switch must be in the same offered set AND differ from the subscription's current `Product.Handle` | `MigrateSubscriptionProduct` / `UpdateSubscription` ← `ListProducts`, `ReadSubscription` | before the write, in the Switch endpoint |
| the brand accepted by New plan must be a brand in the shop's catalog | `CreateProductFamily` / `CreateProduct` ← `IRepository<CatalogBrand>.ListAsync` (repo, not Maxio) | before `ListProductFamilies`/`CreateProductFamily`/`CreateProduct`, in the New plan endpoint |
| `planId` accepted by currency-prices must be the `Id` of an offered plan | `CreateProductCurrencyPrices` / `UpdateProductCurrencyPrices` ← `ListProducts` | before `ReadProductPricePoint`, in the currency-prices endpoint |
| `currency` accepted by currency-prices must be one of the site's non-primary currencies | `CreateProductCurrencyPrices` ← `ReadSite` (`NonPrimaryCurrencies`) | before the write, in the currency-prices endpoint |
| `{subscriptionId}` accepted from a shopper must belong to the caller | `PauseSubscription`/`ResumeSubscription`/`CancelSubscription`/`ReactivateSubscription`/`MigrateSubscriptionProduct`/`UpdateSubscription`/`ListUsages`/`ReadAccountBalances` ← `ReadSubscription` (`Customer.Reference` == JWT `Name`, the reference stamped by Subscribe) | at the top of each shopper endpoint, before any other Maxio call; mismatch answers 404 with a reason (do not reveal that the id exists) |
| a component read for usage must be a metered component of THAT subscription | `ListUsages` ← `ListSubscriptionComponents` (`Kind == MeteredComponent`, not archived) | before `ListUsages`, in the usage endpoint (rule `listUsages.1`: quantity-based components are refused) |
| a Next-billing-date subscription must be in a state that will actually be billed | `UpdateSubscription` ← `ReadSubscription` (`State`) | before the write, in the next-billing-date endpoint |

- There is NO sandbox `ServerEnvironment`: sandbox traffic = a Maxio **test site** subdomain plus that site's API key, both supplied via `Maxio:*`; the Maxio test site is what keeps test traffic off the live system.

## 3. Trap notes

| Step | Hazard | Pointer |
| --- | --- | --- |
| 0 | the SDK has its own env-var credential fallback and a literal `"subdomain"` default host — a half-bound client calls the wrong host or authenticates with the wrong source | MUST load `maxio:dotnet-client-initialization` and `maxio:dotnet-authentication` |
| 0 | the Maxio `HttpClient`, options and client lifetime decide whether rotated secrets, timeouts and DI scopes behave as you expect | MUST load `maxio:dotnet-client-initialization` |

## 6. Assumptions & Blockers

**Blocker-class — OUTCOMES (settled during implementation; headless run, decided without the user):** (1) no-card signup WORKS in the sandbox with `Invoice`/`Remittance` collection: verified. (2) brand = product family implemented; a cross-brand migrate may drop components (not handled; documented risk). (3) currency prices: the sandbox site has no non-primary currencies enabled, so the success path could not be exercised; the endpoint answers 422 with the reason (verified), whole-number create only.

**Original blocker notes:**

1. **No-card signup.** Maxio refuses a paid product signup with no payment method (rule `createSubscription.7`; `createSubscription.9`). The plan sends no card and picks a non-card `PaymentCollectionMethod` from `ReadSite` (`Remittance` when `RelationshipInvoicingEnabled`, else `Invoice`; the card-less methods valid per architecture, `every-request.16`/`createSubscription.41`). The map does not say whether those methods satisfy rule `.7`. If the sandbox answers 422, subscribe cannot be built without card details and needs the user's decision. `UNVERIFIED` (only sandbox traffic settles it).
2. **Brand <-> Maxio mapping.** Maxio products have no brand field and custom metadata exists only for subscriptions and customers (`Models/Enums/ResourceType.cs`: `Subscriptions`, `Customers`). The plan maps **brand = product family** (family name = catalog brand name, created on first use). Consequence: Maxio does not migrate components across product families (rule `migrateSubscriptionProduct.5`) and drops coupons (`.6`), so a switch between plans of different brands loses the subscription's metered components — and then Usage returns nothing. Needs the user's confirmation, or a decision that cross-brand switches re-create component allocations (no operation in this plan does that).
3. **Currency price units.** `CreateProductCurrencyPrice.Price` is `int`; `UpdateCurrencyPrice.Price` is `double`; the model docs give no unit. A fractional price (for example 9.99) cannot be created through the SDK type. Plan: create path accepts only whole-number prices (4xx with reason otherwise); update path takes decimals; read back and compare. `UNVERIFIED` as to unit (major units assumed).

**Assumptions (minor; decide at implementation):**

4. Identity -> Maxio customer: `Customer.Reference` = JWT `ClaimTypes.Name` (the only identity claim the JWT carries). Ownership = `Subscription.Customer.Reference` equals it (ordinal-ignore-case); other callers get 404 with a reason. Case sensitivity of Maxio's reference match is `UNVERIFIED`. Customers created by Subscribe need `FirstName`/`LastName`/`Email` (rule `createSubscription.6`) but the JWT has only the username: email = username, first/last name derived from the username's local part — DECIDED, see §7. A concurrent first subscribe for the same shopper can hit "reference already used" (rule `createCustomer.1`): re-read by reference and retry once with `CustomerReference`.
5. **`paid`.** `paid = true` iff the amount owed is 0: `ReadAccountBalances.OpenInvoices.BalanceInCents` is 0 or null AND `Subscription.BalanceInCents` is 0 or null; if both are null the answer is 4xx "balance unavailable" rather than a guess. Pending invoices, service credits and prepayments are not "owed". Which of the two the sandbox site populates (Relationship Invoicing vs Statements) is `UNVERIFIED`. Restart sends `PreserveBalance = true` so that reactivation does not clear an owed balance and flip `paid` (rule `reactivateSubscription.7`: without it the balance is cleared) — DECIDED, see §7.
6. **Switch.** Active/trialing -> `MigrateSubscriptionProduct` (rule `.1`: only those states); `PreservePeriod` choice (true = prorated charge, billing date kept; false = period reset and full price charged now, rules `.8/.9`; a 422 "not eligible for a prorated migration" means retry unprorated, `.11`) is DECIDED, see §7. Any other state, including `canceled`: `UpdateSubscription` with `ProductHandle` (rule `updateSubscription.3`: product changes now, charge at next period); whether Maxio accepts a product change on a canceled subscription is `UNVERIFIED` — the post-write `ReadSubscription` check on `Product.Handle` decides, and a refusal is answered as 4xx with Maxio's reason. A switch never reactivates (restart is separate).
7. **Cancel** = immediate cancel (no body). **Pause** = indefinite hold (no auto-resume); refused by Maxio when `next_billing_at` is within 24 h or the subscription is not eligible (rules `pauseSubscription.1/.2`) -> 409/422 with the reason. **Resume** after the renewal date behaves like a reactivation and charges immediately (rule `resumeSubscription.3`). `Restart` only when `State == Canceled`, else 409 (rule `reactivateSubscription.1`).
8. **Next billing date.** Input is a calendar date, must be in the future and valid; the app sends noon UTC of that date (Maxio's site time zone is not exposed by `ReadSite`, so the instant is DECIDED, see §7). Allowed only for states that renew (`Active`, `Trialing`, `PastDue`, `SoftFailure`); `Canceled`, `OnHold`/`Paused`, `Expired` and the like are refused 4xx (they do not renew, rule `pauseSubscription.3`), and a subscription with a non-null `SnapDay` (calendar billing) is refused (`snap_day` governs its billing date). Maxio then bills on that date through its own renewal (`updateSubscription.10-.12`; nothing in this app bills); verified by `CurrentPeriodEndsAt`. With a `Remittance`/`Invoice` method, "billed" means an invoice is issued, not a charge.
9. **Usage "day".** `ListUsages` takes `since_date`/`until_date` as midnights (rule `listUsages.2`); the app sends since = date, until = date + 1 and then keeps only rows whose own `CreatedAt` calendar date equals the date (timestamps/dates are site-local, rules `every-request.12/.13`; the SDK's doc calls the `until` bound inclusive of midnight, so next-day-midnight rows must be dropped). Metered kind only (`MeteredComponent`); prepaid usage components are not included (task says metered). Usage recorded by "another system" is read, never written.
10. **New plan.** Maxio requires `Description` — derived from the name (DECIDED, see §7); interval = 1 month; `PriceInCents` = round(price * 100) of a positive decimal; handle derived from brand + name slugs so the plan is findable (`ReadProductByHandle`) and Maxio refuses duplicate handles. Price must be >= 0 (rule `createProductPricePoint.2`). Request field names of the app's own endpoints (`planHandle`, `name`, `price`, `brand`, `currency`, `nextBillingDate`) are DECIDED, see §7; `brand` = brand NAME matched ordinal-ignore-case against `CatalogBrand.Brand`.
11. **Currency prices.** Default price point (`Product.DefaultProductPricePointId`) only; a plan whose price point has a trial or initial charge (`TrialPriceInCents`/`InitialChargeInCents` non-zero) is refused 4xx because currency prices must mirror all roles (rule `createProductCurrencyPrices.2`); only the `Baseline` role is written. Existing row for the currency -> `UpdateProductCurrencyPrices`, else `CreateProductCurrencyPrices`. A price point with `UseSiteExchangeRate == true` may ignore explicit prices (rule `listComponentPricePoints.2`): read back and compare, and answer 4xx if the stored value differs — `UNVERIFIED`.
12. Plans list = non-archived products only; `IncludeArchived` stays unset (archived products cannot be subscribed to via the Billing Portal, rule `archiveProduct.2`; archiving does not stop existing subscribers, `.1`, so existing subscriptions to an archived plan still show on the subscription page).
13. Auth on the shopper endpoints: JWT scheme required; any signed-in role. Staff endpoints: `Administrators`. Unauthenticated -> 401 (framework), non-admin on staff routes -> 403 (framework), as the existing admin endpoints.
14. Webhooks (state-change, payment events) are not consumed: every answer is re-read from Maxio (system of record); no local copy of subscription state is kept except the claim rows.
15. Migration for SQL Server: the claim entity needs an EF migration under `src/Infrastructure/Data/Migrations`; in-memory/test runs need none.
