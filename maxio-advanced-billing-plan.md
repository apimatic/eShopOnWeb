Main-agent questions answered (all from the map/source):
- Customer by reference: **yes** — `Customers.ReadCustomerByReference` (`GET /customers/lookup.json?reference=`), remarks: "Returns a customer by their unique reference ID. It will return a single match."
- Subscription by reference: **yes** — `Subscriptions.FindSubscription` (`GET /subscriptions/lookup.json?reference=`), remarks: "Finds a subscription by its reference."; 404 is typed (`TryGetNoContent`).
- Create-subscription accepts a reference: **yes** — `CreateSubscription.Reference` (`reference`): "The reference value (provided by your app) for the subscription itself." Also `CustomerReference` (`customer_reference`) for an existing customer, and an inline customer via `CustomerAttributes` (`customer_attributes`, which has its own `reference`). Customer-side: CreateCustomer remarks — "you can only create one customer for a given reference value" (provider refuses a duplicate customer reference). No such uniqueness statement exists for subscription `reference` (UNVERIFIED).
- Products in a family by handle: **yes** — `ListProductsForProductFamily` with `ProductFamilyId = "handle:" + handle` (record doc: "Either the product family's id or its handle prefixed with `handle:`").
- Subscription state / next billing / product: on `Subscription` — `State`, `NextAssessmentAt`, `CurrentPeriodEndsAt`, `ProductPriceInCents`, `Product`.

## 6. Assumptions & Blockers

**Blockers:** none.

**Assumptions (A) and risks (R):**
- **A1** Customer reference and subscription reference are derived from the JWT `ClaimTypes.Name` (user name), not `ApplicationUser.Id`: with `UseOnlyInMemoryDatabase=true` the identity store is re-seeded every run, so user ids are not stable across restarts while user names are; Maxio then still finds the same customer after a restart. Exact format (e.g. prefix + lower-cased user name; subscription reference adds `:` + plan handle) is YOUR CALL.
- **A2** One subscription per user per plan: the subscription claim key is (user, plan). A user may hold Pro and Basic at once; re-subscribing to a canceled plan is out of scope (the reference would collide locally).
- **A3** `POST /api/subscriptions` body carries a plan handle; when omitted, default to `eshop-pro` (task: "default subscribe target") — YOUR CALL whether that default is a config value or a constant; it is not one of the mandated `Maxio:` keys, and it is still validated against the family listing.
- **A4** `MAXIO_ENVIRONMENT` is not bound: the task mandates no key for it and the SDK has no sandbox environment (sandbox = site). `ServerEnvironment.Us` is used. If the sandbox site were EU-hosted this would need `Eu` — not indicated.
- **A5** Fail-fast at startup will stop `tests/PublicApiIntegrationTests` (its `WebApplicationFactory<Program>` boots the real `Program`, `tests/PublicApiIntegrationTests/ProgramTest.cs`) unless the test host supplies non-blank dummy `Maxio:` values (e.g. in `tests/PublicApiIntegrationTests/appsettings.test.json`, which `Program` loads) — dummy, not secret.
- **A6** First/last name for `CreateCustomer` are derived from the user name/email (D4).
- **A7** Under `UseOnlyInMemoryDatabase=true` the claim table lives only for one process run (task acknowledges this); across restarts duplicate protection falls back to the provider-side lookups (`ReadCustomerByReference` before `CreateCustomer`, customer-reference uniqueness, `FindSubscription` before `CreateSubscription` when no local claim exists — YOUR CALL whether to add that pre-check). On SQL Server the table outlives the process but needs an EF migration (YOUR CALL; the in-memory provider ignores migrations).
- **R1** Build toolchain: the SDK uses C# 14 features (`extension` block in `ServiceCollectionExtensions.cs`, `field` keyword in `MaxioAdvancedBillingClient.cs`) and so needs the .NET 10 SDK; repo `global.json` pins `8.0.x` with `rollForward: latestFeature`, which does not cross major versions — the main agent's environment step must make the .NET 10 SDK selectable.
- **R2** Package versions: the SDK project pins `Microsoft.Extensions.Http` / `Logging.Abstractions` / `System.Text.Json` etc. at `10.0.8` (`sdk/dotnet/Directory.Packages.props`) while the repo targets `net8.0` with its own central versions (`Directory.Packages.props`); expect possible NU1605/NU1608 downgrade warnings-as-errors to resolve at build time.
- **R3** The `ProjectReference` to the SDK points into this plugin's install directory — builds only where the plugin is installed at that path (CI/teammates must re-point it).
- **R4** No payment method is sent; the task states both plans do not require one. If Maxio nevertheless returns 422 (e.g. 3DS/payment-required), it surfaces via `ErrorListResponse1.Errors` and the claim is released.
