## 1. Scope & sequence

Everything is Maxio **Production** server group (`https://{site}.chargify.com`, US default); `Ebb` group is not touched (usage is only read, via `SubscriptionComponents.ListUsages`).

Domain mapping (decisions the sheet records; see section 6 for assumptions):
- **Plan = Maxio Product.** Public `plan handle` = `Product.Handle`; admin `{planId}` = `Product.Id` (int).
- **Brand = Maxio Product Family**, one per catalog brand, family handle `brand-{CatalogBrand.Id}`, family name = `CatalogBrand.Brand`.
- **User -> Maxio customer** = `Customer.Reference` equals the JWT `ClaimTypes.Name` (Identity username); the link is stored in the app's own DB (`BillingClaim` table, section 2b) as `customer:{username}` -> Maxio customer id. Customer first/last/email come from the Identity user (`UserManager<ApplicationUser>.FindByNameAsync`: `Email`, `UserName`); if the Identity user has no email -> 422 with reason.
- **Ownership** = a subscription is the caller's iff `ReadSubscription(...).Subscription.Customer.Id` equals the caller's linked customer id AND `Customer.Reference` equals the caller's username. Not owned or not found -> 404 (do not reveal existence). Staff endpoints skip ownership but still 404 on unknown id.

| Step | Feature | Operations used (in order) |
| --- | --- | --- |
| 1 | `GET /api/plans` | `Products.ListProducts` (walk pages, `IncludeArchived` unset) |
| 2 | `POST /api/subscriptions` | `Products.ListProducts` (offered-set check) -> claim -> `Customers.ReadCustomerByReference` / `Customers.CreateCustomer` (first time) -> claim -> `Subscriptions.CreateSubscription` |
| 3 | `GET /api/subscriptions/{id}` | `Subscriptions.ReadSubscription` -> `Invoices.ListInvoices` (walk pages) |
| 4 | pause / resume | ownership `ReadSubscription` -> `SubscriptionStatus.PauseSubscription` / `SubscriptionStatus.ResumeSubscription` |
| 5 | cancel / restart | ownership `ReadSubscription` -> `SubscriptionStatus.CancelSubscription` / `SubscriptionStatus.ReactivateSubscription` (only when state is `canceled`) |
| 6 | switch | ownership `ReadSubscription` -> `Products.ListProducts` (offered-set check) -> `SubscriptionProducts.MigrateSubscriptionProduct` (active/trialing) or `Subscriptions.UpdateSubscription` with `ProductHandle` (canceled) -> `Subscriptions.ReadSubscription` (verify) |
| 7 | usage for a day | ownership `ReadSubscription` -> `SubscriptionComponents.ListSubscriptionComponents` (keep `Kind == MeteredComponent`) -> `SubscriptionComponents.ListUsages` per component (walk pages) |
| 8 | `POST /api/admin/plans` | brand check via `IReadRepository<CatalogBrand>` -> `ProductFamilies.ListProductFamilies` -> (`ProductFamilies.CreateProductFamily` if missing) -> claim -> `Products.CreateProduct` |
| 9 | currency price | `Products.ReadProduct` -> `ProductPricePoints.ReadProductPricePoint` (`CurrencyPrices = true`) -> claim -> `ProductPricePoints.CreateProductCurrencyPrices` or `ProductPricePoints.UpdateProductCurrencyPrices` |
| 10 | next billing date | `Subscriptions.ReadSubscription` -> `Subscriptions.UpdateSubscription` (`NextBillingAt`) -> `Subscriptions.ReadSubscription` (verify via `CurrentPeriodEndsAt`) |

Capability gaps: none blocking. Maxio exposes no "list plans I may subscribe to" scoped by shopper: "plans they can subscribe to" is defined as the non-archived Maxio products (section 6, A1).

## 2. CONTRACT SHEET

⚠ Signatures are generated code, verbatim: each operation that takes input takes ONE request record as its first parameter (an operation with no inputs takes none), built with an object initializer using the record's own property names — never flat arguments.
⚠ Every SDK type is written fully-qualified with the namespace its source path implies, taken from the path the map gives for THAT type, never from where a neighbouring type sits. (Namespaces: `MaxioAdvancedBilling.Models`, `.Models.Enums`, `.Models.AnyOf`, `.Requests.<Controller>`, `.Errors`, `.Core.Exceptions`, `.Core.ErrorResponse`, `.Servers`; client + options in `MaxioAdvancedBilling`.)

All operations: `Auth: options.BasicAuth`, throw-only, optional trailing `RequestOptions? requestOptions = null, CancellationToken cancellationToken = default`. Case A = `MaxioAdvancedBilling.Core.Exceptions.ApiException<MaxioAdvancedBilling.Errors.{Op}Error>`; Case B = `ApiException<MaxioAdvancedBilling.Core.ErrorResponse.RawError>`. Every typed `{Op}Error` also has `TryGetRawError(out RawError?)` fallback. `ErrorListResponse1` = `{ errors (errors): IReadOnlyList<string>, required }`; `ErrorArrayMapResponse1` = `{ errors (errors): IReadOnlyDictionary<string, object>? }`.

### 2b. CROSS-OPERATION INVARIANTS

| Invariant | Operations | Enforced where |
| --- | --- | --- |
| `plan handle` supplied to subscribe must be a handle of a product this app offers (non-archived product in the same list `GET /api/plans` returns) | `Subscriptions.CreateSubscription` <- `Products.ListProducts` | in the subscribe handler before `CreateSubscription` (and before the customer is created): list all pages of `ListProducts`, require an exact `Product.Handle` match with `ArchivedAt == null`; otherwise 422 "unknown plan" |
| `plan handle` supplied to switch must be an offered plan (same set) and differ from the subscription's current `Product.Handle` | `SubscriptionProducts.MigrateSubscriptionProduct` / `Subscriptions.UpdateSubscription` <- `Products.ListProducts` | in the switch handler before either write |
| plan `brand` supplied to create-plan must be a brand in the shop's catalog (match by `CatalogBrand.Id` or exact `Brand` text, state which the request carries: brand accepted as the catalog brand NAME, resolved to the row) | `Products.CreateProduct` / `ProductFamilies.CreateProductFamily` <- `IReadRepository<CatalogBrand>.ListAsync()` (the app's catalog, not Maxio) | before any Maxio call in the create-plan handler; unknown brand -> 422 listing nothing invented. The Maxio family is then found by handle `brand-{CatalogBrand.Id}` from `ProductFamilies.ListProductFamilies`, created only if missing |
| `{planId}` for currency pricing must be an existing, non-archived plan this app offers | `ProductPricePoints.CreateProductCurrencyPrices` / `UpdateProductCurrencyPrices` <- `Products.ReadProduct` (confirms existence) AND `Products.ListProducts` (offered set) | in the currency-price handler before the write; id not in the offered list -> 404 |
| `{subscriptionId}` must belong to the caller (shopper endpoints) | every shopper write/read of a subscription <- `Customers.ReadCustomerByReference` / stored `customer:{username}` claim + `Subscriptions.ReadSubscription` | before the first write of every shopper handler (see 0 for rule); staff endpoints: only existence |
| usage `component` must be one of the subscription's metered components | `SubscriptionComponents.ListUsages` <- `SubscriptionComponents.ListSubscriptionComponents` | in the usage handler: ListUsages is only called with ids from the metered-component list |

### 2d. Client construction, auth, server facts

- Client: `new MaxioAdvancedBilling.MaxioAdvancedBillingClient(HttpClient httpClient, MaxioAdvancedBilling.MaxioAdvancedBillingClientOptions options)`; DI: `services.AddMaxioAdvancedBillingClient(options => ...)` (`src/MaxioAdvancedBilling/ServiceCollectionExtensions.cs`). Every API group is a property: `client.Products`, `client.Customers`, `client.Subscriptions`, etc.
- Auth: HTTP Basic. `options.BasicAuth = new MaxioAdvancedBilling.Core.Authentication.Basic.BasicAuthCredentials { Username = <Maxio:ApiKey>, Password = "x" }` (map: Servers & auth: username = API key, password = `x`). If left null the SDK reads its own `MAXIO_ADVANCED_BILLING_BASIC_AUTH_USERNAME/PASSWORD` env vars; this app binds from `Maxio:` configuration instead and sets it in code (code wins).
- Settings (exact keys, nothing hard-coded): `Maxio:ApiKey`, `Maxio:Subdomain`, `Maxio:Environment`, `Maxio:BaseUrl` (optional). `Maxio:Environment` is parsed case-insensitively to `MaxioAdvancedBilling.Servers.ServerEnvironment.Us` ("US") / `.Eu` ("EU") (closed enum: any other value refuses startup). Site: `options.Server.Production.Us.Site` / `.Eu.Site` = `Maxio:Subdomain` (default is the literal `"subdomain"`). `Maxio:BaseUrl` when set: assigned verbatim to `options.Server.Production.Us.BaseUrl` (and `.Eu.BaseUrl`, whichever environment is selected); default templates `https://{site}.chargify.com` (Us) / `https://{site}.ebilling.maxio.com` (Eu). UNVERIFIED: whether a BaseUrl without a `{site}` placeholder resolves cleanly (`Servers/ProductionOptions.cs` builds `UrlTemplate(BaseUrl, path, [site param])`).
- Sandbox: the SDK declares NO sandbox environment (only `Us`, `Eu`). Test traffic is kept off the live site by the credentials/subdomain of a sandbox Maxio site supplied through the settings above (sandbox creds are in user-secrets, loaded by the main agent).
- Error classes to catch: `ApiException<TError>` (`MaxioAdvancedBilling.Core.Exceptions`), `ResponseDeserializationException`, `SdkConnectionException`, `SdkTimeoutException`, `AuthSchemeException` (all `SdkException` family, same namespace).

## 3. Trap notes (state hazards, not fixes)

| Step | Hazard | MUST load |
| --- | --- | --- |
| Client DI | the options object, `HttpClient` ownership and lifetime of the registered client decide whether a rotated secret or a disposed client breaks calls | `maxio:dotnet-client-initialization` |
| Credentials | Basic credential shape (which part is key vs password) and a blank key are not the same failure as a missing one | `maxio:dotnet-authentication` |
| Every call | request records and union-typed ids (`ProductIdModel`, `SubscriptionIdOrReference`, `ComponentIdModel`) have construction rules; wrong shapes fail only at compile or at runtime | `maxio:dotnet-calling-endpoints` |
| Models / dates / quantity | `Quantity1` is a union, enums are open, `DateTimeOffset` serialization vs. a plain calendar date, `AdditionalProperties` — a naive read loses data or shifts a day | `maxio:dotnet-models` |

## 6. Assumptions & Blockers

Blockers: none that stop planning.

Assumptions (A#):
- A1. "Plans a shopper can subscribe to" = all non-archived Maxio products on the site (`ListProducts`, archived excluded). Products created outside this app are offered too. Alternative (restrict to families named `brand-{CatalogBrand.Id}`) is possible; chosen the broader set so seeded sandbox products work. `GET /api/plans` requires a signed-in user (JWT), any role.
- A2. User -> Maxio customer: `Customer.Reference` = Identity username (the only identity claim in the JWT); customer id stored in `BillingClaim` (`customer:{username}`); name/email taken from the Identity user; username used as first/last name when the Identity user holds nothing else (Identity has no name fields) and email is required — missing email -> 422.
- A3. Subscribe without card: `CreateSubscription` with `ProductHandle`, `CustomerId`, `PaymentCollectionMethod = Remittance` (invoice-style collection; no payment profile sent). If the plan has `RequireCreditCard = true`, Maxio will refuse (422 reason relayed). Plans created by this app set `RequireCreditCard = false`. UNVERIFIED: whether remittance accepts the creation without a card on this site.
- A4. `paid` (feature 3) = true iff (a) no invoice of the subscription with status other than Draft/Voided/Canceled has `DueAmount` parsed (invariant culture decimal) > 0, AND (b) `Subscription.BalanceInCents <= 0`. Source: `Invoices.ListInvoices(SubscriptionId)` all pages + `Subscription.BalanceInCents`. A subscription with no invoices and zero balance reports `paid: true`. Draft invoices do not count.
- A5. Restart = `ReactivateSubscription` with no resume flags, allowed only when state is `canceled` (else 422 "only a cancelled subscription can be restarted"). Per remarks: resumable -> original billing date kept, else a new billing period begins and the subscriber is charged. Cancel = immediate (`CancelSubscription` with no body); cancelling a subscription already `canceled` -> 422 reason.
- A6. Switch: state `active`/`trialing` -> `MigrateSubscriptionProduct` (documented valid states; migrating to the same product fails, so same-handle is a 4xx up front). State `canceled` -> `UpdateSubscription` with the new product handle (the migration remarks themselves say a canceled subscription's product is changed this way, then reactivated). Result for a canceled subscription: on the new plan, still canceled until restarted (we do not auto-reactivate; restart is the separate endpoint). Read-back verifies `Product.Handle == new handle`; if Maxio refuses or the handle is unchanged -> 422 with reason. Other states (`paused`, `on_hold`, `past_due`, …) -> 422 "cannot switch in this state". UNVERIFIED on live traffic (map does not state that UpdateSubscription accepts a canceled subscription). Unknown outcomes of the migration are settled by `ReadSubscription` (compare product handle).
- A7. Usage for a day: `ListSubscriptionComponents` -> only `Kind == MeteredComponent`; for each, `ListUsages` with `SinceDate = date-1 day 00:00Z`, `UntilDate = date+2 days 00:00Z` (widened because day boundaries are site-timezone midnights and the remarks say the bounds are inclusive midnights) and all pages; then keep only records whose `CreatedAt` calendar date (the offset-local date as returned) equals the requested date. Response lists per component: id, handle, name, records, summed quantity (quantity union read as int or decimal string). Subscription with no metered components -> empty list, not an error. `date` must be `YYYY-MM-DD` (else 400). UNVERIFIED: the site timezone in which `created_at` is reported.
- A8. Create plan request: `{ name, monthlyPrice (decimal, major units, > 0, max 2 decimals), brand (catalog brand NAME) }`. Maps to `Name`, `Description` (= name), `PriceInCents` = price x 100 rounded exactly, `Interval = 1`, `IntervalUnit = Month`, `RequireCreditCard = false`, `Handle` = lowercase slug of name (a duplicate handle is refused by Maxio 422 -> 409/422). Brand not in `CatalogBrands` -> 422. Response returns plan id (`Product.Id`), handle, name, price, brand.
- A9. Currency price: `{ currency (ISO code), price (decimal) }` on the plan's DEFAULT price point (`Product.DefaultProductPricePointId`). If a `CurrencyPrice` with that currency already exists (read with `CurrencyPrices = true`) -> `UpdateProductCurrencyPrices` using its `Id`; else `CreateProductCurrencyPrices` with `Role = Baseline`. SDK quirk: Create's `Price` is `int`, Update's is `double`. Fractional price for a NEW currency: create with the integer part, then update to the exact value (two writes, UNVERIFIED unit semantics — major units assumed). Currency not defined at site level, or plan having trial/setup fee roles not mirrored -> Maxio 422 relayed as 4xx. Currency validated as 3 letters up front.
- A10. Next billing date: `UpdateSubscription` with `NextBillingAt` = given calendar date at 00:00 UTC; the SDK has this documented path ("Billing Date Changes": after that date passes and the subscription is processed it is billed). Date must be in the future and subscription state must be `active` (else 422); calendar-billing subscriptions use `snap_day` instead (not offered -> Maxio 422 relayed). Verified by `ReadSubscription` then comparing `CurrentPeriodEndsAt` to the requested instant (response omits `next_billing_at` per remarks). Billing on the date is Maxio's scheduler; nothing is faked. UNVERIFIED: timezone normalization of the stored instant.
- A11. Error mapping: Maxio 404 -> 404; 422 -> 422 with Maxio's `Errors` strings (from `ErrorListResponse1`/`ErrorArrayMapResponse1`) as the reason; other 4xx -> same status with `RawError.ReadAsString()`; 401/403 from Maxio or `AuthSchemeException` -> 502 "billing provider rejected the application's credentials" (the caller did nothing wrong, not a 4xx for them); 5xx / `SdkConnectionException` / `SdkTimeoutException` / `ResponseDeserializationException` -> 502/504 with reason. Mapping is done in the endpoint helper (a shared mapper class), response bodies use `ErrorDetails` like `ExceptionMiddleware`.
- A12. Route constraints: `{subscriptionId:int}`; `GET /api/subscriptions/{id}/usage?date=`. Switch/pause body shapes: `POST .../switch` body `{ "planHandle": "..." }`; `POST /api/subscriptions` body `{ "planHandle": "..." }`.
- A13. Staff next-billing-date and admin routes require role Administrators; an admin acting on a subscription does not need ownership.
- A14. Subscribe response/`GET subscription` shape: `{ id, planHandle, planName, state, paid, currentPeriodEndsAt }`. A shopper may hold several subscriptions (also to the same plan sequentially; the claim only blocks concurrent double-submits).
- A15. (Unknown outcome of subscribe) A subscribe whose connection fails after Maxio may have acted is settled in the same catch by `Customers.ListCustomerSubscriptions`: match found -> success; else the claim is released and the caller gets 502 (retry-able). Decision made in code: `BillingService.Subscribe`.
- Settled decisions (YOUR CALL items): 30 s per-request budget = `BillingService.Budgeted`; 50-page cap = `MAX_PAGES`; claim TTL 5 min = `ClaimTtl`; Maxio 401/403 -> 502, 429 -> 503, 400 -> 422 = `BillingService.Map`.
- Sandbox findings: a canceled subscription accepts a product change through `UpdateSubscription` (stays canceled until restarted); currencies must be defined at site level in Maxio, otherwise 422 is relayed; the sandbox site has no extra currency defined.
