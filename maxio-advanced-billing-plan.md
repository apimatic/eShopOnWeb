# Maxio Advanced Billing plan — eShopOnWeb subscribe

Additive PublicApi capability. Does not replace cart or checkout. Maxio Advanced Billing is the billing system of record for recurring plans only.

SDK root cited below is plugin-relative `sdk/dotnet/`. Do not copy the SDK into this repo. Project reference is machine-local: `sdk/dotnet/src/MaxioAdvancedBilling/MaxioAdvancedBilling.csproj` on `src/Infrastructure/Infrastructure.csproj` (the layer that already owns `CatalogContext` and identity). A teammate or CI runner without this plugin at the same path must re-point that reference.

## 1. Scope & sequence

Conventions to imitate (pattern + one exemplar, no snippets):

- PublicApi endpoint: `IEndpoint`, `MapGet`/`MapPost` route without a leading slash, `.Produces<>().WithTags(...)`. Exemplar: `src/PublicApi/CatalogItemEndpoints/CreateCatalogItemEndpoint.cs`. Use `[Authorize(AuthenticationSchemes = JwtBearerDefaults.AuthenticationScheme)]` for any authenticated shopper. Do not copy that exemplar's Administrators role.
- Caller identity: JWT `ClaimTypes.Name` (the username). Exemplar: `src/Infrastructure/Identity/IdentityTokenClaimService.cs`. The token has no user-id claim and no separate email claim. Seeded usernames are emails (`src/Infrastructure/Identity/AppIdentityDbContextSeed.cs`).
- Records store: `CatalogContext` in-memory database named `Catalog` when `UseOnlyInMemoryDatabase` is set. Exemplar: `src/Infrastructure/Data/CatalogContext.cs`, registration `src/Infrastructure/Dependencies.cs`. Primary key via `HasKey` — exemplar `src/Infrastructure/Data/Config/CatalogTypeConfiguration.cs`. Do not copy the count-then-insert check in `CreateCatalogItemEndpoint`.
- Configuration section bind: `src/PublicApi/Program.cs` (`GetRequiredSection` / `Configure`). Binding keys are only `Maxio:ApiKey`, `Maxio:Subdomain`, `Maxio:ProductFamilyHandle`, `Maxio:BaseUrl`.

The host file `src/PublicApi/Program.cs` registers JWT bearer and calls `UseAuthorization` without `UseAuthentication`. The new routes cannot see the token until authentication middleware runs before `UseAuthorization`.

Steps:

1. **Host auth + settings.** Call `UseAuthentication` before the existing `UseAuthorization`. Map `MAXIO_API_KEY` → `Maxio:ApiKey`, `MAXIO_SITE_SUBDOMAIN` → `Maxio:Subdomain`, `MAXIO_DEFAULT_PRODUCT_FAMILY` → `Maxio:ProductFamilyHandle` at startup. Do not add a binding key for `MAXIO_ENVIRONMENT`. `Maxio:BaseUrl` is optional and is read only when that key is already in configuration. Fail fast when ApiKey, Subdomain, or ProductFamilyHandle is missing or blank. Register one long-lived `MaxioAdvancedBilling.MaxioAdvancedBillingClient` (named `HttpClient`, options captured once). No secret values in any file.
2. **Claim entities on `CatalogContext`.** Customer claim: primary key = JWT `ClaimTypes.Name`. Subscription claim: composite primary key = (that same name, product handle). Both survive only for this process when the in-memory provider is on. That is the store this machine uses.
3. **`GET /api/subscription-plans`.** `client.ProductFamilies.ListProductsForProductFamily` with `ProductFamilyId` = `handle:` + `Maxio:ProductFamilyHandle` (bare handle from config, never a numeric id, never a hard-coded handle). Walk pages. Response fields from `Product`: `Handle`, `Name`, `PriceInCents`, `Interval`, `IntervalUnit`.
4. **`POST /api/subscriptions`.** Body carries the chosen product handle (no hard-coded default). Before create, reject a handle that is not in the set step 3 returns. Ensure a Maxio customer (claim, then `ReadCustomerByReference`, then `CreateCustomer` only when the lookup is a 404). Then subscription claim, then `FindSubscription` by the deterministic reference, then `CreateSubscription` only when that lookup is a 404. Omit payment profiles, cards, and bank accounts. Confirm from the create response: plan handle/name, `ProductPriceInCents`, `State`, `CurrentPeriodEndsAt`.
5. **`GET /api/my-subscriptions`.** Do not create a customer. `ReadCustomerByReference`; on 404 return an empty list. Otherwise `ListCustomerSubscriptions` with the runtime `Customer.Id` from that response. Same confirmation fields as step 4. Settle any subscription claim left `Unknown` by `FindSubscription` before returning.
6. **Error boundary, one call budget, logging.** Catch typed `ApiException<TError>`, `ResponseDeserializationException`, and connection failures on the writes as the unknown-outcome rows say.

Out of scope: metered component `api-call`, coupons, card capture, 3-DS, webhooks, the Web MVC cart/checkout.

## 3. Trap notes

- Constructing `MaxioAdvancedBillingClient` per request, or leaving `HttpClient` on the unnamed factory client, pins DNS for the process and shares timeouts with every other unnamed client. **MUST load `maxio-advanced-billing:dotnet-client-initialization`.**
- `BasicAuth` left unset does not throw at startup; the call leaves unauthenticated. Both username and password are parts of the scheme. A startup message that includes the key's value leaks it. **MUST load `maxio-advanced-billing:dotnet-authentication`.**
- Each call takes one request record; a success return has no HTTP status. The `Idempotency-Key` header the method builds with `Guid.NewGuid()` does not dedupe a second call. **MUST load `maxio-advanced-billing:dotnet-calling-endpoints`.**
- `Subscription` on `SubscriptionResponse` is nullable while `Customer` and `Product` envelopes are required. Enums are open string records, not C# enums. Wire names are the `[JsonPropertyName]` values. **MUST load `maxio-advanced-billing:dotnet-models`.**
- `ReadCustomerByReference` is Case B; `FindSubscription` 404 is `TryGetNoContent`, not `RawError` as `TError`. A body that does not match the generated type is not `ApiException<TError>`. **MUST load `maxio-advanced-billing:dotnet-error-handling`.**
- `Retry.Timeout` and `HttpClient.Timeout` are not the caller's budget. POST is outside the default retry-verb list; GET is inside it. `ListProductsForProductFamily` is not a `Pageable` — paging it by hand with no cap of our own can spin. `LogRequestBody` and an unset `LoggerFactory` decide whether customer names and email are written out. `BaseUrl` on a server group or environment other than the one captured at construction is not the URL that is called. **MUST load `maxio-advanced-billing:dotnet-configuration-resilience`.**
- The unknown-outcome tests have to fail the connection the SDK actually throws and assert the re-read, which means stubbing at the `HttpClient` seam and building the typed exceptions the catch names. **MUST load `maxio-advanced-billing:dotnet-testing`.**

## 5. PRODUCTION READINESS

| # | Concern | Decision |
| --- | --- | --- |
| 1 | Credential fail-fast | Bind section `Maxio`. Before the host serves, refuse to start when `Maxio:ApiKey`, `Maxio:Subdomain`, or `Maxio:ProductFamilyHandle` is missing or whitespace. | 3 | Total timeout budget | The caller ceiling is **30 seconds**, enforced by one `CancellationTokenSource` linked to `HttpContext.RequestAborted` and cancelled after 30s, passed from the single service that fronts the SDK into every operation of that request (including each plans page). `options.Retry.Timeout` = 10s (per attempt; on GET/HEAD/PUT/OPTIONS its expiry is retried). | 4 | Write-retry ownership | The SDK may resend GETs in scope (`ListProductsForProductFamily`, `ReadCustomerByReference`, `ListCustomerSubscriptions`, `FindSubscription`) under default `HttpMethodsToRetry` (`GET, HEAD, PUT, OPTIONS`), `MaxRetries` 3. | 5 | Idempotency & ambiguous writes | `CreateCustomerOperationRequest` has no idempotency-key member. Reconciliation: `ReadCustomerByReference` by `Reference` (the token name). | 6 | Observability | SDK logger (`MaxioAdvancedBilling.Core.Configuration.LoggingOptions`) at Information for the request line and the success response line, Warning for failure and retry, Error for the terminal exception. Our catch logs `ApiException.StatusCode` and the message strings from `ErrorListResponse1.Errors`, `CustomerErrorResponse1.Errors` (`Customer` or the string list), `ListProductsForProductFamilyError`'s string, or `RawError.ReadAsString`. None of those payloads has a correlation-id member. Do not log a header the map does not name. Do not log request or response bodies. |
| 7 | Sensitive data | `CreateCustomer` sends email, first name, and last name. ## 6. Assumptions & Blockers

### Assumptions

- `POST /api/subscriptions` requires a product handle in the body. The seeded Pro handle is not an application default and is not hard-coded. A missing handle is a client error.
- A shopper may hold one subscription per product handle in this process. A double-submit of the same handle does not create a second subscription. A different handle is a different claim. Resubscribe after cancel, inside the same process, is blocked by the surviving primary key until the claim row is removed; this task's double-click rule is the one implemented.
- Customer `reference` and `email` are the JWT `ClaimTypes.Name`. `FirstName` and `LastName` are derived as in the `CreateCustomer` row because `ApplicationUser` has neither.
- `MAXIO_ENVIRONMENT` is not a binding key and is not read. Host selection is `ServerEnvironment.Us` plus `Maxio:Subdomain` and optional `Maxio:BaseUrl`.
- The metered component is seeded and unused. This flow does not allocate components.
- Prices are the SDK cent fields (`PriceInCents`, `ProductPriceInCents`). Dollar amounts from the seed table are not constants in code.
- Next billing date shown to the shopper is `CurrentPeriodEndsAt`.
- `UseOnlyInMemoryDatabase=true` drops claims on restart. That store still counts. After restart, `ReadCustomerByReference` and `FindSubscription` reattach to Maxio using the same references.
- PublicApi is the only surface. Web cart/checkout is unchanged.
- `ReadCustomerByReference` uses HTTP 404 for a missing reference. That status is **UNVERIFIED** (not on the map row). The defensive rule is in the contract row.
- Subscription `reference` uniqueness on create is **UNVERIFIED**. The local composite primary key is the duplicate gate.

### Blockers

None. The map has every operation this flow calls. The application has a store that can hold the claims for the process.
