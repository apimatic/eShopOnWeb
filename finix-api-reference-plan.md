| 5 | **Fulfil (capture).** `POST /api/orders/{orderId}/fulfil` (admin): re-read the hold, capture the stored hold amount, read the capture transfer and Finix fees; return captured amount, fee, net proceeds; explain an uncapturable hold. | `GetAuthorization`, `CaptureAuthorization`, `GetTransfer`, `ListFees` |

| 9 | **Tests.** Stub the SDK's `HttpClient` seam; assert outgoing requests, duplicate-claim behaviour, error translation, and the unknown-outcome settlement paths. | — (tests) |

Each route is separately invocable: `POST /api/orders`, `POST /api/orders/{orderId}/pay`, `POST /api/orders/{orderId}/fulfil`, `POST /api/orders/{orderId}/cancel`, `POST /api/orders/{orderId}/refunds`, `GET /api/my-orders`, `GET /api/reconciliation`, `POST /api/payment-methods`, `GET /api/payment-methods`, `DELETE /api/payment-methods/{paymentMethodId}`. Fulfil/cancel/reconciliation use `[Authorize(Roles = BlazorShared.Authorization.Constants.Roles.ADMINISTRATORS, AuthenticationSchemes = JwtBearerDefaults.AuthenticationScheme)]` (the existing exemplar is `src/PublicApi/CatalogItemEndpoints/CreateCatalogItemEndpoint.cs`); the rest use `[Authorize(AuthenticationSchemes = JwtBearerDefaults.AuthenticationScheme)]`. Caller identity is the JWT `ClaimTypes.Name` value (`src/Infrastructure/Identity/IdentityTokenClaimService.cs`); it is the order `BuyerId` and the card owner key.

### CROSS-OPERATION INVARIANTS

| Invariant | Operations | Enforced where |
| --- | --- | --- |
| `orderId` accepted by pay/fulfil/cancel/refunds must be an order returned by `POST /api/orders` for the caller | `CreateAuthorization` / `CaptureAuthorization` / `VoidAuthorization` / `CreateTransferReversal` ← `POST /api/orders` | order-store lookup by (caller, `orderId`) before every SDK call; unknown or foreign id → 404 |
| `paymentMethodId` accepted by pay (saved card) and `DELETE` must be a card returned by `POST /api/payment-methods` for the caller and still enabled | `CreateAuthorization` / `UpdatePaymentInstrument` ← `CreatePaymentInstrument` (stored; listed by `GET /api/payment-methods`) | saved-card store lookup by (caller, `paymentMethodId`) plus `Enabled` check before `CreateAuthorization` / `UpdatePaymentInstrument` |
| `source` sent to authorization must be the payment-instrument id returned by `CreatePaymentInstrument` | `CreateAuthorization` ← `CreatePaymentInstrument` | stored `FinixPaymentInstrumentId` on the saved-card row or the one-off card resolution, before `CreateAuthorization` |
| `authorizationId` used by capture/void/re-read must be the id returned by `CreateAuthorization` | `CaptureAuthorization` / `VoidAuthorization` / `GetAuthorization` ← `CreateAuthorization` | stored `FinixAuthorizationId` on the order's payment state, before each call |
| `captureTransferId` used by refunds must be the `transfer` id returned by `CaptureAuthorization` (or the re-read `GetAuthorization`) | `CreateTransferReversal` / `ListTransferReversals` ← `CaptureAuthorization` | stored `CaptureTransferId` on the order's payment state, before `CreateTransferReversal` |
| refund amount must be ≤ the captured amount minus all prior refunds for that capture | `CreateTransferReversal` ← `CaptureAuthorization` plus prior `CreateTransferReversal` results | refund-ledger sum check before the reversal; provider also rejects a single refund above the parent transfer |
| refund `idempotencyKey` must map to at most one refund per order; a distinct key remains a legitimate second partial refund | `CreateTransferReversal` ← refund claim store populated by earlier `CreateTransferReversal` calls | claim store `TryAdd` on (orderId, caller key) before the reversal |
| `currency` sent to authorization must be a declared `Currency` member and be supported by the merchant | `CreateAuthorization` ← `GetMerchant` (`MerchantSchema.Currencies`) | startup `FinixOptions` validation plus the cached `GetMerchant` currency check before `CreateAuthorization` |
| `merchant` sent to authorization must be the configured merchant whose `identity` created the payment instrument | `CreateAuthorization` ← `GetMerchant` / `CreatePaymentInstrument` | cached `FinixOptions.MerchantId` and the stored `FinixIdentityId`, before `CreateAuthorization` |

### Client construction, auth, server nodes

- Construct with `new FinixApiReferenceClient(HttpClient httpClient, FinixApiReferenceClientOptions options)` (the only constructor) **or** DI `services.AddFinixApiReferenceClient(options => { ... })` — the DI extension registers the client as a singleton, obtains its `HttpClient` from `IHttpClientFactory`, invokes the configure delegate **once at registration**, and fills `options.Logging.LoggerFactory` from DI when it is null (`ServiceCollectionExtensions.cs`). Use DI.
- Auth is HTTP **Basic**: `options.BasicAuth = new BasicAuthCredentials { Username = ..., Password = ... }` (`FinixApiReference.Core.Authentication.Basic.BasicAuthCredentials`). Every operation in scope carries an **Auth** bullet `options.BasicAuth`. A credential left null is read from the SDK's own environment variable at construction; set it in code from `FinixOptions` so a missing value fails startup instead.
- `options.Environment = ServerEnvironment.Production` (`FinixApiReference.Servers`); the **only** declared environment has value `"production"` and host `https://finix.sandbox-payments-api.com` (sandbox). There is **one server group**, `Default`. Override the host with `options.Server.Default.Production.BaseUrl = <Finix:BaseUrl>` (verbatim; `ServerOptions.Default` is `DefaultOptions`, whose `Production.BaseUrl` defaults to the sandbox host).
- `options.Retry` is `RetryOptions` (all members `required`; start from `RetryOptions.Default()`). `options.Logging` is `LoggingOptions` (`LoggerFactory`, `LogRequestHeaders`, `LogResponseHeaders`, `LogRequestBody`, `BodySizeLimit`, `LoggableContentTypes`, `RedactedHeaders`, `RedactedKeys`, `UnmaskHeaders`, `RedactionPlaceholder`). `options.TimeProvider`, `options.Hooks`, `options.StreamReadTimeout` exist but are not otherwise used.
- The SDK sends a fresh `Idempotency-Key: Guid.NewGuid()` header on every non-GET call (`Api/*.cs`); it is **not** a key. The only real key in scope is `AuthorizationAllFields.IdempotencyId` (`idempotency_id`).
- Response status/headers of a **successful** call are not on the return value; there is no no-throw variant (all 135 operations are throw-only). Read a success status only through hooks if ever needed.

## 3. Trap notes

- **Client lifetime and options** — the client is a singleton holding one options object and an `IHttpClientFactory` client; constructing it per request or disposing its `HttpClient` changes socket lifetime and credential rotation semantics. **MUST load `finix:dotnet-client-initialization`.**
- **Basic auth is two parts** — a blank username or password is not a missing credential, and the failure appears as `AuthSchemeException` on the first call, not at startup unless you check it. **MUST load `finix:dotnet-authentication`.**
- **Request records, not flat arguments** — a call built from flat arguments, or a list read taken off the response root instead of its `_embedded` envelope, compiles against nothing and silently returns no items. **MUST load `finix:dotnet-calling-endpoints`.**
- **Unions and open enums** — `AuthorizationsRequest`, `AuthorizationsRequest1`, `TransfersReversalsRequest`, `PaymentInstrumentsRequest`, `PaymentInstrumentsRequest1`, `CreatePaymentInstrument`, `PaymentInstrumentsResponse1`, `PaymentInstrumentsResponse`, `PaymentInstruments3` are `AnyOf` unions; `Currency`, `State1`, `State11`, `VoidState`, `Type31`, `Type53`, `State24`, `Type18` are open string enums with no public factory. Handled as an ordinary record or a closed C# enum, a union loses its variant on write and an undeclared wire value throws on read. **MUST load `finix:dotnet-models`.**
- **Typed errors are per operation** — every operation throws `ApiException<{Operation}Error>` with `TryGetGenericError` / `TryGetRawError`; a catch ladder that only handles one status shape misses the rest. **MUST load `finix:dotnet-error-handling`.**
- **Write retries are verb-based** — the SDK's default retry policy includes `PUT`, and capture/void/disable are PUTs; decide which verbs may be resent before any money moves. **MUST load `finix:dotnet-configuration-resilience`.**
- **Cursor pagination is not in the map's default table** — the map's default says "no pagination", yet the request records expose `after_cursor`/`limit` and the response models expose `page.next_cursor` / `_links.next`; reconciliation must not stop after one page. **MUST load `finix:dotnet-configuration-resilience`.**
- **Card data on the wire** — `PaymentInstrumentCard1.Number` and `.SecurityCode` are raw card fields; logging configuration can put request bodies in logs without a code change. **MUST load `finix:dotnet-configuration-resilience`.**
- **Testing the SDK seam** — the client takes an `HttpClient`, so the stub is at that seam; a connection failure must be reproducible to exercise the unknown-outcome paths. **MUST load `finix:dotnet-testing`.**

## 6. Assumptions & Blockers

**Blockers:** none identified. Every task action has a grounded SDK operation: authorize `CreateAuthorization`, capture `CaptureAuthorization`, release `VoidAuthorization`, refund `CreateTransferReversal`, save card `CreatePaymentInstrument`, list/disable cards `ListPaymentInstruments`/`UpdatePaymentInstrument`, reconciliation `ListTransfers`. The SDK has **no hard-delete payment-instrument operation**; "remove" is implemented as disable (`enabled: false`) plus an app-store tombstone, which satisfies "absent from list and unusable to pay" — a decision, not a capability gap.

**Assumptions (to be confirmed or accepted before/while implementing):**

1. **Environment naming.** `FINIX_ENVIRONMENT` / `Finix:Environment` accepts `"production"` or `"sandbox"` and maps both to `ServerEnvironment.Production`, whose host is the Finix sandbox. Any other value fails startup. `Finix:BaseUrl` overrides the host verbatim for every call.
2. **Currency.** `Finix:Currency` must resolve to `Currency.Usd` or `Currency.Cad`; the `Currency` enum declares only those two members and has no public factory, so any other ISO code fails startup rather than being sent.
3. **Identity for card instruments.** `PaymentInstrumentCard1.Identity` is required; the app resolves the merchant's Finix `identity` from `GetMerchant(FINIX_MERCHANT_ID).Identity` and caches it. If that value is null or the provider rejects payment instruments under it, the fallback is `Identities.CreateIdentity` with the `Buyer` variant (a `Buyer` requires `Entity5`, whose fields are all optional); that fallback is not part of the base plan and is used only if the first sandbox card creation is rejected.
4. **Ownership.** Provider-level ownership is not relied on for listing: `GET /api/payment-methods` and `GET /api/my-orders` read the app store filtered by the JWT name; every pay/delete/refund checks the stored owner before any SDK call. The provider's `OwnerIdentityId` filter is used only in the card-save settle helper. One-off card payment instruments are not added to the saved-card store; they remain at Finix unless an optional cleanup step is added.
5. **Order shape.** `Order`/`OrderItem` are reused as-is: `Order(buyerId, shipToAddress, items)` and `OrderItem(CatalogItemOrdered, unitPrice, units)`. The task's order request carries catalog item ids + quantities; because `Order` requires an `Address`, the request also accepts an optional `shipToAddress` and falls back to a configured default. `Order.Id` is a protected `int`; the app store assigns and owns the public `orderId`.
6. **Money units.** Catalog prices are decimal currency units; every Finix `amount`/`capture_amount` is cents (`long`), computed with `Math.Round(total * 100m, MidpointRounding.AwayFromZero)`. `RefundTransfer.RefundAmount` is `int`; reject amounts outside `int` range before the call.
7. **Refund idempotency.** `CreateTransferReversal` has no idempotency member and the SDK's `Idempotency-Key` header is a fresh GUID; the caller-supplied key is enforced only by the app claim store, and unknown outcomes are settled by a reversal count/sum delta on the parent transfer. This is the only available mechanism in this SDK version.
8. **Fee/net reporting.** `ListFees(LinkedTo = captureTransferId)` is the primary Finix-fee source (`Fee.Amount` is `double?`, documented as cents or a fractional amount); `Transfer.Fee` (`long?`) is the fallback. If neither has posted, `finixFee`/`netProceeds` are null, `feesFinalized=false`, and the response explains that Finix has not posted the fee yet. Live sandbox traffic showed the capture transfer moves PENDING -> SUCCEEDED after roughly a minute and fees then post; `PersistCaptureAsync` polls for up to 90 s before reading fees.
9. **Reconciliation scope.** "Finix's own transactions" means `Transfer` resources (DEBIT captures and REVERSAL refunds), not uncaptured `Authorization` holds. Matching is by stored capture `TransferId` and, for reversals, `ParentTransfer`; unmatched transfers are `providerOnly`, orders with no matching transfer in range are `eshopOnly`.
10. **Order/card dedupe without a header.** `POST /api/orders` and `POST /api/payment-methods` accept an optional `Idempotency-Key` header. Without it, order placement and card save are intentionally not cross-request deduplicated (a duplicate order or a duplicate saved card is a distinct resource the caller can remove); the money-moving writes are always deduplicated by the order/action key.
11. **Single-run store.** The store is a process singleton, lost on restart, with no cross-process sharing — consistent with the task's in-memory, single-run constraint.
12. **PCI posture.** Raw card details are accepted by the API only because this is a sandbox integration with the supplied test card; the SDK's `CreatePaymentInstrument` remarks state that creating payment instruments directly via the API is for testing and that hosted fields are required to stay out of PCI scope. Production would use tokenized/hosted input.
13. **Build.** The SDK project lives under its own `Directory.Build.props` / `Directory.Packages.props` (LangVersion 14, its own package versions), so the repo-root central package management does not apply to it. The only build workaround is the SDK pin: run with `DOTNET_ROLL_FORWARD=Major` or set `rollForward` to `latestMajor` in `global.json`, because only the .NET 10 SDK is installed while `global.json` pins 8.0.x.
14. **Reconciliation date-filter workaround.** The SDK serializes `CreatedAtGte`/`CreatedAtLte` as `yyyy-MM-ddTHH:mm:ss.fffZ`; Finix sandbox rejects that shape with HTTP 422 (`Must be in format 2018-01-26T11:21:23`). Reconciliation therefore walks `ListTransfers` newest-first without the broken date filters and filters client-side by `Transfer.CreatedAt`, stopping once a page is entirely older than `from`. The walk is bounded, reports `truncated`/`nextCursor`, and covers the whole requested range rather than the first page.
15. **Capture settlement and partial refunds.** A Finix capture transfer can be created in `PENDING` state. Sandbox reported that a `PENDING` capture accepts only a full reversal; partial reversals require the transfer to reach `SUCCEEDED`. Fulfilment therefore polls `GetTransfer` for up to 90 s (then reads `ListFees`), and the refund endpoint polls the capture for up to 90 s before a partial refund. A full refund is still attempted immediately when the capture remains `PENDING`.
16. **Idempotency id uniqueness.** The authorization idempotency id is derived from a per-order `PaymentReference` GUID (`eshop-{PaymentReference}-auth`), not the store-assigned integer id, so an order id reused after a process restart cannot collide with a previous Finix authorization.
