# finix-api-reference-plan.md — eShopOnWeb card payments + saved cards

SDK root for every `source` cell below: `.opencode/sdk/dotnet/` (plugin-relative; the map and the source it names ship there). SDK root namespace `FinixApiReference`.

## 1. Scope & sequence

Implementation order. Each step names the Finix operations it uses. Capabilities the map lacks are §6 Blockers, not invented data paths.

1. **Config + client + fail-fast** — bind the app's `Finix` section (`Finix:Username`, `Finix:Password`, `Finix:MerchantId`, `Finix:Environment`, `Finix:Currency`, `Finix:BaseUrl`) to an app options type; map env vars `FINIX_USERNAME`/`FINIX_PASSWORD`/`FINIX_MERCHANT_ID`/`FINIX_ENVIRONMENT`/`FINIX_CURRENCY` into those keys; refuse to start on any blank value, and on `Environment=live` with no `BaseUrl`. Register `AddFinixApiReferenceClient` with explicit `BasicAuth`, `Environment = ServerEnvironment.Production`, `Server.Default.Production.BaseUrl` when set, `Retry` with `HttpMethodsToRetry = [GET, HEAD]`, explicit `Logging` (`LogRequestBody = false`, container `LoggerFactory`). Ops: none (client construction).
2. **App persistence + auth wiring** — additive entities in `CatalogContext` (the store this codebase already keeps its records in): order payment state, refund records, saved payment methods, shopper Finix identity, idempotency claims; add `app.UseAuthentication()` before `UseAuthorization()` in `src/PublicApi/Program.cs` (it is absent today). No Finix ops.
3. **Saved cards (Flow 2)** — `POST /api/payment-methods` → lazy `CreateIdentity` (buyer) then `CreatePaymentInstrument`; persist only safe fields. `GET /api/payment-methods` → app rows scoped to caller (optionally refreshed with `ListPaymentInstruments`). `DELETE /api/payment-methods/{id}` → `UpdatePaymentInstrument` with `PaymentInstrumentDisableAPaymentInstrument { Enabled = false }`, then soft-delete the app row. Ops: `CreateIdentity`, `CreatePaymentInstrument`, `ListPaymentInstruments`, `GetPaymentInstrument`, `UpdatePaymentInstrument`.
4. **Place order** — `POST /api/orders`: validate catalog item ids + quantities against the catalog, create the existing `Order`/`OrderItem`, payment state `AwaitingPayment`; response carries top-level `orderId`. No Finix op.
5. **Pay** — `POST /api/orders/{orderId}/pay`: claim `pay:{orderId}`; if card details, tokenize with `CreatePaymentInstrument` (never persisted); if `paymentMethodId`, load the caller's app row and confirm with `GetPaymentInstrument`; then `CreateAuthorization` with `AuthorizationAllFields` (`Amount` = order total in cents, `Currency`, `Merchant`, `Source`, `IdempotencyId = pay:{orderId}:{PaymentReference}` where `PaymentReference` is the per-order GUID stored on `OrderPayment`, `PartialAuthorization = false`); store authorization id, amount, state. Ops: `CreatePaymentInstrument`, `GetPaymentInstrument`, `CreateAuthorization`.
6. **Fulfil** — `POST /api/orders/{orderId}/fulfil` (admin): claim `capture:{orderId}`; `GetAuthorization` and check capturable (state, void, expiry, already-captured); `CaptureAuthorization` with `CaptureAuthorization { CaptureAmount = authorized cents }`; `GetTransfer(Authorization.Transfer)` for captured amount/fee/state; `ListFees(LinkedTo = captureTransferId)` for the Finix fee; store captured amount, fee, net. Ops: `GetAuthorization`, `CaptureAuthorization`, `GetTransfer`, `ListFees`.
7. **Cancel** — `POST /api/orders/{orderId}/cancel`: claim `void:{orderId}`; `GetAuthorization`; `VoidAuthorization` with `VoidAnAuthorization { VoidMe = true }`; store void state. Ops: `GetAuthorization`, `VoidAuthorization`.
8. **Refund** — `POST /api/orders/{orderId}/refunds` (caller-supplied key): claim `refund:{orderId}:{callerKey}`; `GetTransfer` the capture and `ListTransferReversals` to compute refundable remainder; reject over-refund; `CreateTransferReversal` with `TransfersReversalsRequest.RefundTransfer(new RefundTransfer { RefundAmount = … })`; store reversal id/amount/state; response carries top-level `refundId`. Ops: `GetTransfer`, `ListTransferReversals`, `CreateTransferReversal`.
9. **My orders** — `GET /api/my-orders`: app query by caller id, projecting payment state + Finix ids. No Finix op.
10. **Reconciliation** — `GET /api/reconciliation?from={from}&to={to}` (admin): parse `DateTimeOffset`, page `ListTransfers` and `ListAuthorizations` with `CreatedAtGte/Lte` and `Limit = 100` until `Page.NextCursor` is null (page cap 1000, surface truncation), match by stored Finix ids and by `IdempotencyId` (`pay:{orderId}:{PaymentReference}`), report unmatched both ways. Ops: `ListTransfers`, `ListAuthorizations`.
11. **Tests** — stub the SDK at the `HttpClient` handler seam; cover authorize/capture/void/refund double-submit, ambiguous-connection reconciliation, over-refund, non-capturable hold, ownership isolation, and pagination truncation. See `dotnet-testing`.

## 3. Trap notes

1. **Authorization body is a 14-variant union; `source` is a Payment Instrument id on every variant.** Raw card details must be tokenized first — there is no "card number" field on any authorization body. The variant that carries `idempotency_id` is `AuthorizationAllFields`, not `AuthorizationMinimalFields`. MUST load `dotnet-models`.
2. **Card data lives on `PaymentInstrumentCard1.Number` and `.SecurityCode`.** The SDK's logging posture decides whether that body can reach your logs; a card number in a log is a PCI incident. MUST load `dotnet-configuration-resilience`.
3. **`CaptureAuthorization` and `VoidAuthorization` are `PUT`, and the SDK's retry policy does not treat every verb alike.** A transient failure can reach a capture or void more than once, which is money. MUST load `dotnet-configuration-resilience`.
4. **The capture's money is on the `Transfer`, not the `Authorization`.** `Authorization.Amount` is the hold; the captured amount and fee are on the `Transfer` named by `Authorization.Transfer`. MUST load `dotnet-calling-endpoints`.
5. **`Fee.Amount` is `double?` and may be fractional** (the model says integer cents *or* a double), while capture/refund amounts are integer cents — naive summing/truncation loses a cent. MUST load `dotnet-models`.
6. **Enums are `OpenStringEnum<T>`, not C# enums.** Comparing `State1` to `"SUCCEEDED"` fails; use the static members, `TryGetKnownValue`, or `Match` (whose `otherwise` receives values Finix adds later). MUST load `dotnet-models`.
7. **`List*` operations return a single page envelope, not `Pageable`.** Treating one response as the whole set silently drops later pages — and a reconciliation that misses pages is a wrong answer. MUST load `dotnet-configuration-resilience`.
8. **A `2xx` body that drifts from its declared shape throws `ResponseDeserializationException`, which is not `ApiException<TError>`.** A catch ladder written for Case A only lets it escape. MUST load `dotnet-error-handling`.
9. **A blank credential is treated as configured and sent as-is.** A missing half surfaces as `AuthSchemeException` on the first payment, not at startup. MUST load `dotnet-authentication`.
10. **How the client is registered decides what its logger does when no `LoggerFactory` is assigned** — and the SDK's request log carries the URL, which includes path ids. MUST load `dotnet-client-initialization`.
11. **`Environment` and `Server` are read at different times.** A base-URL change made after construction can be silently ignored, and the selected environment decides which server options are read at all. MUST load `dotnet-configuration-resilience`.
12. **Union accessors are `[NotNullWhen(true)] out T?`.** Read the value inside the `if`; a `TryGet…` outside a guard yields a nullable the compiler will not narrow. MUST load `dotnet-models`.
13. **`UpdatePaymentInstrumentRequest` has no `FinixVersion` member**, unlike the other writes — do not add one. `GetAuthorizationRequest` likewise carries no version and the method sends no headers. MUST load `dotnet-calling-endpoints`.
14. **A test that stubs the controller instead of the transport never exercises the SDK's serialization, retry or error translation.** The request record is never serialized, so the wire contract is only observable below it. MUST load `dotnet-testing`.

## 6. Assumptions & Blockers

**Blockers**

1. **No live host in the map.** The SDK declares one server group (`Default`) and one environment member (`ServerEnvironment.Production`) whose base URL is the **sandbox** host `https://finix.sandbox-payments-api.com`. There is no live URL to select. The plan therefore treats `Finix:Environment=live` as *requiring* `Finix:BaseUrl` and refuses to start otherwise; if the user expects the SDK to know a live host, that is blocked pending the URL.
2. **No delete-payment-instrument operation.** `PaymentInstrumentsApi` has 8 operations, none deleting an instrument; the closest is `UpdatePaymentInstrument` with `PaymentInstrumentDisableAPaymentInstrument { Enabled = false }`, whose `<remarks>` says the instrument "can't be used in requests". `DELETE /api/payment-methods/{id}` is therefore disable-at-Finix + soft-delete-in-app. If the user requires the instrument erased at Finix, that is blocked.
3. **No caller-supplied idempotency key on refunds (or capture/void).** `RefundTransfer` has only `refund_amount`; `CreateTransferReversalRequest` adds only `TransferId`/`FinixVersion`/`Body`. The refund key is app-enforced by the claim table, and provider-side duplicate refunds are only detectable by `ListTransferReversals` reconciliation. If provider-side dedupe is required, it is not available in this SDK.
4. **PCI scope.** `CreatePaymentInstrument`'s own `<remarks>` warn that creating instruments directly via the API is for testing and that production must use Finix hosted fields. Acceptable for this reference app; production card capture through this path is a compliance blocker.
5. **Claim durability under the task's DB mode.** `UseOnlyInMemoryDatabase=true` makes `CatalogContext` per-process, so claims and payment state do not survive a restart and cannot guard a second process. That matches the task's stated "state only survives within a run"; if cross-process duplicate prevention is required, the store must be the SQL Server configuration.

**Assumptions**

- `FINIX_MERCHANT_ID` is the Finix `Merchant` id sent as `Merchant` on authorizations; `FINIX_CURRENCY` is a currency the merchant supports (map enum has `USD`/`CAD`).
- `FINIX_ENVIRONMENT=sandbox` selects the default host; `live` requires `Finix:BaseUrl`.
- Order totals are dollars; the cents value is `(long)Math.Round(order.Total() * 100m, MidpointRounding.AwayFromZero)` and is asserted equal to `Authorization.Amount` and `CaptureAuthorization.CaptureAmount`.
- One Finix buyer `Identity` per signed-in shopper, created lazily and stored app-side; one-off card payments reuse it and their instrument is not saved app-side.
- The signed-in shopper's email and a display name are available from the identity user record to fill `Entity5` (all fields optional) and the required `PaymentInstrumentCard1.Name`. If Finix rejects a buyer Identity that carries only email/name, that is a provider rejection and becomes a blocker at implementation.
- Administrator role is `BlazorShared.Authorization.Constants.Roles.ADMINISTRATORS` (`"Administrators"`); caller identity is the JWT `ClaimTypes.Name` claim.
- The existing `BuyerAggregate.PaymentMethod` entity is unmapped (no `DbSet`, no ownership field) and is not reused as-is; a new app-owned entity with `BuyerId` is added.
- `src/PublicApi/Program.cs` lacks `app.UseAuthentication()`; the implementer adds it before `app.UseAuthorization()`.
- Net proceeds = captured amount − sum of `Fee.Amount` for `ListFees(LinkedTo = captureTransferId)`, rounded to whole cents; `Transfer.Fee` is the fallback when no fee rows are returned.
- `POST /api/orders` makes no Finix call; two submissions create two orders unless the user asks for a caller-supplied order idempotency key (not in the task).
- **Finix date-filter wire format.** Finix's sandbox rejects the SDK's `DateTimeOffset.ToIso8601()` output for `created_at.gte`/`created_at.lte` (`yyyy-MM-ddTHH:mm:ss.fffZ`) with `422 INVALID_FIELD` and demands `yyyy-MM-ddTHH:mm:ss`. `Program.cs` installs `SdkHook.OnRequest(NormalizeFinixDateQuery)` to rewrite only those query keys before the request is sent; reconciliation therefore works for the full range.
- **Per-order idempotency reference.** `OrderPayment.PaymentReference` is a GUID generated when the payment row is created; the Finix authorization idempotency id is `pay:{orderId}:{PaymentReference}`. This keeps a re-created in-memory order id from colliding with a prior authorization at Finix while still being deterministic per order.
- **PublicApi integration-test base address.** `tests/PublicApiIntegrationTests/ProgramTest.cs` creates clients with `BaseAddress = https://localhost` so `UseHttpsRedirection()` does not 307 the request and strip the bearer token; the production app is unchanged.
- Connection-failure reconciliation branches (`SettleUnknown*` in `PaymentService`) are implemented but not covered by an automated connection-fault test; `tmp/opencode/e2e.ps1` verifies the end-to-end happy paths against Finix sandbox.
