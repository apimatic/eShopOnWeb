# finix-api-reference-plan.md — Finix payments + saved cards for eShopOnWeb `src/PublicApi`

Planner output for `finix/dotnet-integrate-finix-api-reference`. Every SDK fact below was read this session from the SDK source this plugin carries. **All `Source` cells are relative to the SDK root `sdk/dotnet/`** (on this machine: `<repo>/.opencode/sdk/dotnet/`); the project cites that plugin-relative root only.

Scope: `src/PublicApi` (ASP.NET Core, .NET, `MinimalApi.Endpoint` + `Ardalis.ApiEndpoints`), additive to the existing catalog/basket/order flow. App-side persistence is `CatalogContext` (`src/Infrastructure/Data/CatalogContext.cs`; EF InMemory when `UseOnlyInMemoryDatabase` is set, else SQL Server — `src/Infrastructure/Dependencies.cs`).

## 1. Scope & sequence

Each step names the operations it uses. A capability the map lacks is a Blocker (§6), never an invented data path.

| # | Step | Operations used |
| --- | --- | --- |
| 1 | **Config + DI + fail-fast.** Bind `Finix:Username`, `Finix:Password`, `Finix:MerchantId`, `Finix:Environment` (`sandbox`\|`live`), `Finix:Currency`, optional `Finix:BaseUrl` from `IConfiguration` (env vars supply them). Validate all of them at startup, build `FinixApiReferenceClientOptions` once, register the client as a singleton. | — (construction facts in §2) |
| 2 | **Startup merchant check.** Confirm `Finix:MerchantId` resolves and its `currencies` admit `Finix:Currency`; refuse to start otherwise. | `client.MerchantsApi.GetMerchant` |
| 3 | **Persistence (additive).** New EF entities + configurations in `CatalogContext` for: shopper→Finix buyer identity, saved card (instrument id + safe descriptor), order payment record (authorization id, capture transfer id, state, amounts), refund records (caller key, reversal id), and write claims. Reuse the existing `Order`/`OrderItem` aggregate unchanged (`Order.Total()`). | — |
| 4 | **Saved cards — create.** Resolve/create the shopper's Finix buyer identity, then create a card instrument; persist only instrument id + safe descriptor. | `client.Identities.CreateIdentity` → `client.PaymentInstrumentsApi.CreatePaymentInstrument` |
| 5 | **Saved cards — list / delete.** List from the app store. Delete = disable at Finix + soft-delete in the app store (no delete operation exists). | `client.PaymentInstrumentsApi.UpdatePaymentInstrument` (disable), `client.PaymentInstrumentsApi.GetPaymentInstrument` |
| 6 | **Place order.** Build `Order` from catalog item ids + quantities, `BuyerId` from the token, status awaiting payment; return top-level `orderId`. | — |
| 7 | **Pay (authorize/hold).** Resolve the instrument (saved card id, or create a throw-away instrument from one-off card details), then authorize the order total in cents. Persist authorization id + state. | `client.PaymentInstrumentsApi.CreatePaymentInstrument` (one-off only) → `client.AuthorizationsApi.CreateAuthorization` |
| 8 | **Fulfil (capture).** Operator-only. Capture the held amount, then read the capture `Transfer` and its fees to persist captured amount / Finix fee / net. Translate a non-capturable hold into operator-actionable text. | `client.AuthorizationsApi.CaptureAuthorization` → `client.TransfersApi.GetTransfer` → `client.FeesApi.ListFees`; on refusal `client.AuthorizationsApi.GetAuthorization` |
| 9 | **Cancel (void).** Release the hold before fulfilment. | `client.AuthorizationsApi.VoidAuthorization` |
| 10 | **Refund.** Operator/caller-supplied idempotency key; refuse amounts above captured-minus-refunded. | `client.TransfersApi.ListTransferReversals` (cap) → `client.TransfersApi.CreateTransferReversal` |
| 11 | **Reads.** Caller's orders + payment state from the app store; operator reconciliation walks Finix transfers **and** authorizations across the whole range. | `client.TransfersApi.ListTransfers`, `client.AuthorizationsApi.ListAuthorizations` |
| 12 | **Error boundary + tests.** One translation layer for the typed `GenericError` payloads and `ResponseDeserializationException`; stub the `HttpClient` seam. | — |

**Client construction, auth and server facts** (`sdk-map.md` *Getting a client* / *Servers & auth*; `sdk/dotnet/src/FinixApiReference/FinixApiReferenceClientOptions.cs`, `…/ServerOptions.cs`, `…/Servers/DefaultOptions.cs`, `…/Servers/ServerEnvironment.cs`, `…/Core/Configuration/RetryOptions.cs`, `…/Core/Configuration/LoggingOptions.cs`; `sdk/dotnet/README.md:55-83, 286-357`):

- Root namespace `FinixApiReference`; client `FinixApiReferenceClient`; the only constructor is `FinixApiReferenceClient(HttpClient httpClient, FinixApiReferenceClientOptions options)`; API groups are properties (`client.AuthorizationsApi`, `client.TransfersApi`, `client.PaymentInstrumentsApi`, `client.Identities`, `client.FeesApi`, `client.MerchantsApi`).
- DI: `services.AddFinixApiReferenceClient(options => { … })`.

## 3. Trap notes

1. **Client construction.** A `null` `BasicAuth` is silently filled from the SDK's own variables and a set-but-blank credential is sent as-is (the SDK checks presence, never content) — so an "empty password" fails as a provider 401, not a startup error. **MUST load dotnet-authentication.**
2. **Client lifetime / DI.** `FinixApiReferenceClient` owns no `HttpClient` of its own; who disposes what and how the registration resolves decides whether a socket-exhausted client survives. **MUST load dotnet-client-initialization.**
3. **Calling shape.** One request record per operation, response unions/envelopes read one level down (`_embedded`), and per-call `RequestOptions` + `CancellationToken` — getting the envelope depth wrong yields a null payload, not a compile error. **MUST load dotnet-calling-endpoints.**
4. **Models and unions.** Every request variant here is an open `AnyOf` union whose read path can land in `TryGetUnknown`; `PaymentInstrumentCard1.Type` is get-only; enum members are not C# enum values and `TryGetKnownValue`/`Match` is how a wire value is resolved. **MUST load dotnet-models.**
5. **Sensitive bodies.** `PaymentInstrumentCard1.Number` and `.SecurityCode` are serialized verbatim by the SDK when body logging is armed, and there is no redaction for JSON bodies. **MUST load dotnet-configuration-resilience.**
6. **Error boundary.** Every operation in scope is Case A with a `GenericError` payload, but a drifted 2xx body or a non-2xx body that does not match the declared error type surfaces as an `ApiException` subclass that is *not* `ApiException<TError>`. **MUST load dotnet-error-handling.**
7. **Retries and timeouts.** The default retried verb list includes `PUT`, and `Timeout` does not bound a whole call — capture and void are `PUT`. **MUST load dotnet-configuration-resilience.**
8. **Pagination.** List operations return a page plus a next cursor; the loop termination is the response, not the request. **MUST load dotnet-configuration-resilience.**
9. **Tests.** Stubbing the `HttpClient` seam and asserting the outgoing request is how a capture/refund path is proven not to double-send. **MUST load dotnet-testing.**

## 6. Assumptions & Blockers

**Resolved decisions (previously listed as blockers)**

1. **Payment-instrument deletion.** The SDK has no delete operation. `DELETE /api/payment-methods/{paymentMethodId}` disables the instrument at Finix (`UpdatePaymentInstrument` + `PaymentInstrumentDisableAPaymentInstrument { Enabled = false }`) and soft-deletes the `SavedPaymentMethods` row. Verified: after deletion the card is absent from `GET /api/payment-methods` and `pay` returns `404 PAYMENT_METHOD_NOT_FOUND`.
2. **Live environment.** `ServerEnvironment` only declares `Production` (sandbox host). `ResolveFinixBaseUrl` uses `Finix:BaseUrl` verbatim when set; otherwise `live` selects `https://finix.live-payments-api.com` and `sandbox` keeps the SDK default. `Finix:BaseUrl` wins in both cases.
3. **Refund idempotency.** The app's `OrderRefunds` composite key (`OrderId`, caller key) is the authoritative duplicate gate. The Finix `idempotency_id` is sent via `AdditionalProperties.Set("idempotency_id", ...)` with a value unique to the payment (`eshop-refund-{PaymentReference}-{callerKey}`), so a caller key reused across orders cannot collide at Finix. Verified by repeating the same caller key (same `refundId`, no second refund) and by two distinct partial refunds of one capture (both succeed).
4. **Finix date-query format.** The SDK serializes `DateTimeOffset` query values as `yyyy-MM-ddTHH:mm:ss.fffZ`, which Finix rejects with `422 Must be in format 2018-01-26T11:21:23`. `FinixDateQueryHandler` (a `DelegatingHandler` on the SDK's default `HttpClient`) normalizes `created_at.gte`/`created_at.lte` to `yyyy-MM-ddTHH:mm:ss` in UTC. Verified by a successful reconciliation over a date range.
5. **Capture is asynchronous in the sandbox.** `CaptureAuthorization` returns a capture transfer in `PENDING`; fees and a refundable balance appear when the transfer becomes `SUCCEEDED` (about 20–30 s in sandbox). `FulfilAsync` stores the captured amount immediately and leaves `FeeComplete=false` until Finix reports fees; a later `fulfil` call refreshes fee/net via `RefreshFeesIfNeededAsync`. `RefundAsync` returns `409 CAPTURE_PENDING` with an operator-actionable message until the capture transfer is `SUCCEEDED`. Verified by polling fulfil until `fee=79`, `net=1621`, then refunding.

**Assumptions**

1. **Caller identity = the JWT `ClaimTypes.Name` value** (the token carries `ClaimTypes.Name` and `ClaimTypes.Role` only — `src/Infrastructure/Identity/IdentityTokenClaimService.cs:30-35`); it is stored as `Order.BuyerId` (string, max 256 — `OrderConfiguration`). There is no user-id claim to key on.
2. **Operator role = `Administrators`** (`BlazorShared.Authorization.Constants.Roles.ADMINISTRATORS = "Administrators"`, seeded in `AppIdentityDbContextSeed`).
3. **`app.UseAuthentication()` is now called before `app.UseAuthorization()`** in `src/PublicApi/Program.cs`; JWT endpoints resolve the caller principal.
4. **New persistence is additive in `CatalogContext`**: no change to `Order`/`OrderItem`; payment state lives in new tables. `UseOnlyInMemoryDatabase` is honoured by tests, so the claim design uses **primary keys** (InMemory enforces them) rather than relying on a unique index.
5. **Order total → cents** uses the existing `Order.Total()` (decimal dollars) rounded to 2 dp then multiplied by 100 and cast to `long`; the same value is held, captured and refunded, so "to the cent" holds by construction. Verified: a $17.00 order held and captured 1700 cents.
6. **One-off card details never become a saved card**: the throw-away `PaymentInstrument` id is used for one `CreateAuthorization` and not persisted; only its id lives in memory for the call.
7. **Fee and net**: "Finix fee" = sum of `Fee.Amount` from `ListFees(LinkedTo = capture transfer id)`; "net proceeds" = captured amount − that sum. `Fee.Amount` is a `double?`; the sum is treated as cents and rounded once. Verified in sandbox: fee 79 cents on a 1700-cent capture, net 1621. `FeeRead.Truncated` makes an incomplete fee list explicit.
8. **`POST /api/orders` is not idempotent** (no caller key in the stated contract, so no claim row): a double submit creates two awaiting-payment orders, neither of which is charged. The task's idempotency requirement is scoped to payment operations.
9. **Pagination**: every list response exposes `page.next_cursor`; the walk stops on a null/unchanged cursor or an empty page, with a `MaxPages=500` backstop. Reconciliation surfaces `truncated`; refunds refuse an incomplete reversal ledger; fees surface `FeeComplete=false`.
10. **`Finix:Currency` maps to `Currency.Usd`/`Currency.Cad`** (the enum declares `USD`/`CAD` only); any other value fails the startup check rather than being sent as an unknown open-enum value.
11. **Sandbox test card** Mastercard `5200 8282 8282 8210`, exp `12/2029`, CVC `022` is used only in manual verification; no card data is committed.
12. **Payment reference**: each `OrderPayment` gets a GUID `PaymentReference` at creation; authorization idempotency ids use it (`eshop-{PaymentReference}-pay-{attempt}`), so order-id reuse after an in-memory restart cannot collide at Finix.
13. **Tests**: `dotnet test tests/PublicApiIntegrationTests` runs 15 tests; 11 pass. The 4 failures are the pre-existing admin catalog tests that lose the bearer token on the `UseHttpsRedirection` redirect from the test client's HTTP base address; they are unrelated to the payment surface. Payment flows were verified end to end against the live Finix sandbox through the API.
