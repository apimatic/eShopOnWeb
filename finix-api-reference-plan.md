# Finix API Reference — eShopOnWeb integration plan

SDK root for every source path below: `.opencode/sdk/dotnet/` (plugin-relative). Root namespace `FinixApiReference`. Target `netstandard2.0`.

## 1. Scope & sequence

| # | Step | Finix operations used |
| --- | --- | --- |
| 0 | **Client wiring.** Add `ProjectReference` to `src/FinixApiReference/FinixApiReference.csproj`; bind `Finix:Username`, `Finix:Password`, `Finix:MerchantId`, `Finix:Environment`, `Finix:Currency`, optional `Finix:BaseUrl`; build `FinixApiReferenceClientOptions` once, register the client in DI, fail fast on missing parts. | none |
| 1 | **Shopper Finix identity.** Lazily create one Finix `Identity` per authenticated shopper (token `ClaimTypes.Name`) and persist its `Id` on the app's shopper record — `PaymentInstrumentCard1.Identity` is `required`. | `Identities.CreateIdentity`, `ListIdentities` (re-read) |
| 2 | **Saved cards (Flow 2).** `POST /api/payment-methods` (raw card → instrument, store only Finix id + display fields), `GET /api/payment-methods` (list by owner identity), `DELETE /api/payment-methods/{paymentMethodId}` (disable, then hide). | `PaymentInstrumentsApi.CreatePaymentInstrument`, `ListPaymentInstruments`, `GetPaymentInstrument`, `UpdatePaymentInstrument` |
| 3 | **Place order.** `POST /api/orders` — create the existing `Order`/`OrderItem` aggregate from catalog ids + quantities; total from `CatalogItem.Price`; order starts `AwaitingPayment`. No Finix call. | none |
| 4 | **Pay (authorize).** `POST /api/orders/{orderId}/pay` — one-off card (instrument created in-line, never stored) or saved card id; authorize the order total in cents; persist authorization id + state. | `AuthorizationsApi.CreateAuthorization` |
| 5 | **Fulfil (capture).** `POST /api/orders/{orderId}/fulfil` — capture the full held amount, persist `Authorization.Transfer` as the captured transfer id, then read transfer + fees and store captured amount / fee / net. | `AuthorizationsApi.CaptureAuthorization`, `TransfersApi.GetTransfer`, `FeesApi.ListFees` |
| 6 | **Cancel (void).** `POST /api/orders/{orderId}/cancel` — void the hold before capture, record void state. | `AuthorizationsApi.VoidAuthorization` |
| 7 | **Refunds.** `POST /api/orders/{orderId}/refunds` — reversal against the captured transfer, full or partial, capped by captured minus prior refunds; caller idempotency key claimed app-side first. | `TransfersApi.CreateTransferReversal`, `ListTransferReversals`, `GetTransfer` |
| 8 | **My orders.** `GET /api/my-orders` — app-only read of orders + persisted payment state. | none |
| 9 | **Reconciliation.** `GET /api/reconciliation?from=&to=` — walk every page of Finix transfers (and authorizations) in `[from,to]`, match Finix ids against stored capture/refund ids, report both directions of mismatch. | `TransfersApi.ListTransfers`, `AuthorizationsApi.ListAuthorizations`, `TransfersApi.ListTransferReversals` |
| 10 | **Tests.** Stub the `HttpClient` seam; assert outgoing routes/bodies, duplicate-claim refusal, unknown-outcome settlement, partial-refund ceiling. | none |

## 2. CONTRACT SHEET

> ⚠ Signatures are generated code, verbatim. Every operation that takes input takes **ONE request record as its first parameter** (an operation with no inputs takes none), built with an object initializer whose property names are the record's own — never flat arguments.
>
> ⚠ Every SDK type below is written fully-qualified with the namespace its source path implies, taken from the path the map gives for **that** type, never from where a neighbouring type sits.

Legend for **Source** cells: a map page or map-named source file that was read for the row; `UNVERIFIED` = only live traffic can settle it; `YOUR CALL — not in the map` = an application decision.

### 2.3 Client construction, auth, server facts

- Only constructor: `new FinixApiReference.FinixApiReferenceClient(HttpClient httpClient, FinixApiReference.FinixApiReferenceClientOptions options)`.
- `FinixApiReference.FinixApiReferenceClientOptions` members: `Environment: ServerEnvironment` (default `ServerEnvironment.Default()`), `Retry: RetryOptions` (`RetryOptions.Default()`), `Logging: LoggingOptions`, `TimeProvider: TimeProvider`, `Server: ServerOptions`, `StreamReadTimeout: TimeSpan?` (60 s), `Hooks: IReadOnlyList<SdkHook>`, `BasicAuth: BasicAuthCredentials?`, `BasicAuthProvider: CredentialProvider<BasicAuthCredentials>?`.
- Auth is HTTP **Basic**: `options.BasicAuth = new FinixApiReference.Core.Authentication.Basic.BasicAuthCredentials { Username = …, Password = … }` (both `required`). A `null` `BasicAuth` is filled from the SDK's own `FINIX_USERNAME` / `FINIX_PASSWORD` env vars at construction (`BasicAuthCredentialsExtensions.WithEnvironmentDefaults`); setting it in code wins, so the app must bind `Finix:Username`/`Finix:Password` (fed from those env vars) itself.
- `FinixApiReference.Servers.ServerEnvironment` declares **one** member: `Production` = `"production"`, doc-commented **"Sandbox server"**, `ServerEnvironment.Default()` → `Production`. **There is no live environment in this SDK.**
- One server group `Default`, `Production` base URL `https://finix.sandbox-payments-api.com` (this *is* the sandbox host), override point `options.Server.Default.Production.BaseUrl`. When `Finix:BaseUrl` is set it must be assigned **verbatim** to that property for every call; when unset, leave the default.
- DI: `services.AddFinixApiReferenceClient(options => { … })` (`src/FinixApiReference/ServiceCollectionExtensions.cs`).
- `using` directives are **not** transitive: `FinixApiReference` (client/options), `FinixApiReference.Servers` (`ServerEnvironment`), `FinixApiReference.Api` (controllers), `FinixApiReference.Requests.<Controller>` (request records), `FinixApiReference.Models`, `FinixApiReference.Models.AnyOf`, `FinixApiReference.Models.Enums`, `FinixApiReference.Errors`, `FinixApiReference.Core.Exceptions`, `FinixApiReference.Core.ErrorResponse`, `FinixApiReference.Core.Authentication.Basic`.

### 2.4 CROSS-OPERATION INVARIANTS

| Invariant | Operations | Enforced where |
| --- | --- | --- |
| `paymentMethodId` accepted by pay / delete must be one this caller owns and that Finix still reports `Enabled = true` | `PaymentInstrumentsApi.CreatePaymentInstrument` → `ListPaymentInstruments` / `GetPaymentInstrument` | before `CreateAuthorization` and `UpdatePaymentInstrument`: look up the saved-card row by `(buyerId, paymentMethodId)`, then confirm via `GetPaymentInstrument` |
| `captureAmount` must equal the amount Finix holds, and must be ≤ `Authorization.Amount` | `AuthorizationsApi.GetAuthorization` (and the `CreateAuthorization` result) | before `CaptureAuthorization`: compare `order.TotalCents` with `Authorization.Amount` |
| `transferId` used for a refund must be the capture transfer that `CaptureAuthorization` produced, not any transfer id | `AuthorizationsApi.CaptureAuthorization` → `Authorization.Transfer` | before `CreateTransferReversal`: use the persisted `capturedTransferId` only |
| `refundAmount` must be ≤ captured amount minus the sum of prior refunds (full/part), never beyond capture | `TransfersApi.GetTransfer` (`Amount`) + `TransfersApi.ListTransferReversals` (Σ `Amount`) | before `CreateTransferReversal`: compute remaining and reject a larger request |
| `PaymentInstrumentCard1.Identity` must be the shopper's Finix `Identity` created by this app | `Identities.CreateIdentity` → `Identity.Id` | before `CreatePaymentInstrument`: read the persisted identity id for the caller; create it first if absent |
| `AuthorizationAllFields.Currency` must be a currency this SDK can express | `FinixApiReference.Models.Enums.Currency` declared members (`USD`, `CAD`) | at startup: map `Finix:Currency` to the static member, fail fast on any other value |
| `orderId` accepted by pay/fulfil/cancel/refund must be an order stored by this app and owned by the caller (or any order, for an operator) | eShop `CatalogContext.Orders` (app store, not a Finix operation) | in each endpoint before any Finix call: load by id and compare `BuyerId` with the token's `ClaimTypes.Name` |

## 3. Trap notes

- **Step 0 — options and HttpClient lifetime.** Building `FinixApiReferenceClientOptions` per request, or letting a short-lived `HttpClient` be owned by the client, decides socket exhaustion and whether the captured credentials ever refresh. MUST load `dotnet-client-initialization`.
- **Step 0 — credentials.** `BasicAuthCredentials` requires both parts; a blank part is not a missing one, and the SDK's own env-var fallback only fires when `BasicAuth` is `null`. Which parts to check and what `AuthSchemeException` vs `401` mean is in the companion. MUST load `dotnet-authentication`.
- **Step 0 — base URL and retries.** What `Retry.Timeout` actually bounds, whether a POST can be resent, and how `options.Server.Default.Production.BaseUrl` interacts with `Environment` are not visible from the property names. MUST load `dotnet-configuration-resilience`.

## 6. Assumptions & Blockers

**Blockers (must be answered before coding if they apply):**

1. **Currency is limited to what the SDK declares.** `FinixApiReference.Models.Enums.Currency` is an `OpenStringEnum<Currency>` that declares only `USD` and `CAD`, has a `private` constructor and **no public factory**; `TryGetKnownValue` returns known members only. `AuthorizationAllFields.Currency` therefore cannot carry any other ISO code. If `FINIX_CURRENCY` must be anything other than `USD` or `CAD`, this SDK version cannot express it → Blocker. Plan assumes `USD`.
2. **A Finix `Identity` per shopper is unavoidable.** `PaymentInstrumentCard1.Identity (identity)` is `required`, so no card (saved or one-off) can be tokenised without an `Identity` id. The plan creates one lazily with `Identities.CreateIdentity` (`Buyer` variant) and persists it. If merchant credentials are not permitted to create buyer identities, that is a Blocker; it cannot be confirmed from the map.
3. **Refund key is app-owned.** No `CreateTransferReversal` variant (`RefundTransfer`, `RefundTransferSplitTransaction`, `RefundCardPresentTransferReferenced`) declares `idempotency_id` or `tags`; the request record declares no key. The caller's idempotency key is enforced **only** by the app claim (primary key) — if a process dies after the provider accepted the reversal and before the claim was recorded, settlement is by amount + reversal-count on `ListTransferReversals`, which is ambiguous for two identical partial refunds. Accepted risk; recorded, not solved by the SDK.
4. **No delete operation exists for payment instruments.** `PaymentInstrumentsApi` has 8 operations and none deletes; "delete" is `UpdatePaymentInstrument` with `PaymentInstrumentDisableAPaymentInstrument { Enabled = false }`. The instrument stays at Finix (disabled), and the app hides it. If a hard delete is required, the SDK cannot do it → Blocker.
5. **`ServerEnvironment` has no live environment.** `Production` is the *sandbox* host. There is no SDK-declared way to select a live Finix host except overriding `options.Server.Default.Production.BaseUrl` (which the task reserves for `Finix:BaseUrl`). Sandbox-only is therefore structurally guaranteed here, and no live deployment is possible without changing code.

**Assumptions & implementation decisions:**

1. `FINIX_ENVIRONMENT` carries `sandbox` (or `live`); `sandbox` maps to `ServerEnvironment.Production`. `live` is accepted only when `Finix:BaseUrl` is set (the SDK declares only the sandbox host). Any other value fails start. Only sandbox is used here.
2. `FINIX_PASSWORD` is the literal env-var name for `Finix:Password`; `FINIX_USERNAME` → `Finix:Username`, `FINIX_MERCHANT_ID` → `Finix:MerchantId`, `FINIX_CURRENCY` → `Finix:Currency`. `FinixServiceCollectionExtensions` maps those names into the `Finix:` section when the section is otherwise empty, and the values were also loaded into .NET user-secrets; no value is written to the repository.
3. Shopper identity is the JWT `ClaimTypes.Name` claim — the only identity claim `IdentityTokenClaimService` puts in the token; there is no subject id. `Order.BuyerId` stores that value.
4. Operator role is `BlazorShared.Authorization.Constants.Roles.ADMINISTRATORS` (`"Administrators"`), the role already used by `CreateCatalogItemEndpoint`/`DeleteCatalogItemEndpoint` with `AuthenticationSchemes = JwtBearerDefaults.AuthenticationScheme`.
5. **Decision — money conversion:** order totals come from `CatalogItem.Price` (decimal) × quantity and are converted to integer cents with `decimal.Round(amount * 100m, 0, MidpointRounding.AwayFromZero)`; `PaymentService.ToCents` implements it.
6. `CaptureAuthorization.CaptureAmount` is `long` while `RefundTransfer.RefundAmount` is `int`; order totals must fit `int` cents for refunds (≈ $21.4 M) — accepted.
7. **Decision — fee and net:** `Transfer` has no net field. The capture reads `ListFees(LinkedTo = transferId)`; when fee records exist, "Finix's fee" is their sum, otherwise it falls back to `Transfer.Fee`. "Captured amount" is `Transfer.Amount`, and "net proceeds" is captured − fee, stored as `OrderPayment.CapturedAmountCents`, `FeeCents`, and `NetCents`. `PaymentService.FinalizeCaptureAsync` implements this.
8. `PaymentInstrumentCard1.Address` is optional and its `Address` fields are all `required` when supplied; the implementation omits `Address` (task says any billing address), so no address is stored or sent.
9. **Decision — saved-card persistence:** a dedicated `SavedPaymentMethod` entity (buyer id, Finix instrument id, brand, last four, expiry, fingerprint, alias, active flag) is used; the existing `BuyerAggregate.PaymentMethod` entity is untouched. Only Finix ids and display fields are stored, never a PAN/CVV.
10. **Decision — saved-card duplicate key:** `POST /api/payment-methods` accepts an optional caller-supplied `requestId` used as the `PaymentClaims` key; without it, a completed instrument is still deduplicated by Finix `fingerprint` for the same buyer. `PaymentService.SavePaymentMethodAsync` implements both paths.
11. **Decision — claims store:** `PaymentClaims` lives in the existing `CatalogContext` (one store per PublicApi process), so claims outlive a request. If PublicApi is scaled out, the claim must move to the shared database.
12. **SDK limitation — date filters:** `ListTransfers`/`ListAuthorizations` serialize `DateTimeOffset` as `yyyy-MM-ddTHH:mm:ss.fffZ`, which Finix's sandbox rejects with `INVALID_FIELD` ("Must be in format 2018-01-26T11:21:23"). `FinixGateway.ListTransfersAsync`/`ListAuthorizationsAsync` therefore try the provider filter, and on that specific rejection re-walk every page without the filter and apply the `[from, to]` range to `CreatedAt` client-side. This still covers the whole range, and `ReconciliationResult.Truncated` reports any page-cap cut-off. This is a defect in the generated SDK's date serialization, not a missing Finix capability.
13. **Decision — capture settlement:** `FinalizeCaptureAsync` polls `GetTransfer` for up to 10 seconds while the capture is `PENDING`, records `CapturedTransferState`, and then reads fees. This makes an immediately-following refund see a settled capture; a partial refund against a still-`PENDING` transfer is refused with `CAPTURE_NOT_SETTLED`, while a full refund of the original capture is allowed (Finix's own rule).
