## 1. Scope & sequence

Each step names the operations it uses. Steps 0–2 are plumbing; 3–10 are the endpoints in the user's order; 11 is verification.

| # | Step | Operations used |
| --- | --- | --- |
| 0 | **SDK + config wiring.** Add `<ProjectReference>` from `src/PublicApi/PublicApi.csproj` to the plugin's `sdk/dotnet/src/FinixApiReference/FinixApiReference.csproj`. Bind configuration section `Finix` (keys `Username`, `Password`, `MerchantId`, `Environment`, `Currency`, `BaseUrl`) from env vars `FINIX_USERNAME`, `FINIX_PASSWORD`, `FINIX_MERCHANT_ID`, `FINIX_ENVIRONMENT`, `FINIX_CURRENCY` — ASP.NET Core's env provider does **not** map `FINIX_USERNAME` onto `Finix:Username`, so the app maps `FINIX_*` → `Finix:*` explicitly at startup, section values winning. | 4 | **`GET /api/payment-methods`** — caller's cards, local records reconciled against the provider list. | `PaymentInstrumentsApi.ListPaymentInstruments` (paged, all pages) |

| 6 | **`POST /api/orders`** — place an order from catalog item ids + quantities, reusing `ApplicationCore.Entities.OrderAggregate.Order`/`OrderItem`/`CatalogItemOrdered`/`Address`; state awaiting payment; persist `PaymentRecord`. Response `orderId`. | — (no Finix call) |
| 7 | **`POST /api/orders/{orderId}/pay`** — claim (DUPLICATE CLAIMS), then authorize the order total in cents as a hold; store `Authorization.id`/`state`/`idempotency_id`. | 8 | **`POST /api/orders/{orderId}/fulfil`** — operator only. Claim, then capture the full held amount; read `Authorization.transfer`; fetch the `Transfer` and record `amount`/`fee`/net/state. A hold that cannot be captured yields an operator message built from `state`/`is_void`/`expires_at`/`failure_code`/`failure_message`. | `AuthorizationsApi.CaptureAuthorization`; `TransfersApi.GetTransfer`; `AuthorizationsApi.GetAuthorization` (settle) |
| 9 | **`POST /api/orders/{orderId}/cancel`** — operator only. Claim, then void the hold (no money moves). | `AuthorizationsApi.VoidAuthorization`; `AuthorizationsApi.GetAuthorization` (settle) |
| 10 | **`POST /api/orders/{orderId}/refunds`** — operator or shopper as the task allows; claim keyed by the caller's idempotency key, then reverse the captured `Transfer` in full or in part; cap the sum of refunds at the captured amount; store reversal id/state. Response `refundId`. | `TransfersApi.CreateTransferReversal`; `TransfersApi.ListTransferReversals` / `TransfersApi.ListTransfers` (settle) |
| 11 | **`GET /api/my-orders`** — caller-scoped orders with stored payment state. | — (store only) |
| 12 | **`GET /api/reconciliation?from&to`** — operator only. Walk **every** page of the provider ledger for `created_at.gte/lte` and join to stored orders/transfers; surface provider-only and app-only rows. | `TransfersApi.ListTransfers` (paged, all pages) |
| 13 | **Tests + verification.** `dotnet build`/`dotnet test`; the failing-connection test per write (UNKNOWN OUTCOMES), the double-claim test per money write, and the full-range reconciliation test. | `dotnet-testing` seam |

**Not used, deliberately:** `TransfersApi.CreateTransfer` — `CaptureAuthorization` itself creates the `Transfer` (`Authorization.transfer`), so no transfer is created by hand. `PaymentInstrumentsApi.UpdatePaymentInstrument` is *not* a delete (see §6 B5). `WebhooksApi` is out of scope: no webhook endpoint is requested.

### 2.2 Enum value tables actually needed

Enums are **not** C# enums: they are `OpenStringEnum<T>` records with public static members (PascalCase names, uppercase wire values), no public factory, `TryGetKnownValue(string?, out T?)` and a generated `Match`. Store/compare `.Value` (implicit `string` conversion exists).

**`Currency`** (`Models/Enums/Currency.cs`) — only two declared values:

| Member | Wire value |
| --- | --- |
| `Currency.Cad` | `CAD` |
| `Currency.Usd` | `USD` |

Resolution of `Finix:Currency` (fed by `FINIX_CURRENCY`): uppercase-trim the configured code, then `Currency.TryGetKnownValue(code, out var currency)`; `true` → use it; `false` → **fail startup** (no public construction path for an undeclared code — `TypedEnum.FromValueCore` is `internal`, `OpenStringEnum`'s constructor is `protected`). Consequence: only USD/CAD can be configured with this SDK version (§6 B6).

**`State1`** — `Authorization.state`: `CANCELED`, `PENDING`, `FAILED`, `SUCCEEDED`, `UNKNOWN`.

**`State11`** — `Transfer.state`: `CANCELED`, `PENDING`, `FAILED`, `SUCCEEDED`, `UNKNOWN`, `RETURNED`.

**`Type31`** — `Transfer.type`: `DEBIT`, `CREDIT`, `REVERSAL`, `ADJUSTMENT`, `DISPUTE`, `RESERVE`, `SETTLEMENT`, `UNKNOWN`.

**`Type10`** — `Identity.type`: `PERSONAL`, `BUSINESS` (left null on the Buyer create; the union arm already selects Buyer).

`Brand` (card brand, `Models/Enums/Brand.cs`) is an open enum with 21 declared members (`Visa`, `Mastercard`, `AmericanExpress`, …). The app never branches on it: it persists `Brand.Value` as the display brand and reads it back as a string.

### 2.3 Client construction, auth, server-node facts

- **Constructor:** the only one is `FinixApiReferenceClient(HttpClient httpClient, FinixApiReferenceClientOptions options)`. DI alternative `services.AddFinixApiReferenceClient(options => { … })` (`src/FinixApiReference/ServiceCollectionExtensions.cs`). Register **once**, singleton, options built at registration.
- **Auth:** HTTP **Basic** — `options.BasicAuth = new BasicAuthCredentials { Username = …, Password = … }` (`FinixApiReference.Core.Authentication.Basic`). Both parts come from `Finix:Username`/`Finix:Password`. A required credential that is not configured fails with `AuthSchemeException` **before anything is sent**; a credential left `null` is read from the SDK's own environment variable at construction — we always set it in code, so that fallback is not used.
- **Environment:** `options.Environment = ServerEnvironment.Production` (`FinixApiReference.Servers`) — a **closed** enum with **exactly one** member: `Production` = `"production"`, hosted as **Sandbox** at `https://finix.sandbox-payments-api.com`. There is **no live environment member** in this SDK.
- **Server groups:** **one** group, `Default`, with a single base-URL template `Production` → `https://finix.sandbox-payments-api.com`, overridable at `options.Server.Default.Production.BaseUrl` (`ServerOptions` → `DefaultOptions` → `ProductionOptions.BaseUrl`, a settable `string`). Every operation resolves through `_server.Default(path)` (`Api/*.cs`).
- **`Finix:BaseUrl` semantics (as the task requires):** when non-blank it is assigned **verbatim** to `options.Server.Default.Production.BaseUrl` and is used for every call regardless of `Finix:Environment`; when blank, `sandbox` uses the SDK default host and `live` **fails startup** (the map names no live host — §6 B1).
- **`Finix:Environment`:** exactly `sandbox` or `live` (case-insensitive); anything else fails startup. Only `sandbox` is a value this SDK can represent.
- **`Finix:MerchantId`:** feeds `AuthorizationAllFields.Merchant` (required on the authorization body).
- **Options surface used:** `BasicAuth`, `Environment`, `Server`, `Logging`, `Retry`, `TimeProvider`, `Hooks` (map, *Getting a client*). `RetryOptions` (namespace `FinixApiReference.Core.Configuration`) has **all members `required`** — start from `RetryOptions.Default()` or build a full instance. `LoggingOptions` is a `record` with `LoggerFactory`, `LogRequestBody`, `LogRequestHeaders`, `LogResponseHeaders`, `BodySizeLimit`, `LoggableContentTypes`, `RedactedHeaders`, `RedactedKeys`, `UnmaskHeaders`, `RedactionPlaceholder`.
- **Response metadata:** a successful call returns only the deserialized body — status/headers are reachable only through `SdkHook.OnResponse` on `options.Hooks` or `requestOptions.Hooks` (map, *Response metadata*).
- **Every write's `Idempotency-Key` header is `Guid.NewGuid()`** per call (`Api/AuthorizationsApi.cs`, `Api/TransfersApi.cs`, `Api/PaymentInstrumentsApi.cs`, `Api/Identities.cs`) — it deduplicates nothing and is **not** a key.

## 6. Assumptions & Blockers

**Blockers**

- **B1 — `live` has no base URL in this SDK.** `ServerEnvironment` (`src/FinixApiReference/Servers/ServerEnvironment.cs`) is a closed enum with exactly one member, `Production` = `"production"`, hosted as Sandbox at `https://finix.sandbox-payments-api.com`; the map's *Servers & auth* section lists one group and one environment. There is no live host anywhere in the map or source, and the plan will not invent one. Consequence: `FINIX_ENVIRONMENT=live` works **only** with `Finix:BaseUrl` supplied by the deployment (used verbatim); with it blank the app fails startup. The live hostname is an operator input, not a plan fact.
- **B2 — SDK reference is plugin-local.** `src/PublicApi/PublicApi.csproj` currently has no Finix reference. Step 0 adds a `<ProjectReference>` to the plugin's `sdk/dotnet/src/FinixApiReference/FinixApiReference.csproj`; that path is machine-local, so the solution builds only where this plugin is installed at that path (a teammate/CI must re-point it). Not fixable inside the repo.
- **B3 — no delete-payment-instrument capability (not a blocker for the requested capability).** `PaymentInstrumentsApi` has 8 operations: `CreateApplePaySession`, `CreatePaymentInstrument`, `CreatePaymentInstrumentVerification`, `CreatePaymentInstrumentVerificationPushToCard`, `GetPaymentInstrument`, `ListInstrumentHistoryEntries`, `ListPaymentInstruments`, `UpdatePaymentInstrument`. **Assessed: the provider API has no DELETE and no operation that removes an instrument.** The requested capability is satisfied at the application boundary: `DELETE /api/payment-methods/{paymentMethodId}` marks the owner-scoped `SavedCard.Removed`, `GET` excludes it, and `POST /api/orders/{orderId}/pay` refuses a removed or non-owned id before any provider call (`PaymentApplicationService.DeleteCardAsync` / `ResolvePaymentInstrumentAsync`). The instrument stays at Finix, so this is not a provider-side delete; no `UpdatePaymentInstrument` disable call is made.
- **B4 — no provider-side idempotency key on capture or refund.** `CaptureAuthorization` body has no `idempotency_id`; no reversal variant (`RefundTransfer`, `RefundTransferSplitTransaction`, `RefundCardPresentTransferReferenced`) declares one, and the response model documents `idempotency_id` for "refund requests" that the request model cannot express. Consequence: a refund's caller-supplied key is enforced by the app claim (correctness) and sent best-effort through `AdditionalProperties`; if the user requires provider-enforced refund idempotency, that is an SDK/API gap to raise with Finix, not something this integration can guarantee.
- **B5 — `Transfer` declares no net proceeds field.** `Transfer` has `amount` and `fee` but no `net`/`net_amount` (and no such member is declared anywhere the map points for it). Consequence: fulfil records `fee` from `Transfer.fee` and computes net = `amount − fee`. If the user expects a provider-reported net figure, the field does not exist in this SDK version and the computed value must be labelled as computed.
- **B6 — `Currency` supports only USD and CAD.** `Currency` declares exactly `Cad ("CAD")` and `Usd ("USD")`; there is no public factory (`TypedEnum.FromValueCore` is `internal`, `OpenStringEnum`'s constructor is `protected`), so an undeclared code cannot be turned into a `Currency` to put on an authorization. Consequence: `FINIX_CURRENCY` must be `USD` or `CAD`; anything else fails startup. A merchant configured for another currency cannot be served by this SDK version without a provider-side default.

**Assumptions (minor — proceed, but confirm if wrong)**

- **A1 — caller identity.** The token issues `ClaimTypes.Name` (`src/Infrastructure/Identity/IdentityTokenClaimService.cs`), so shopper scoping uses that claim value as `BuyerId` (matching `Order.BuyerId`). Administrator operations are gated on `ClaimTypes.Role`; the exact admin role name is read from the seeded identity data at implementation time, not assumed here.
- **A2 — money conversion.** `Order.Total()` is a `decimal` in currency units; the authorization/capture/refund amounts are integer **cents**. Conversion is `decimal → long` cents with `MidpointRounding.AwayFromZero` at the order-total boundary only, so the hold equals the order total to the cent; refunds are capped against the captured cents.
- **A3 — one Buyer identity per shopper.** Created lazily on first saved card (or first pay with a one-off card), stored on the shopper record; `ListIdentities` recovers a create whose response was lost.
- **A4 — one-off card pay.** Pay accepts either a `paymentMethodId` (Flow 2) or raw card details. **Decided:** raw details are tokenized with `CreatePaymentInstrument` (with `SecurityCode`) and the resulting instrument id is used as the `Authorization.source`; implemented in `PaymentApplicationService.ResolvePaymentInstrumentAsync`. The PAN/CVV are never persisted and the instrument id is what the payment record keeps. Paying with a saved card passes the saved instrument id as `source`.
- **A5 — reconciliation ledger = Transfers.** **Decided:** "Finix's own record of transactions" is `ListTransfers` (money movements: captures/`DEBIT` and refunds/`REVERSAL`) over `created_at.gte/lte`; authorizations/holds are not part of the ledger. `PaymentApplicationService.ReconcileAsync` joins those transfers to stored `OrderPayment.TransferId` and `RefundRecord.RefundTransferId`.
- **A6 — refunds are shopper-scoped.** The task makes only fulfil/cancel/reconciliation operator actions, so refunds are shopper-scoped to the caller's own order; `PaymentApplicationService.RefundAsync` loads the order with `LoadOrderForBuyerAsync` and enforces the captured-amount cap server-side.
- **A7 — `FinixVersion`.** Every request record defaults `FinixVersion = "2022-02-01"`; the plan accepts that default and never sets it by hand.
- **A8 — in-memory claim durability.** `UseOnlyInMemoryDatabase=true` is mandated; claims and payment records live in the PublicApi process's InMemory DB. A restart loses them (and a multi-process deployment would not share them). Correct for this task's environment; a durable store would be required before this integration handled real money across restarts.
- **A9 — `UpdatePaymentInstrument` is not used** for DELETE; see B3.
