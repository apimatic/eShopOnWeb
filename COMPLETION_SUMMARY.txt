API ENDPOINTS DELIVERED
================================================================================

1. GET /api/subscription-plans
   - Lists available subscription plans
   - Public endpoint (no authentication required)
   - Returns: Array of plans with handle, name, price, billingCycle
   - HTTP Status: 200 OK, 500 Error

2. POST /api/subscriptions
   - Creates a subscription for authenticated user
   - Requires: JWT token in Authorization header
   - Request: { "planHandle": "string" }
   - Returns: Subscription details with ID, state, dates, price
   - HTTP Status: 201 Created, 400 Bad Request, 401 Unauthorized, 500 Error

3. GET /api/my-subscriptions
   - Retrieves authenticated user's subscriptions
   - Requires: JWT token in Authorization header
   - Returns: Array of user's active subscriptions
   - HTTP Status: 200 OK, 401 Unauthorized, 500 Error

All endpoints follow PublicApi conventions and are discoverable in Swagger UI.

DESIGN HIGHLIGHTS
================================================================================

✅ Maxio as Single Source of Truth
   - All subscription data stored in Maxio
   - Local DB only caches user↔customer mappings
   - Eliminates sync complexity

✅ Idempotent Customer Management
   - User ID used as Maxio customer reference
   - First subscription creates customer
   - Subsequent subscriptions reuse customer
   - No duplicate customers

✅ Clean Architecture
   - Separation of concerns (API, Service, Client layers)
   - Dependency injection for testability
   - Following PublicApi conventions
   - Extensible design

✅ Security First
   - Credentials from environment only
   - JWT authentication on mutations
   - User isolation
   - HTTPS for all API calls

✅ Developer Experience
   - Setup script for credential management
   - In-memory database for development
   - Clear error messages
   - Comprehensive documentation
