## 2. CONTRACT SHEET

> **Signatures are generated code, verbatim — every parameter name is the literal
> C# identifier. The cancellation-token parameter really is named `ct`: in named
> arguments write `ct:`, never `cancellationToken:`.**
>
> **Every SDK type is written fully-qualified with the namespace the map gives it** — take
> each one from that type's own map row, never from where a neighbouring type sits. A members
> table names the namespace outright; otherwise the row's source path implies it
> (`Core/Configuration/…` ⇒ `…Core.Configuration`; a file at the repo root ⇒ the root
> namespace). Enums, unions, auth, server and client-config types are spread across different
> child namespaces, and two types configured side by side in the same options object routinely
> live in different ones. Dropping a type to the root or to `.Models` makes the implementer
> guess the wrong `using`, and the build breaks.

## 3. Trap notes

- ⚠ Step 2 (client registration) — generated DI uses a singleton over the default unnamed factory client; handler rotation, DNS lifetime, timeout, and cross-client handler sharing can affect production behavior. **MUST load `dotnet-client-initialization`** before wiring the client.
- ⚠ Step 2 (authentication) — credential placement, token caching/reacquisition, and 401 behavior are not visible from operation signatures. **MUST load `dotnet-authentication`** before supplying credentials.
- ⚠ Steps 2/4–11 (resilience) — retry triggers differ for HTTP status and transport failure, so a write may be resent; timeout scopes and full-range paging termination also require deliberate configuration. **MUST load `dotnet-configuration-resilience`** before client registration or calls.
- ⚠ Steps 4–11 (calls) — nullable parameters without C# defaults must still be passed, exact named parameter `ct` matters, and `Prefer` changes whether required response data is returned. **MUST load `dotnet-calling-endpoints`** before the first endpoint call.
- ⚠ Steps 4–11 (models) — generated `required` is not provider acceptance, records are init-only, and string-enums must use static members/`FromValue`, not C# enum parsing. **MUST load `dotnet-models`** before building payloads or reading statuses.
- ⚠ Steps 4–12 (errors) — each operation has its own typed accessor shape except raw transaction search, and status/transport/parse failures reach different catch paths. **MUST load `dotnet-error-handling`** before writing the boundary.
- ⚠ Step 12 (tests) — the `HttpClient`/handler is the supported seam; retry and serialization tests must assert outgoing requests and effects without coupling to SDK internals. **MUST load `dotnet-testing`** before writing integration tests.
- ⚠ Error boundary — a drifted or malformed **2xx** body (a missing `required` member) surfaces as a `System.Text.Json.JsonException` from deserialization, **not** as an `SdkException` — so an SDK-exception-only catch ladder lets it escape the integration boundary. **MUST load `dotnet-error-handling`** before writing that boundary.
- ⚠ Error boundary — a **non-2xx** body that does not match its operation's generated `{Operation}Error` shape throws `System.Text.Json.JsonException` *while the error object is being constructed*, so the `JsonException` **replaces** the `SdkException` and the HTTP status is destroyed with it — a boundary that maps every `JsonException` to a 5xx then reports a deterministic rejection as an outage, and a caller that retries 5xx retries something that can never succeed. **MUST load `dotnet-error-handling`** before writing that boundary.

## 5. Assumptions & Blockers

### Assumptions

- The task's stated sandbox merchant enablement for direct card processing and card vaulting is accepted as an environment fixture. The SDK's own client summary says Vault availability is US-only; the supplied enabled sandbox account satisfies that prerequisite.

### Blockers

- None. The SDK covers every required PayPal operation. The live challenge response shape and conflicting prose about multiple reauthorizations are handled defensively and are not blockers for the required one-renewal, no-browser flow.
