# Maxio subscription billing plan

## 1. Scope & sequence

| Step | Change | Maxio operations |
| --- | --- | --- |
| 1 | Vendor the source-built SDK package at the recorded source revision; bind and validate `Maxio:` options; register one managed `HttpClient` and the generated client. | Client construction only |
| 2 | Add the application billing contracts and Maxio adapter; list only active products in the configured family by stable handle. | `ProductFamilies.ListProductsForProductFamily` |
| 3 | Add durable provisioning intents plus an in-process keyed lock. Validate the requested product belongs to the configured family, derive opaque deterministic customer/subscription references from the normalized Identity username, select the non-card invoice/remittance collection method from the site's invoicing architecture, reconcile before each write, create the customer when absent, then create and confirm the subscription. | `Products.ReadProductByHandle`, `Subscriptions.FindSubscription`, `Sites.ReadSite`, `Customers.ReadCustomerByReference`, `Customers.CreateCustomer`, `Subscriptions.CreateSubscription` |
| 4 | Read the caller's customer and subscriptions directly from Maxio, keeping Maxio as system of record. | `Customers.ReadCustomerByReference`, `Customers.ListCustomerSubscriptions` |
| 5 | Add JWT-only minimal endpoints at the three mandated routes, map provider failures to sanitized API problems, and leave catalog/basket/order behavior untouched. | No additional operations |
| 6 | Add adapter and endpoint tests, build/test the solution, then run a detached sandbox host and exercise authentication, plan listing, idempotent subscribe, and account listing. | All operations above |

## 3. Trap notes

- Client registration: generated wrapper and `HttpClient` lifetime can cause socket/lifetime faults if registered with the wrong ownership. **MUST load maxio-platforms-team:dotnet-client-initialization**
- Authentication: incomplete Basic credentials can silently send an unauthenticated request. **MUST load maxio-platforms-team:dotnet-authentication**
- List and write calls: many nullable parameters have no C# default and positional calls can silently mis-bind. **MUST load maxio-platforms-team:dotnet-calling-endpoints**
- Request/response mapping: generated records, open string enums, required members, envelopes, and extension data can be handled incorrectly by ordinary DTO assumptions. **MUST load maxio-platforms-team:dotnet-models**
- Provider boundary: Case A and Case B failures expose different status/body surfaces and a wrong catch ladder can lose the actionable failure. **MUST load maxio-platforms-team:dotnet-error-handling**
- A drifted or malformed **2xx** body (a missing `required` member) surfaces as a `System.Text.Json.JsonException` from deserialization, **not** as an `SdkException`, so an SDK-exception-only catch ladder lets it escape. **MUST load maxio-platforms-team:dotnet-error-handling**
- A **non-2xx** body that does not match its operation's generated `{Operation}Error` shape throws `System.Text.Json.JsonException` *while the error object is being constructed*, so it **replaces** the `SdkException` and the HTTP status is destroyed with it. **MUST load maxio-platforms-team:dotnet-error-handling**
- Resilience: per-attempt timeout, total-call deadline, retry eligibility, ambiguous POST outcomes, base URL override, and body logging can otherwise create excess latency, duplicate writes, or data disclosure. **MUST load maxio-platforms-team:dotnet-configuration-resilience**
- Tests: faking generated controllers couples tests to SDK internals and misses the actual serialized request. **MUST load maxio-platforms-team:dotnet-testing**

| 2 | Secret sourcing & rotation | Development credentials are copied from the named process environment variables into PublicApi .NET user-secrets, outside the repository. | 3 | Total timeout budget | SDK attempt timeout is 5 seconds with at most two GET retries; every public billing operation also gets a linked 20-second cancellation deadline, bounding retries and delays as one caller-visible budget. | YOUR CALL — not in the map |
| 4 | Write-retry ownership | SDK retry eligibility remains GET/HEAD/PUT/OPTIONS; scoped POST writes (`CreateCustomer`, `CreateSubscription`) are not retried by the SDK or application.
