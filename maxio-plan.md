# Maxio subscription endpoints — implementation plan

## 1. Scope & sequence

1. Register one long-lived Maxio client for PublicApi and bind its SDK options from the application's approved Maxio configuration binding. Keep the existing JWT policy at the PublicApi boundary; JWT is not sent to Maxio. Use `ReadProductByHandle` and `ListProducts` for plan discovery/details.
2. For an authenticated caller, derive the application's stable customer reference and subscription reference according to the application's identity/idempotency policy. Resolve the customer with `ReadCustomerByReference`; create it with `CreateCustomer` only on the documented not-found status. Resolve an existing subscription with `FindSubscription`; create it with `CreateSubscription` only on its documented typed 404 shape.
3. Supply the resolved customer ID and selected product handle (and, if the approved application contract requires it, product price-point handle/payment-profile data) to `CreateSubscription`. Read the resulting `SubscriptionResponse.Subscription` defensively and map only the SDK fields listed below to the PublicApi response contract.
4. Add the JWT-protected plan and subscription endpoints using the repository's existing route, policy, DTO, and status-code conventions. The exact route names, claim names, and application DTO member names are application-owned and are not asserted by this SDK sheet.
5. Add tests through the SDK's `HttpClient` seam for lookup/create idempotency branches, typed/raw errors, nullable envelopes, pagination, JWT authorization, and response mapping. Do not use live Maxio traffic in unit tests.

## 2. CONTRACT SHEET

**Signatures are generated code, verbatim — every parameter name is the literal
C# identifier. The cancellation-token parameter really is named `ct`: in named
arguments write `ct:`, never `cancellationToken:`.**

**Every SDK type is written fully-qualified with the namespace the map gives it** — take
each one from that type's own map row, never from where a neighbouring type sits. A members
table names the namespace outright; otherwise the row's source path implies it
(`Core/Configuration/…` ⇒ `…Core.Configuration`; a file at the repo root ⇒ the root
namespace). Enums, unions, auth, server and client-config types are spread across different
child namespaces, and two types configured side by side in the same options object routinely
live in different ones. Dropping a type to the root or to `.Models` makes the implementer
guess the wrong `using`, and the build breaks.

### Early error-boundary hazards

- a drifted or malformed **2xx** body (a missing `required` member) surfaces as a `JsonException` from deserialization, **not** as an `SdkException` — so an SDK-exception-only catch ladder lets it escape the integration boundary;
- a **non-2xx** body that does not match its operation's generated `{Operation}Error` shape throws `JsonException` *while the error object is being constructed*, so the `JsonException` **replaces** the `SdkException` and the HTTP status is destroyed with it — a boundary that maps every `JsonException` to a 5xx then reports a deterministic rejection as an outage, and a caller that retries 5xx retries something that can never succeed.

**MUST load `dotnet-error-handling`** before writing that boundary.

## 3. Trap notes

- ⚠ Step 1 (client registration) — the SDK wrapper and the registered `HttpClient` have different lifetime concerns; an incorrect registration can create a new handler pipeline per request. **MUST load `dotnet-client-initialization`**.
- ⚠ Step 1 (authentication) — PublicApi JWT authorization and the SDK's outbound credential are separate boundaries; confusing them can send the wrong credential or hardcode a secret. **MUST load `dotnet-authentication`**.
- ⚠ Step 1 (configuration/resilience) — SDK retry, timeout, server selection, logging, and pagination options do not describe the complete PublicApi request policy; transport retries can affect non-idempotent calls. **MUST load `dotnet-configuration-resilience`**.
- ⚠ Steps 2–4 (calls) — several nullable parameters have no C# default and a mis-bound positional call can select the wrong filter; the cancellation parameter is literally `ct`. **MUST load `dotnet-calling-endpoints`**.
- ⚠ Steps 2–4 (models) — request wrappers, nullable response envelopes, wire names, `StringEnum<T>`, and any unions must be handled according to generated-model rules; dropped fields are not recovered. **MUST load `dotnet-models`**.
- ⚠ Steps 2–4 (error boundary) — Case A typed errors and Case B raw errors require different access paths, and all SDK calls are throw-only. **MUST load `dotnet-error-handling`**.
- ⚠ Step 5 (tests) — tests must fake the `HttpClient` seam and assert observable mapping/error behavior rather than SDK internals. **MUST load `dotnet-testing`**.

## 5. Assumptions & Blockers

- **Assumption — application-owned JWT surface:** PublicApi already has, or will use, its existing JWT authentication policy. Exact route names, JWT claim/header names, principal-to-customer-reference derivation, and response DTO member names are not in the SDK map and remain `YOUR CALL — not in the map`.
- **Assumption — stable references:** the application supplies a stable customer reference and a stable subscription reference. The customer operation Notes document uniqueness for a supplied customer reference; the map does not document a subscription-reference uniqueness guarantee.
- **Blocker — strict exactly-once subscription creation is not an SDK guarantee:** the SDK exposes no idempotency-key parameter, and its documented retry configuration can retry transport failures for `POST`; no setting disables that behavior. The implementer must choose and document the application's durable idempotency/concurrency/reconciliation policy before claiming exactly-once behavior. Until then, the plan guarantees only lookup-before-create best effort.
- **Blocker — payment/3DS policy:** Maxio may require payment information for the selected product, and the CreateSubscription Notes describe a 422 3DS `action_link` while the generated typed payload exposes only `ErrorListResponse1.Errors`. The application must decide whether the PublicApi collects a payment profile, rejects unsupported products, and how it handles a 3DS response; action-link extraction is `UNVERIFIED` and must fall back to a generic error if unavailable.
- **Assumption — environment:** use `ServerEnvironment.Us` and the Production US server defaults unless the application's approved configuration selects EU hosting or an explicit Production base URL/site override.
