## 2. CONTRACT SHEET

> **Signatures are generated code, verbatim — every parameter name is the literal
> C# identifier. The cancellation-token parameter really is named `ct`: in named
> arguments write `ct:`, never `cancellationToken:`.**
>
> **Every SDK type is written fully-qualified with the namespace the map gives it** — take
> each one from that type's own map row, never from where a neighbouring type sits. A members
> table names the namespace outright; otherwise the row's source path implies it
> (`Core/Configuration/…` ⇒ `…Core.Configuration`; a file at the repo root ⇒ the root
> namespace). Enums, unions, auth, server and client-config types are spread across different
> child namespaces, and two types configured side by side in the same options object routinely
> live in different ones. Dropping a type to the root or to `.Models` makes the implementer
> guess the wrong `using`, and the build breaks.

## 3. Trap notes

⚠ Step 1 (client registration) — client/handler lifetime and the DI registration shape determine whether connection reuse is preserved. **MUST load `dotnet-client-initialization`** before wiring the client.

⚠ Step 1 (authentication) — setting Basic credentials at the wrong point or sourcing them outside the configured secret path risks broken authentication and disclosure. **MUST load `dotnet-authentication`** before wiring credentials.

⚠ Steps 2–7 (endpoint calls) — nullable, no-default generated parameters and response envelopes can silently bind/read the wrong value if called positionally or without unwrapping. **MUST load `dotnet-calling-endpoints`** before writing calls.

⚠ Steps 3–7 (models) — records are immutable, required members must be initialized, and type-safe enum/nullable response members cannot be treated as ordinary C# enums/non-null payloads. **MUST load `dotnet-models`** before building or mapping models.

⚠ Steps 3–8 (error boundary) — typed and raw SDK exceptions use different accessor paths, and error bodies must not become API responses or logs containing sensitive provider detail. **MUST load `dotnet-error-handling`** before writing that boundary.

⚠ Step 4 (idempotent enrollment) — retry/timeout behavior can leave an uncertain write outcome, so reconciliation must precede any repeat enrollment decision. **MUST load `dotnet-configuration-resilience`** before tuning the client or defining write-retry behavior.

⚠ Step 8 (tests) — the SDK client's `HttpClient` construction seam, not controller internals, determines whether provider success/error paths are testable independently. **MUST load `dotnet-testing`** before writing integration tests.

⚠ Steps 3–8 (error boundary) — a drifted or malformed **2xx** body (a missing `required` member) surfaces as a `JsonException` from deserialization, **not** as an `SdkException` — so an SDK-exception-only catch ladder lets it escape the integration boundary; **MUST load `dotnet-error-handling`** before writing that boundary.

⚠ Steps 3–8 (error boundary) — a **non-2xx** body that does not match its operation's generated `{Operation}Error` shape throws `JsonException` *while the error object is being constructed*, so the `JsonException` **replaces** the `SdkException` and the HTTP status is destroyed with it — a boundary that maps every `JsonException` to a 5xx then reports a deterministic rejection as an outage, and a caller that retries 5xx retries something that can never succeed. **MUST load `dotnet-error-handling`** before writing that boundary.

## 5. Assumptions & Blockers

| Type | Item |
|---|---|
| Assumption | The application can obtain non-empty shopper first name, last name, and email; all three are required by `CreateCustomer`. |
| Assumption | The endpoint request supplies a plan handle and the application provides a durable idempotency/concurrency boundary for a user-plan enrollment intent. These are application contracts, not SDK contracts. |
| Blocker | None in the SDK surface. The integration must not submit a subscription without a resolved family, approved product handle, non-null Maxio customer ID, and application-owned duplicate prevention. |
